# Tingle 포팅 매뉴얼 2 — 외부 서비스

프로젝트가 쓰는 외부 서비스와, 새로 가입해 연결할 때 필요한 정보다.
실제 키 값은 적지 않는다. 넣는 위치(환경 변수 이름)만 적는다.

## 한눈에 보기

| 서비스 | 용도 | 값을 넣는 곳 |
|---|---|---|
| 카카오 로그인 | 소셜 로그인 | 서버 `KAKAO_APP_ID`, `KAKAO_NATIVE_APP_KEY` / 앱 `KAKAO_NATIVE_APP_KEY`, `KAKAO_NATIVE_APP_KEY_DEV` |
| 구글 로그인 | 소셜 로그인 | 서버·앱 `GOOGLE_WEB_CLIENT_ID` |
| 네이버 로그인 | 소셜 로그인 | 서버 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` / 앱 `NAVER_CLIENT_ID` |
| Firebase Cloud Messaging | 푸시 알림 | 서버 `FIREBASE_PROJECT_ID`, `/srv/tingle/secrets/fcm.json` / 앱 `google-services.json` |
| SSAFY GMS | AI 문장 생성 | 서버 `GMS_API_KEY` |
| Let's Encrypt | HTTPS 인증서 | 서버 `/etc/letsencrypt` |
| SSAFY GitLab | 소스 저장소, 웹훅 | Jenkins 자격 증명 `gitlab-clone`, `gitlab-api` / `GITLAB_WEBHOOK_SECRET` |

서버 값은 `/srv/tingle/app.env`, 앱 값은 `~/.gradle/gradle.properties`에 넣는다(매뉴얼 1의 2장).

## 1. 카카오 로그인

- 가입: [Kakao Developers](https://developers.kakao.com) → 내 애플리케이션 → 애플리케이션 추가.
- 설정
  1. **앱 키**에서 네이티브 앱 키를 확인한다. 앱 ID는 앱 설정 > 일반에 있다.
  2. **플랫폼 > Android** 등록: 패키지 이름 `com.ssafy.tingle`(운영)과 `com.ssafy.tingle.dev`(개발), 각 서명 키의 **키 해시**.
  3. **카카오 로그인** 활성화, 동의 항목에서 필요한 항목(이메일 등)을 설정한다.
- 서버는 앱이 보낸 카카오 토큰을 카카오에 확인하고, 이 앱(`KAKAO_APP_ID`)에 발급된 토큰인지 검사한다.

## 2. 구글 로그인

- 가입: [Google Cloud Console](https://console.cloud.google.com) → API 및 서비스 → 사용자 인증 정보.
- 설정
  1. OAuth 동의 화면을 만든다.
  2. OAuth 클라이언트 ID를 두 종류 만든다.
     - **웹 애플리케이션** — 이 ID가 `GOOGLE_WEB_CLIENT_ID`다(서버와 앱이 같은 값을 쓴다).
     - **Android** — 패키지 이름과 서명 키의 SHA-1을 등록한다(운영·개발 각각).
- 서버는 앱이 보낸 구글 ID 토큰의 서명과 대상(`GOOGLE_WEB_CLIENT_ID`)을 확인한다.

## 3. 네이버 로그인

- 가입: [NAVER Developers](https://developers.naver.com) → Application → 애플리케이션 등록 → 네이버 로그인.
- 설정
  1. 사용 API: 네이버 로그인, 필요한 제공 정보 선택.
  2. 환경: Android(패키지 이름)와 서비스 URL.
  3. Callback URL: `https://k15e106.p.ssafy.io/auth/naver/callback`.
- 발급된 Client ID / Client Secret을 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 넣는다.

## 4. Firebase Cloud Messaging (푸시 알림)

- 가입: [Firebase Console](https://console.firebase.google.com) → 프로젝트 추가.
- 설정
  1. Android 앱을 등록한다(패키지 이름 `com.ssafy.tingle`, `com.ssafy.tingle.dev`).
  2. `google-services.json`을 내려받아 `front/app/androidApp/`에 둔다.
  3. 프로젝트 설정 > 서비스 계정 > **새 비공개 키 생성** → 받은 JSON을 서버의 `/srv/tingle/secrets/fcm.json`으로 둔다(Jenkins 자격 증명 `tingle-fcm`).
  4. 프로젝트 ID를 `FIREBASE_PROJECT_ID`에 넣는다.
- 용도: 새 제안, 매칭 성사, 채팅 메시지 알림.

## 5. SSAFY GMS (AI)

- SSAFY가 교육생에게 제공하는 AI 호출 서비스다. SSAFY에서 받은 키를 `GMS_API_KEY`에 넣는다.
- 호출 주소: `https://gms.ssafy.io/gmsapi/api.openai.com/v1/responses`
- 모델: `gpt-6-luna`
- 쓰는 곳: AI 서버(`ai-server/`)가 **매칭 이유 설명**과 **채팅 대화 주제(아이스브레이커)** 문장을 만든다.
- GMS가 응답하지 않으면 미리 준비한 기본 문장으로 대신한다. 서비스는 멈추지 않는다.

## 6. Let's Encrypt (HTTPS)

- 무료 인증서. 가입은 필요 없고 서버에서 certbot으로 발급한다(webroot 방식).
- 인증서 위치: `/etc/letsencrypt`. Nginx 컨테이너가 이 폴더를 읽는다.
- 90일마다 갱신한다.

## 7. SSAFY GitLab ↔ Jenkins

- GitLab 프로젝트 > 설정 > 웹훅에 Jenkins 주소(`https://k15e106.p.ssafy.io/jenkins/project/...`)와 비밀 토큰(`GITLAB_WEBHOOK_SECRET`)을 등록한다. push·MR 이벤트를 보낸다.
- Jenkins 자격 증명
  - `gitlab-clone`: 저장소를 내려받는 토큰
  - `gitlab-api`: MR에 빌드 결과를 남기는 토큰
  - `tingle-app-env`: 앱 빌드 키 묶음
  - `tingle-release-key`, `tingle-release-password`: 앱 release 서명 키와 비밀번호
  - `tingle-fcm`: Firebase 서비스 계정 키

## 8. 하드웨어 (참고)
