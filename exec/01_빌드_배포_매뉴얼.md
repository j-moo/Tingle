# Tingle 포팅 매뉴얼 1 — 빌드·배포

SSAFY 15기 자율 프로젝트 E106 **Tingle** (BLE 키링 오프라인 소개팅).
GitLab 저장소를 클론한 뒤 이 문서 순서대로 하면 서버·앱·키링 펌웨어를 빌드하고 배포할 수 있다.

> 비밀값(비밀번호·키)은 이 문서에 적지 않는다. 이름과 위치만 적는다. 실제 값은 팀 내부에서 따로 전달한다.

## 3. 빌드와 실행

### 3-1. 로컬에서 백엔드 실행

```bash
git clone <저장소 주소>
cd S15P31E106/back
cp .env.example .env        # 값 채우기
docker compose up -d        # 로컬 PostgreSQL 17 (back/compose.yaml)
./gradlew clean build       # 빌드 + 테스트 + Checkstyle
./gradlew bootRun           # local 프로필로 실행
```

로컬 DB 구조가 바뀌면 `docker compose down -v` 후 다시 띄운다(로컬 데이터가 지워진다).

### 3-2. 앱 빌드

```bash
cd front/app
./gradlew :androidApp:assembleDebug     # 개발 서버용 (.dev)
./gradlew :androidApp:assembleRelease   # 운영 서버용 (서명 키 필요)
```

`front/app/androidApp/google-services.json`(Firebase 설정)은 저장소에 들어 있다.

### 3-3. 키링 펌웨어

1. Windows PowerShell에서 `iot/tools/build-firmware.ps1` 실행 → `iot/build/zephyr.uf2` 생성.
2. 키링의 리셋 버튼을 빠르게 두 번 누른다 → PC에 `XIAO-SENSE` 드라이브가 뜬다.
3. `zephyr.uf2`를 그 드라이브에 복사하면 자동으로 다시 켜진다.

자세한 내용은 `iot/README.md`.

## 4. DB

- 한 PostgreSQL 컨테이너(`tingle-db-1`) 안에 DB가 두 개다: 운영 `tingle`, 개발 `tingle_dev`.
- `infra/db/init.sql`이 처음 뜰 때 `tingle_dev`를 만든다.
- 서버가 테이블을 만들지 않으므로(`ddl-auto: validate`) 구조를 직접 넣는다. 둘 중 하나를 쓴다.
  - **간단한 방법**: 이 폴더의 DB 덤프 파일을 복원한다.

    ```bash
    docker exec -i tingle-db-1 sh -c 'psql -U $POSTGRES_USER -d tingle' < 03_DB_덤프_구조만.sql
    ```

  - **저장소 파일로**: `back/src/test/resources/database/schema.sql` → `infra/db/prod-changes/*.sql`(파일 이름 순서) → `back/src/main/resources/database/*.sql`.
- 백업: 매일 `infra/backup-daily.sh`가 `/backup`에 덤프를 남긴다(cron `0 19 * * *`, 서버 시간 UTC = 한국 새벽 4시). 복원은 `infra/restore-db.sh`.

## 6. 배포 시 특이사항

1. **운영과 개발이 같은 서버·같은 DB 컨테이너**를 쓴다. DB 이름만 다르다(`tingle` / `tingle_dev`). 명령을 실행할 때 DB 이름을 꼭 확인한다.
2. **DB 구조는 자동으로 바뀌지 않는다.** 구조를 바꾸는 배포는 SQL을 먼저 적용한 뒤 서버를 올린다. 안 그러면 서버가 켜지다 멈춘다.
3. **운영은 blue-green 방식**이다. 새 컨테이너가 정상인 것을 확인한 뒤 Nginx가 가리키는 쪽을 바꾼다. 현재 방향은 `/srv/tingle/nginx-state`에 기록된다.
4. **Jenkins는 한 번에 하나만 빌드**한다. 여러 건이 겹치면 줄을 선다. 백엔드 전체 빌드는 9분쯤 걸린다.
5. **키링은 운영용·개발용을 나눠 쓴다.** 키링에는 주인이 바뀐 횟수(소유 번호)가 하나만 있어서, 같은 키링을 운영과 개발에 번갈아 등록하면 번호가 어긋나 등록이 거절된다.
6. **키링 정품 인증**: 새 보드는 시리얼과 기기 공개키를 DB에 먼저 넣어야 등록된다. 보드를 USB에 꽂으면 직렬 포트에 `ENROLL serial=… keyId=… publicKeySpkiBase64url=…` 줄이 나온다.
7. **앱은 스토어가 아니라 서버에서 내려받는다** (`/app/latest.apk`). 디버그 앱(`.dev`)은 개발 서버, release 앱은 운영 서버에 붙는다. 둘을 한 폰에 같이 설치할 수 있다.
8. **소셜 로그인 키 해시**: 카카오·구글은 앱 서명 키의 해시를 콘솔에 등록해야 로그인된다. 서명 키가 바뀌면 다시 등록한다.
9. **HTTPS 인증서**는 90일마다 갱신한다(certbot).
