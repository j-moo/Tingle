## 이번 추가 확정

기존 회원의 재검사 이어하기 거절은 재검사를 시작했던 화면으로 복귀한다. 회차·답변·기존 적용 결과와 기존 유효 제안/채팅은 보존한다. 최초 가입은 가입 진행 요약(A안)을 유지한다. 출처의 저장·복구와 유실 예외는 화면 계약에서 확정한다.

## 읽는 방법과 공통 예외

민트 사각형은 화면, 회색은 화면 내 기능 또는 기기/서버 처리, 평행사변형은 입력, 마름모는 판단, 캡슐은 시작/종료/다른 구역 연결이다. 실선은 진행, 점선은 나중에 발생하거나 선택하는 경로다. 04~05 구역의 처리 노드를 모두 앱 화면으로 만들지 않는다.

실패 시 입력 보존·재시도, 응답 유실 시 서버 상태 재확인, 저장 중 중복 제출 억제, 계정/회차 변경 뒤 늦은 응답 무시는 전 구역의 공통 예외다. 단순히 뒤로 가거나 재로그인했다는 이유로 기회·제안·채팅의 기한을 다시 시작하지 않는다. 상세 전이와 타임아웃/권한 경합은 명세의 수용 기준을 따른다.

## 00 전체 서비스 지도

앱의 화면 이동과 키링에서 시작되는 만남 흐름을 함께 봅니다.

- 민트 사각형은 화면, 회색 사각형은 화면 내 기능·기기/서버 처리, 평행사변형은 사용자 입력, 마름모는 판단, 흰 캡슐은 시작·종료입니다.
- 숫자 표시는 상세 흐름 번호입니다. 실선은 진행, 점선은 나중에 발생하거나 선택하는 경로입니다. 화면 이름과 메뉴 배치는 UX 초안입니다.
- 명세의 목표 동작을 표현한 검토본입니다. 실제 구현 완료·팀 승인·실물 시험 결과를 뜻하지 않습니다.

## 01 로그인·재진입

서버에서 확인한 계정 상태로 도착 화면을 결정합니다.

- 소셜 로그인은 구글·카카오·네이버 3종(CM13 변경). 서로 다른 소셜 계정을 자동으로 합치지 않습니다.
- 탈퇴 대기·탈퇴 완료 등 계정 제한을 홈·알림 목적지보다 먼저 확인합니다. 재가입 제한은 탈퇴 완료부터 72시간입니다.
- 기존 회원의 키링 0개·AI 동의 철회는 최초 가입으로 되돌리는 이유가 아닙니다. 기존 유효 제안은 접근 가능하고, AI 미동의자의 채팅 이용은 11번을 따릅니다.
- 일반 로그인은 홈, 알림 진입은 현재 계정·대상의 권한과 최신 상태를 재확인합니다.

## 02 최초 가입·매칭 준비

약관 → 키링 → 프로필 → 설문 → 희망 조건 → 동기화 순서입니다.

- 각 단계는 저장·등록 성공과 서버 상태를 확인한 뒤 이동합니다. 저장 실패는 입력을 보존하고 재시도하며 응답 유실은 상태를 재조회합니다.
- 프로필 필수: 닉네임·생년월일·성별·흡연·음주. 사진·종교·자기소개는 선택입니다. 만 19세 미만은 가입 불가입니다.
- 프로필 임시 저장은 최종 등록이 아닙니다. 생년월일·성별은 최종 등록 전 확인하고 이후 직접 수정은 제한합니다.
- 키링 미발견·권한 거부·타인 소유·영구 차단을 등록 성공으로 처리하지 않습니다. 구매 링크 방문만으로 가입 단계가 완료되지 않습니다.
- 기기별 동기화를 표시합니다. 한 대가 실패해도 준비된 다른 기기의 참여는 유지합니다. 최초 매칭·진동·LED ON, 사진 있는 상대만 옵션 OFF입니다.

## 03 설문·이어하기·재검사

- **2026-10-26 확정:** Q97 미확인/엄격 제외와 허용 범위 충돌, Q98 미확인은 재확인으로 연결하고 새 응답의 매칭 적용을 보류합니다. Q97 any는 유효하며 Q98 some 자동 대체는 금지합니다. 최초 가입은 유효 결과 준비 전 매칭 시작을 보류하고 재검사는 기존 유효 결과를 유지합니다. 정책 .123·명세 .118 V261~265 기준이며 그림/Figma·제품 코드 반영은 별도 후속입니다.

답변 저장, 제출, 계산 완료를 서로 다른 상태로 구분합니다.

- 현재 설문 SIS-Q-1.1-100은 총 100문항. 문항 ID·회차·버전에 맞춰 저장합니다. 결과 점수·유형은 사용자에게 공개하지 않습니다.
- 이번 확정: 기존 회원이 이어하기를 거절하면 재검사를 시작했던 화면으로 돌아갑니다. 최초 가입은 가입 진행 요약으로 돌아가며 필수 단계를 건너뛰지 않습니다.
- 이어하기 거절은 답변 삭제가 아닙니다. 새 재검사 회차는 빈 답변·1번부터 시작합니다. 제출 완료 상태는 재확인 필요와 기술적 계산 실패를 구분해 재응답 안내 또는 계산 복구로 연결합니다.
- 재검사 작성·계산 대기·실패 중에는 기존 유효 결과와 기존 제안·채팅을 유지합니다. 새 결과 성공 시 새 매칭에 적용·기기 동기화합니다.
- 앱 재시작 시 재검사 진입 출처를 복구하는 방법과 출처를 잃은 경우의 처리는 FE 계약으로 남깁니다.

### 03-A 재확인부터 새 결과 반영까지 (명세 .119 보완)

1. 앱 진입/복귀 시 해당 계정의 회차·제출·계산·현재 적용 결과를 확인합니다. 상태 조회에 실패하면 ‘다시 확인’이며 새 회차 생성이나 성공 표시로 넘어가지 않습니다.
2. **미제출 초안에서 재확인 필요:** 본인 확인 항목 안내 → 해당 초안의 답변 보완 → 저장 성공 → 전체 제출 검증. Q97 엄격 제외와 허용 범위 충돌은 범위를 정하거나 해당 제외를 해제하고, Q98은 직접 선택합니다. 해소되지 않은 항목은 남겨둡니다.
3. **완료 응답에서 재확인 필요:** 기존 원본 보관 안내 → 지원 버전의 별도 새 회차 시작 → 빈 답변·1번부터 검사. 기존 진행 초안이 있으면 이어하기를 적용합니다. 완료 응답의 문항을 직접 덮어쓰지 않습니다. 정확한 버전/회차 API는 담당 계약과 대조합니다.
4. **제출 접수 후:** 답변 검증/계산 중 → 입력 재확인 사유면 2~3의 해당 경로, 기술적 계산 실패면 같은 제출 입력으로 재시도. 네트워크 응답 유실은 먼저 처리 상태 조회로 복구합니다.
5. **유효 결과 저장·현재 결과 전환 확인:** 서버 적용 완료 → 등록 키링의 반영 대기/성공/실패 표시. 최신 사본이 확인된 기기와 다른 준비 조건을 함께 평가합니다. 새 결과 적용용 별도 승인 버튼은 없습니다.
6. **최초 가입:** 유효 결과가 없으면 준비 보류, 결과 성공 후에도 남은 가입 단계/기기 준비를 확인합니다. **재검사:** 보완·계산 중 기존 유효 결과와 제안·채팅을 유지하고 다른 제한은 그대로 적용합니다.

상세 상태는 기능 명세 SUR-02의 UX-SUR01~09, 수용 기준 V266~271을 따릅니다. 안내를 닫거나 재진입해도 재확인 필요를 해제하지 않으며 오래된 응답으로 현재 결과를 되돌리지 않습니다. 문서 흐름을 보완한 것으로, 연결된 Mermaid/Figma/SVG 화면은 이번에 수정하지 않았습니다.

## 04 키링 만남·오프라인 설렘

휴대폰·인터넷 없이 키링끼리 판단하는 경험이 MVP 필수입니다.

- 이 구역의 회색 노드는 앱 화면이 아닌 키링 내부 동작입니다. 설정·시간이 준비된 키링끼리 통신합니다.
- 양쪽 매칭 ON 및 나이·성별·사진 옵션·관계 제한과 계산 조건을 확인합니다. 진동·LED OFF는 매칭 OFF와 다릅니다.
- 충분한 입력 교환 뒤 상대가 멀어져도 후속 계산·기록·제안 경로를 유지합니다. 이탈 후 지연 진동·LED는 생략합니다.
- 진동은 두 사람 모두 ON일 때만 양쪽 실제 감지 키링에서 실행됩니다. 한쪽이라도 OFF이면 양쪽 무진동이며 저장된 상대 설정 값은 바꾸지 않습니다. LED는 본인 설정만 적용하며 둘 다 LED ON이면 같은 색. 진동은 짧게 2회 한 묶음이고 버튼으로 남은 진동을 멈춥니다.
- 같은 쌍의 미접수 기록·상대 기록 대기·유효 제안·활성 채팅은 반복 생성/안내를 억제합니다. 원격 집 키링으로 안내를 전파하지 않습니다.
- 여러 후보는 조건 확인 완료순, 한 번에 한 상대를 안내합니다. 충분한 BLE 교환·근접 거리/시간·시계 오차는 U02 기술 계약으로 미정입니다.

## 05 기록 동기화·제안 생성

양쪽 기록이 모이기 전에는 제안도 24시간 타이머도 시작하지 않습니다.

- 만남 기회는 만남 발생부터 최대 7일. 상대 기록 대기 마감은 만남+7일과 첫 유효 접수+7일 중 빠른 시각입니다.
- 서버에 제안을 생성한 때부터 별도 24시간 응답 기한이 시작됩니다. 기회 7일 직전 생성된 제안도 자신의 24시간을 유지합니다.
- 수동·재연결·설정/관계 변경·자정 동기화를 지원합니다. 정각 자동 완료는 보장하지 않습니다.
- 앱이 기록을 읽은 것과 서버가 안전하게 접수한 것은 다릅니다. 서버 접수 확인 전 기기 원본을 지우지 않습니다.
- 현재 매칭 OFF·차단·탈퇴 등 생성 제한을 서버에서 재검증합니다. 실패 상세 사유·상대 정보는 노출하지 않습니다.
- 기회/기록 대기 자동 만료에는 거절 30일 제한이 없습니다. 만료 기록을 재전송해 부활시키거나 기한을 연장하지 않습니다.

## 06 제안·수락·거절

내 결정 전 상대의 수락·거절 여부를 드러내지 않습니다.

- 24시간은 서버 제안 생성부터 계산합니다. 목록/상세는 최신 공개 프로필을 제공하며 매칭 이유는 P1 추가 목표입니다.
- 수락 직전 공개 프로필이 바뀌었으면 같은 화면에 최신 정보를 갱신하고 다시 수락하도록 합니다. 조회 실패는 비성사로 표시하지 않습니다.
- 내가 거절하거나 수락을 취소하면 같은 제안 재수락 불가·기존 거절 30일 제한 적용. 아직 미응답인 상대에게 선행 거절/취소를 드러내지 않습니다.
- CM12로 수락 취소를 제공하지 않습니다. 수락 후 상대 응답/원래 기한을 기다리며 차단·탈퇴 및 방 생성 후 나가기는 유지합니다.
- 상호 수락과 방 생성 성공을 구분합니다. 현재 구현의 준비 상태를 실제 채팅 입장으로 오인하지 않습니다.
- 설문·나이·사진 옵션 변경으로 기존 유효 제안을 자동 취소하지 않습니다. 원래 응답/만료 시각 유지, 종료 제안 복원 금지입니다.

## 07 채팅·대화 종료

입장하지 않아도 방 생성일부터 7일이 흐릅니다.

- 확인 버튼 없이 채팅방에 바로 진입하며 상단에 실제 종료 시각과 종료 후 대화 확인 불가를 항상 표시합니다(CM05). 종료 1시간 전 별도 알림은 CM04로 후속입니다. 나중에 입장·재로그인으로 이용 기한을 늘리지 않습니다.
- MVP는 텍스트만 전송. 공백/줄바꿈뿐인 입력은 불가, 원문 최대 1,000자. 웹 주소는 서버에서 해당 부분을 가린 뒤 전달합니다. 수정·삭제·비텍스트 첨부는 미지원입니다.
- 상대에게 보여주는 읽음 표시는 CM06으로 후속입니다. 본인 목록의 새 메시지 표시와 전송 성공/실패 안내는 유지하며 로그인·목록 조회·푸시 수신만으로 본인 확인 완료 처리하지 않습니다.
- 위험 안내는 AI 적용 조건이 확인된 경우의 목표 동작입니다. 차단은 사용자 선택이며 AI 경고가 자동 차단·제재를 뜻하지 않습니다. 신고는 CM09 후속입니다. 아이스브레이킹 질문은 P1 추가 목표입니다.
- 종료된 방은 양쪽 목록·대화에서 제거하고 이력으로 복원하지 않습니다. 종료 후 서버 기록 보관은 사용자 재열람 기능이 아닙니다.
- 자발적 나가기·7일 자동 종료 후 같은 상대와 재매칭 금지. 차단·AI 철회·탈퇴는 각 상세 흐름의 종료 규칙을 따릅니다.

## 08 프로필·설정·키링 관리

설정 저장과 실제 기기 반영 상태를 따로 보여줍니다.

- 매칭·진동·LED는 독립 스위치, 최초 모두 ON입니다. 사진 있는 상대만 옵션은 최초 OFF입니다. 재로그인·재연결로 사용자가 저장한 값을 초기화하지 않습니다.
- 매칭 OFF는 새 제안/매칭을 중지하지만 기존 유효 제안·채팅은 유지합니다. 진동/LED OFF만으로 기록·제안 푸시를 끄지 않습니다.
- 프로필 일반 정보·사진 수정과 생년월일/성별 서비스팀 정정은 다릅니다. 희망 나이·사진 옵션·재검사 변경 후 기존 제안은 유지합니다.
- 압축 MVP는 계정당 등록 키링1개입니다. ‘내 키링’의 연결/준비 상태를 표시하고 추가 등록을 막습니다. 초기화는 기기와 서버 소유 해제가 모두 완료돼야 성공입니다. 복수 등록/동시 참여는 후속입니다.
- 기기 재시작 뒤 시간/설정 동기화 전 새 매칭 대기. 마지막 키링 초기화 뒤 기존 회원의 제안·채팅 접근은 유지합니다.
- LED 색/패턴·버튼과 LED 관계·OFF 전파 지연은 미정입니다. 진동 중지 버튼을 매칭 OFF·제안 거절로 해석하지 않습니다.

## 09 차단·나가기

CM09로 신고 기능 전체는 후속입니다. 차단과 채팅 나가기는 유지합니다.

- 차단은 유효 제안·활성 채팅 양쪽 종료, 차단 중 새 매칭 금지. 나가기는 해당 방 양쪽 종료와 같은 상대 재매칭 금지입니다.

**[CM09 후속 신고 참고 — MVP 제외]** - 상대에게 신고자·신고 사실·차단/나가기 상세 사유를 노출하지 않습니다. 신고는 운영팀 수동 검토 대상입니다.

## 10 로그아웃·탈퇴·분실

문의 접수, 초기화, 실제 탈퇴 완료를 구분합니다.

- 로그아웃은 매칭 OFF가 아닙니다. 준비된 키링의 매칭/출력과 일반 문구의 새 제안 푸시는 유지합니다. 채팅 메시지·방 생성·종료 임박 알림은 보내지 않습니다.
- 일반 탈퇴는 등록 키링 0개일 때 진행합니다. 조회 실패를 0개로 간주하지 않습니다. 탈퇴 사유 입력은 MVP에서 생략합니다.
- 정상 기기와 분실 기기가 함께 있으면 정상 기기를 먼저 초기화합니다. 서비스팀이 남은 분실 기기를 영구 사용 불가 처리하고 탈퇴를 완료합니다. 문의 접수만으로 완료되지 않습니다.
- 탈퇴 완료 시 양쪽 제안/채팅 종료·프로필 접근 중지·전체 세션/푸시 연결 해제. 72시간 후 새 가입 가능하며 과거 계정 내용은 복구하지 않습니다.
- 생년월일 정정에서 만 19세 미만 확인 시 안내 후 24시간 탈퇴 대기. 대기 중 초기화·문의만 가능하며 초기화를 빨리 해도 탈퇴 시각은 앞당기지 않습니다.
- 연령 미달 최초 안내 실패 시 기산 기준과 분실/소유 증빙 방식은 미정입니다.

## 11 AI 동의 철회·재동의

철회 당시의 기존 방 종료와 철회 이후 새 방의 이용 제한을 구분합니다.

- 가입 시 AI 위험 감지 별도 필수 동의는 제품 요구입니다. 실제 적용 근거·제공업체 조건 확인 전 실제 사용자 대화를 분석하지 않습니다.
- 철회 시 당시 참여 중인 활성 방을 모두 양쪽 종료하고 해당 상대와 재매칭 금지. 신규 분석/외부 전송 중단. 자동 회원탈퇴는 아닙니다.
- 철회 후에도 다른 조건이 맞으면 다른 상대와 매칭·제안·수락은 가능하며 상호 수락 시 새 방을 생성합니다. 미동의자 본인의 입장·조회·전송은 제한합니다.
- 새 방의 동의한 상대방은 평소처럼 메시지를 보낼 수 있습니다. 상대에게 철회/재동의 대기 사실을 표시하지 않습니다.
- 재동의 저장을 확인하면 아직 유효한 새 방 이용 가능. 과거 종료된 방 복구·재매칭 제한 해제·7일 기한 연장은 없습니다.
