### 2.3 테스트 빌드 전달과 운영 화면 MVP 범위 (2026-10-21 확정)

순철은 테스트에 사용할 코드 버전을 확정하고 설치 파일 생성·설치 확인·버전별 변경사항 정리를 맡는다. 재준은 확인된 설치 파일과 설치 안내를 테스터에게 전달하고 피드백에 사용 버전을 기록한다. 실제 파일 생성·설치 검증·외부 전달은 별도 실행이며 담당 확정으로 완료 처리하지 않는다. 빌드 도구·대상 환경·배포 채널과 세부 일정은 순철·재준이 구현 계획에서 맞춘다.

운영 화면은 팀 내부용 간단한 웹 화면으로 구현한다. FE는 재준, 운영 API와 운영자 권한 검사는 가을, 운영 API에 연결할 채팅 보관/삭제는 영빈이 맡는다. 아래는 기존 AUTH-03·KEY-04·PRO-03·SAFE-01·CHAT-06의 운영 흐름을 구체화한 범위이며, 새 기능 ID를 추가하거나 기존 P0 우선순위를 바꾸지 않는다.

| 화면 | MVP 동작과 확인 기준 |
| --- | --- |
| 운영자 로그인·접근 제한 | 일반 사용자의 운영 화면 접근을 막고 서버도 운영 API의 조회·처리 권한을 검사. 화면에서 버튼을 숨기는 것만으로 접근 제한 완료로 보지 않음 |
| [CM09 후속] 신고 목록·상세 | 신고 사유·상세 설명·선택 메시지와 해당 신고 방 전체 대화 조회. 처리 상태·결과 기록. 신고 대화 조회는 기존 보관 기한 내에서만 제공하며 전체 사용자 대화 검색은 제공하지 않음 |
| 문의 목록·상세 | 정보 정정·분실/탈퇴 요청 구분(일반 문의는 CM08 외부 창구로 제외), 추가 확인 요청과 처리 결과 기록. 기존 증빙·정정·탈퇴 정책 유지 |
| 계정·키링 처리 | 해당 요청에 필요한 계정·키링 상태 확인, 기존 정책에 따른 정정·분실 키링 영구 차단·탈퇴 처리. 분실 확인·정상 보유 기기의 초기화 순서는 유지. 연령 미달 확인 시 일반 이용 제한·초기화/문의 접근을 유지하며 이후 운영 처리 시점·완료 조건은 별도 협의. CM16으로 24시간 자동 탈퇴·초기화 마감·기한 초과 기기 차단은 MVP 제외이며 즉시 강제 탈퇴로 대체하지 않음 |

처리 실행 전에 대상과 변경 내용을 다시 확인하고, 서버의 실제 처리 결과를 기준으로 완료/실패를 표시한다. 실패·부분 실패를 완료로 표시하지 않으며 복구·재시도 계약은 DES11에서 정의한다. 누가 언제 무엇을 처리했는지 기록하며 업무 기록의 최소 항목/보관 기간은 §2.4를 따른다. 보안 접속·권한·동의 기록은 §2.5를 따르며 조회/처리 역할은 §2.6을 따르고 동의/예외 보관 근거는 POL04에서 확인한다. 운영 화면 추가를 새 제재 정책이나 데이터 보관 기간의 근거로 쓰지 않는다.

MVP에서는 통계 대시보드·전체 사용자 대화 검색·AI 신고 우선순위 정렬을 제외한다. AI 신고 검토 지원은 기존 AI-03의 MVP 이후 범위를 유지한다. 운영 역할/조회 범위는 §2.6을 따르고 실제 권한 설정과 잔여 정정/강제 탈퇴 판단 기준은 POL04·POL07·DES11에서 구체화하며, 이 문서 반영은 실제 계정에 운영 권한을 부여한 것이 아니다.

**압축 MVP CM08(2026-10-26 사용자 승인):** 일반 문의는 앱 내 작성·접수 상태·문의 내역·답변 조회 대신 외부 문의 창구로 연결한다. ‘문의하기’에서 일반 문의의 외부 이동을 안내하고, 생년월일·성별 정정 및 키링 분실/탈퇴 요청은 기존 앱 내 경로로 구분한다. 차단과 해당 요청의 인증·권한·처리 결과/이력은 유지한다. 일반 문의 전용 앱/운영 웹 화면 및 접수·답변 API 요구는 현재 MVP에서 제외하고, 외부 문의를 제품 DB로 자동 수집하거나 상태를 동기화하지 않는다. 공용 문의 테이블 전체 삭제를 뜻하지 않는다.

실제 외부 채널 종류와 주소는 미정이다. 연결을 열거나 앱으로 돌아온 사실만으로 ‘문의 접수 완료’를 표시하지 않는다. 외부 연결 실패 시 목적지 안내와 재시도/주소 확인 경로를 제공한다. 기존 14일 무응답 종료·종료 후 30일 보관 및 앞선 탈퇴 시 삭제 기준은 일반 문의도 운영 절차로 유지하며, 제품 서버의 자동 처리와 외부 창구의 실제 삭제/운영 설정은 구분해 확인한다. 정정·분실의 기존 서버 상태/보관 처리는 그대로 유지한다. 외부 채널 개설·실제 연결·처리 설정을 완료한 것은 아니다.

### 2.4 운영 업무 기록과 미응답 문의 보관 (2026-10-21 확정)

업무 처리에 필요한 기록과 운영자 접속/권한·동의 기록을 분리한다. 아래 30일은 서비스 업무 기록의 확정 기준이며 운영자 보안 기록이나 동의 기록에 일괄 적용하지 않는다.

| 기록 | 저장할 최소 업무 정보 | 보관·삭제 기준 |
| --- | --- | --- |
| [CM09 후속] 신고 접수·처리 | 신고 ID, 신고자/대상/방 ID, 사유·상세 설명, 선택 메시지 ID, 접수 시각, 상태, 담당자, 처리 결과·시각 | 해당 신고 방의 대화 삭제일에 함께 삭제. 방별 최초 신고 + 90일 상한, 모두 기각이면 마지막 기각 + 30일과 상한 중 빠른 시점. 추가 신고·재조회·재시도로 연장하지 않음 |
| 분실 문의(제품 내) | 문의 ID, 요청자, 문의 종류·내용, 필요한 기기 참조, 추가 확인 내용, 답변·처리 결과, 담당자·시각 | 완료·반려부터 30일(720시간). 그 전에 탈퇴하면 기존 회원 데이터 삭제 정책 적용 |
| 생년월일·성별 정정 요청 | 요청 항목·값·사유, 필요한 추가 설명, 확인 방법·결과, 담당자·처리 시각 | 기존 완료·반려부터 30일 유지, 그 전에 탈퇴하면 삭제. 증빙 사진/파일 사본 미보관 유지 |
| 업무별 운영 처리 이력 | 연결된 요청, 처리자, 처리 시각, 수행 작업, 성공/실패, 필요한 결과 코드 | 연결된 문의와 같은 삭제 기한. 작업·재시도마다 새 보관 기간을 시작하지 않음. 개인정보 조회/수정에 대한 별도 보안 접속기록과 구분 |
| 장애 확인용 일반 로그 | 발생 시각, 오류 코드, 기능, 요청 추적 ID, 앱 버전 | 발생일부터 30일(720시간). 대화/문의 본문·인증 토큰·프로필 원문은 기록하지 않음. 보안 접속기록·AI 분석 기록의 보관 기준을 이 기간으로 대체하지 않음 |

**[CM09 후속 참고 — 현재 MVP 제외]** 신고의 선택 메시지는 ID로 연결하고 대화를 신고 기록·운영 메모에 복사하지 않는다. 최초 신고 후 80일째 모든 신고를 기각하면 90일째 해당 방의 대화와 신고 상세·처리 이력을 함께 삭제한다. 원문 삭제 후에도 내용이 운영 메모/일반 로그에 남도록 구현하지 않는다.

분실 문의 삭제와 키링의 영구 사용 불가 상태는 별개다. 기기 식별·차단 상태 등 영구 차단에 필요한 최소 정보는 유지하며 과거 소유자의 프로필이나 문의 본문을 계속 연결하지 않는다. 문의 삭제가 기기를 다시 등록 가능하게 만들면 안 된다.

제품 내 정정·분실 등 문의는 추가 확인 요청 후 사용자가 14일(336시간) 동안 답하지 않으면 해당 문의를 '응답 없음'으로 종료하고 그 종료일부터 30일 뒤 삭제한다. 이 기준은 정정 등 추가 확인이 필요한 문의에도 적용하며, 문의 종료가 정정 승인·키링 초기화·탈퇴 성공을 뜻하지 않는다. 답변이 온 경우 사용자 무응답으로 종료하지 않는다. 운영팀이 처리를 못 한 건은 사용자 무응답으로 종료하지 않고 담당자에게 지연 건으로 표시한다. 연령 미달 확인 계정은 일반 이용 제한·초기화/문의 접근을 유지한다. 문의 종료만으로 해당 제한을 해제하거나 탈퇴시키지 않으며, 이후 운영 처리 시점·완료 조건은 별도 협의한다. CM16으로 연령 미달 24시간 탈퇴 기한은 현재 MVP에 적용하지 않는다.

14일 기산에 사용할 요청/전달 상태, 전달 실패·중복 요청·답변/종료 경합의 처리 계약은 FE·BE가 구체화한다. 기한이 지난 데이터는 화면 숨김만으로 삭제 완료로 표시하지 않고 기존 저장소별 삭제·재시도/복원 시 재삭제 계약을 적용한다.

### 2.5 운영자 접속·권한 및 동의 기록 (2026-10-21 확정)

업무 기록과 별도로 다음 최소 기록을 보관한다. 접속·작업 기록은 개인정보 오남용 확인, 권한 기록은 접근 권한의 부여/변경/회수 확인, 동의 기록은 해당 개인정보 처리에 관한 사용자 선택 확인에 사용한다.

| 기록 | 저장할 최소 항목 | 보관·삭제 기준 |
| --- | --- | --- |
| 운영자 접속·작업 기록 | 운영자 ID, 서버 기준 시각, 접속 IP, 수행 작업, 조회/처리한 사용자 및 문의의 내부 ID, 성공/실패 여부 | 각 기록 발생일부터 2년 |
| 운영자 권한 기록 | 권한 대상 운영자 ID, 부여/변경/회수 구분, 변경 전후 권한, 처리한 관리자 ID, 처리 시각·사유 | 각 변경 발생일부터 3년 |
| 사용자 동의 기록 | 사용자 내부 ID, 동의 항목, 동의/거부/철회 상태, 처리 시각, 안내문 버전·언어, 동의를 받은 화면 | 해당 개인정보 처리에 필요한 동안 보관. 탈퇴·동의 철회로 불필요해지면 삭제하며 일괄 3년/5년 보관하지 않음 |

회원이 이용 중인 기능에 필요한 동의 이력은 버전별로 구분하며 안내문 변경으로 이전 기록을 덮어쓰지 않는다. 탈퇴·철회 시 해당 동의에 의존하던 처리를 중단하고 불필요한 동의 기록도 삭제한다. 탈퇴 후 기존 정책으로 보관하는 채팅 자료의 동의 증빙이 필요한 경우에는 보관 근거와 필요성을 확인한 최소 기록만 해당 자료의 삭제 기한까지 보관한다. 모든 동의 기록을 일괄 30일/90일 연장하지 않으며, 기록 보관이 철회된 동의에 따른 처리를 계속할 권한을 뜻하지 않는다. 개인정보가 없는 안내문 원본·버전 이력은 문서로 유지하되 사용자와의 연결 기록은 위 삭제 기준을 따른다.

이 기록에는 실제 대화 내용·프로필 사진·종교 값·비밀번호·인증 토큰을 넣지 않는다. 권한 변경 사유에도 대화/프로필 원문을 복사하지 않는다. 운영 접속 기록과 실제 데이터 본문은 서로 다른 보관 기한을 적용한다. CM09로 신고 대화 조회는 MVP에서 제공하지 않는다. 사용자가 탈퇴해도 법정 보관 대상인 최소 접속/권한 기록은 정해진 기간을 유지한다. 조회·재시도는 기존 기록의 보관 기간을 다시 시작하지 않는다. 별도로 발생한 조회/권한 변경의 새 기록은 그 사건 시각을 기준으로 관리한다. 동의/보안 기록을 과거 프로필·대화의 복구나 재가입 시 데이터 연결에 사용하지 않는다.

근거 확인(2026-10-21): [개인정보의 안전성 확보조치 기준 제5조·제8조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000281400)는 권한 부여/변경/말소 기록 최소 3년, 접속기록 일반 최소 1년 및 민감정보 등을 처리하는 시스템 최소 2년을 정한다. 종교 정보를 받는 서비스 특성을 고려해 접속기록 2년을 설계 기준으로 채택했다. [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027063705)의 불필요한 개인정보 파기 원칙에 따라 동의 기록의 불필요한 장기 보관을 피한다. 이 합의가 모든 서비스 데이터의 보관 근거를 확인한 것은 아니며, 적용 대상·시행/경과 규정과 개별 보관 근거는 실제 운영 전에 확인한다.

운영 역할/조회 범위는 아래 운영 역할 기준으로 확정했으며, 잔여 POL04는 항목별 동의/예외 보관의 근거·필요성 확인이다. 동의 항목 분류/화면 배치는 아래 단계별 동의 기준을 따르며 최종 문구·실제 수집 범위·처리 근거·외부 전송 동의 계약은 잔여 확인이다. 저장 구조·권한 검사·위변조 방지·삭제 일정/재시도·백업 복원 시 재삭제는 FE·BE·인프라가 DES01·DES11·DES12에서 구체화한다. 이 문서 반영은 기록 수집/삭제 구현이나 실제 운영 권한 부여 완료가 아니다.

CM16으로 제외한 24시간 자동 처리나 즉시 강제 탈퇴를 운영 권한만으로 실행하지 않으며, 이후 운영 처리 시점·완료 조건은 POL07에서 별도 협의한다.

운영 계정·권한 관리자 역할 자체에 신고 대화 열람 권한을 포함하지 않는다. CM09로 서비스 운영 역할에도 신고 대화 조회 기능을 제공하지 않는다. 개발 장애는 우선 필요한 내부 ID·오류 정보로 진단하고, 실제 정보 접근이 추가로 필요하면 재준이 대상·목적·기간을 정해 필요한 권한만 임시 부여한다. 임시 권한의 기한 만료/회수 검사·기록은 서버에서 구현할 계약으로 남긴다.

**AI 가입 동의 계약(2026-10-22 영빈 회신·저장소 대조):** `AI_RISK_DETECTION`은 가입 시 필수이며 확인한 버전은 `2026-10-22`다. FE는 `GET /api/v1/agreements`에서 받은 항목·버전·필수 여부·표시 문구를 사용하고, 실제 표시한 `type`·`version`·`agreed`를 약관 동의 요청에 보낸다. 날짜나 항목 목록을 앱에 고정하지 않는다. 버전 불일치 응답은 최신 약관을 다시 표시하고 사용자 동의를 다시 받아 처리한다. 최초 가입 필수 동의와 가입 완료 후 AI 동의 철회는 구분하며, 철회 후 기존 제안 접근과 채팅 제한은 AUTH-02·AI-02 기준이다. 이 계약 확인은 실제 개인정보 처리/외부 전송 조건의 검토 완료가 아니다.

가입 화면의 항목명 초안은 '[필수] 서비스 이용약관 동의', '[필수] 계정 생성·관리를 위한 개인정보 수집·이용 동의', '[필수] AI 대화 위험 감지를 위한 개인정보 처리 동의', '만 19세 이상입니다'로 구성하고 개인정보 처리방침 열람 링크를 제공한다. 처리방침 링크 열람만으로 개별 동의를 대체하지 않는다. 소셜 제공자의 동의와 우리 서비스의 동의를 구분하며, 소셜 로그인 성공을 우리 서비스 전체 항목 동의로 처리하지 않는다. 연락용 이메일은 소셜 제공 동의와 서비스 개인정보 수집·이용(`PRIVACY`) 동의가 있는 회원에 한해 저장한다. 동의 전 첫 로그인에서는 저장하지 않고 동의 후 로그인부터 저장하며, 이후 로그인에서 최신 값으로 갱신하고 제공되지 않으면 삭제한다. 구글은 인증된 이메일, 카카오는 유효하고 인증된 이메일, 네이버는 제공된 프로필 이메일을 사용한다. 이메일 제공 거부만으로 로그인을 막지 않으며 계정 식별·자동 통합·상대 공개에 사용하지 않고 인증/프로필 응답에도 포함하지 않는다. 이름·사진은 소셜에서 수집하지 않으며 전화번호를 추가 수집하지 않는다. 개인정보 처리 안내에는 수집 항목(이메일), 목적(회원 연락), 저장 조건과 제공 거부 시 로그인 가능 여부, 갱신/삭제 기준을 명시한다. 동의를 통한 수집·이용을 제품 처리 기준으로 기록하되, 최종 동의 문구·처리 근거·보관기간과 철회 처리는 POL04에서 확인한다. 탈퇴 시 이메일도 일반 회원 데이터와 함께 삭제하며 재가입 제한 기록에는 넣지 않는다.

프로필 공개 안내의 핵심은 '매칭 제안이 발생하면 채팅 수락 전에도 상대방이 내 공개 프로필을 확인할 수 있어요. 생년월일·소셜 계정 식별값·설문 개별 답변은 공개하지 않아요.'이다. 실제 제공 대상·항목·목적·보관과 필요한 동의 구분을 확인한 뒤 최종 문구로 작성한다. 사진·자기소개·종교의 선택 동의를 일반 공개 프로필 필수 동의로 대신하지 않는다. 종교는 민감정보 처리 검토 대상으로 분리하고 일반 프로필 동의와 별도로 받는다.

닉네임·생년월일·성별·흡연·음주의 기존 필수 입력과 사진·자기소개·종교의 선택 입력 기준은 유지한다. 입력 필수라는 사실만으로 법적 필수 수집/동의의 필요성이 확인된 것은 아니다. 성향테스트 실제 문항의 수집 범위 및 민감정보 포함 여부, 프로필 공개/외부 전송 처리 근거와 필요한 별도 동의·기존 회원 전환은 POL02·POL04에서 확인한다. AI 외 항목별 철회 전용 화면과 자동 처리의 상세 설계는 LATER06으로 분리한다. 이 합의가 최종 약관 작성·실제 동의 수집·가입 제한 배포 완료를 뜻하지 않는다. 동의 이력은 기존 항목·버전·시각·언어·화면 및 보관/삭제 기준을 적용한다.

**MVP 범위 조정(2026-10-21):** 사진·자기소개·종교 등 AI 외 항목별 동의 철회 전용 화면과 자동 처리 기능은 MVP 이후로 미룬다. 현재 단계에서 이를 추가로 세분화하거나 신규 P0 완료 조건으로 넣지 않는다. MVP에서는 기존 문의 창구로 요청을 접수하고 서비스 운영 담당 재준이 해당 개발 담당과 필요한 처리/삭제를 확인한다. 요청 접수와 실제 처리 완료를 구분하며, 전용 화면을 미루는 것이 요청 거부·무기한 보관·기존 삭제 기준 유예를 뜻하지 않는다. 이미 확정한 프로필 수정/선택값 삭제와 AI 동의 철회·방 종료·재매칭 금지·재동의 동작은 유지한다. 기존 동의 기록/보관 기준 및 실제 데이터 처리 전 확인 사항도 유지하며, 이후 논의는 MVP 구현을 막는 미정 사항을 우선한다.
