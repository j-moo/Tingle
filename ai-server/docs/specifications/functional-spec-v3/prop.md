# 팅글 기능 명세 — 매칭 제안

기준 원문: v0.1.132-draft → 문서 분리: v0.1.133-draft / 2026-10-27.

[전체 목차·공통 기준](../functional-spec-v3.md) · [운영 기준](operations.md) · [검증 시나리오](verification.md) · [협의·변경 이력](decisions.md)

공통 범위는 전체 목차의 §1·§2.1과 [2026-10-28 ERD 기준 MVP 결정](../reviews/erd-mvp-scope-20261028.md)을 함께 적용한다. 신고 접수·증거·운영 검토·최초 신고90일 보관은 MVP에 포함하며 과거 CM09 신고 제외 문구를 대체한다. 그 밖의 기존 합의와 ERD의 미합의/충돌 동작은 연결 결정문 기준으로 대조한다. 원문 절 번호·기능 ID·사례 ID는 보존하며 완료 기준은 실제 구현·테스트 통과를 뜻하지 않는다.

### PROP-01 제안 목록과 상대 공개 프로필

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 제안을 받은 당사자. 상대가 먼저 거절했어도 내가 미응답이고 응답 기한이 남아 있으면 그 거절만으로 접근 종료하지 않음 |
| 실행·입력 | 본인 제안 목록·상세 조회 |
| 정상 동작·결과 | 수락/거절 전에 상대 사진·닉네임·소개·나이·성별·생활 정보와 매칭 이유 확인. 같은 두 계정의 동일 만남은 감지한 키링 수와 관계없이 각 당사자의 목록에 상대 한 건만 표시 |
| 예외 | 타인 제안 조회 차단. 사진 없음은 기본 이미지, 종교 미입력/비공개는 비공개 표시. 내 결정 전 상대 수락/거절·응답 시각 미공개. 선행 거절로 목록 제거·정렬/버튼/프로필 상태를 바꾸어 선택을 드러내지 않음. 내 결과 확인 이후·만료 후 접근 종료 시점은 계약 검토 |
| 완료 기준 | 수락 전 공개 프로필 조회 가능, 비공개 데이터 제외, 삭제 사진 재조회 반영, 다른 회원의 제안 접근 불가. A/B 각각 키링1개의 반복 감지/재전송에도 같은 제안 ID·각 목록 한 건. 다른 상대의 제안은 유지 |
| 데이터·검토 | 제안·당사자·유효 기간·공개 프로필·내 응답/공개 상태. 내부 상대 응답값/시각/선행 거절 코드가 미응답자의 API·푸시·실시간 이벤트에 포함되지 않도록 계약. 종료 이력 목록은 미제공으로 확정. 목록 순서/페이지 처리·종료 후 프로필 접근/캐시 정리는 38번과 FE 합의 |

거절·만료 등으로 끝난 제안은 내 목록에 남기지 않고 별도 종료 이력 목록도 제공하지 않는다. 내 거절는 서버 처리 성공 후 결과 안내와 함께 제거하고, 내 수락에 대한 비성사는 “매칭이 성사되지 않았어요.” 안내 후 제거한다. 만료된 제안은 원래 기한에 목록에서 제외하며 안내 확인 여부로 기한을 늘리지 않는다. 상대 선행 거절만 있고 내가 미응답·기한 내이면 기존 비공개 규칙에 따라 내 목록·프로필·선택 경로를 유지하고, 내 결정 또는 원래 기한 만료 시 제거한다.

탈퇴한 상대의 제안은 AUTH-03에 따라 양쪽 목록에서 제거하고 프로필 조회/수락을 막는다. 이는 상대 선행 거절 비공개 예외와 구분한다.

목록 재조회·앱 재진입·재로그인·실시간 갱신에도 같은 사용자별 공개 기준을 적용한다. 재로그인 시 서버 최신 상태를 조회하고 내 수락 후 상대 미응답인 유효 제안은 수락 대기로 표시한다. 조회 실패는 빈 목록으로 표시하지 않고 재시도를 제공한다. 제거된 제안을 캐시에서 다시 표시하지 않으며 실패한 요청만으로 제거를 확정하지 않는다. 목록 미노출과 서버 기록 삭제는 구분하고, 중복 요청 처리·재제안 제한 등에 필요한 내부 상태의 보관 계약은 별도로 정한다.

### PROP-02 수락·거절·제안 만료

**압축 MVP CM12(2026-10-26 사용자 승인):** 내 수락 취소 기능을 MVP에서 제외한다. 취소 버튼/확인/완료 화면·취소 API·수락에서 거절 또는 미응답으로 되돌리는 사용자 상태 전이는 제공하지 않는다. 수락 후에는 상대 응답 또는 서버 제안 생성부터 원래 24시간 만료를 기다린다. 차단·탈퇴 등 별도 종료 규칙은 유지하고, 상호 수락으로 방이 만들어진 뒤 나가기도 유지한다. 차단을 수락 취소와 같은 동작으로 설명하지 않는다. 서버는 거절 API 등 다른 경로로 이미 수락한 응답을 되돌리는 요청도 허용하지 않으며, 중복 수락/응답 유실은 저장된 결과로 복구한다. 초기 거절의 기존 30일 재매칭 제한과 무응답 자동 만료의 별도 기준은 그대로다. 기존 취소 데이터/유효한 제한이 있다면 새 상태로 자동 변환하거나 제한을 해제하지 않고 전환 범위를 별도로 확인한다.

제안 수락 성공과 채팅 입장 가능 여부는 별도다. 방 존재/본인 접근 조건을 반영하는 `chatAvailable`·`chatRoomId` 확인과 실제 연동 검증 범위는 CHAT-01을 따른다.

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 응답 기한 내 제안 당사자. 상대가 먼저 거절했어도 내가 미응답이면 결정 요청을 처리하되 채팅 성사는 불가 |
| 실행·입력 | 미응답 상태에서 수락 또는 거절. 내 수락 확정 후 취소/거절로 변경 불가(CM12). 양쪽 유효 만남 기록 대조 후 서버 제안 생성 시각부터 24시간 유효 |
| 정상 동작·결과 | 내 결정 전 상대 응답 비공개. 내가 수락했을 때 상대 미응답이면 대기, 이미 수락이면 CHAT-01 연결, 이미 거절이면 “매칭이 성사되지 않았어요.” 표시. 내가 먼저 수락한 뒤 상대가 거절해도 같은 비성사 결과. 내가 거절하면 내 처리 결과만 안내. 거절/만료는 신규 채팅 생성 불가 |
| 예외 | 중복·동시 응답·만료 경계 요청을 일관되게 처리. 같은 만남의 반복 감지·재전송으로 제안 생성/만료 시각·사용자별 응답을 초기화하거나 종료된 제안을 다시 생성하지 않음. 사진 옵션 변경·재검사 새 결과 적용·희망 나이 변경만으로 이전 유효 제안을 취소하거나 수락을 차단하지 않음. 기존 제안의 설명 근거는 생성 당시 결과 버전 유지 |
| 완료 기준 | 한쪽만 수락하면 채팅 불가, 둘 다 수락하면 연결. 상대 선행 수락/거절은 내 결정 전 화면/API/이벤트에 미노출. 선행 거절 후 내 수락은 비성사 안내·채팅 미생성. 통신/처리 실패는 비성사로 오인하지 않고 재시도/재조회. 거절·만료·타인 요청·중복/동시 요청 검증 |
| 데이터·검토 | 내부 사용자별 응답/시각·제안 상태와 사용자별 공개 상태 분리. 선행 거절 오류 대신 내 결정 처리와 비성사 결과를 반환하는 계약은 38·43번. 초기 거절의 기존 30일 제한 유지. 수락 취소는 CM12 후속이며 수락/거절·만료 동시 처리와 중복/실패 복구는 38·43번 계약. 사진 삭제/생일 후 기존 유효 제안·수락 상태·원래 만료 시각 유지는 확정. 공개 프로필 변경 시 같은 화면에서 갱신/안내 후 다시 수락·조회 실패 시 재시도 확정. 비교/표시 버전·동시 변경 계약 필요 |

제안 수신 후 상대 사진이 삭제되거나 생일로 최신 나이가 희망 범위를 벗어나도 기존 유효 제안은 원래 만료까지 유지하며 응답 가능하다. 미응답/한쪽 수락 상태를 보존하고 수락 요청에서 변경된 사진/나이 조건만으로 거부하지 않는다. 현재 프로필은 기본 이미지/최신 나이를 표시하고 이후 새 매칭은 최신 사진 조건·양쪽 나이 조건으로 판단한다. 만료·거절·차단·탈퇴 등 기존 종료 규칙은 적용하며 종료된 제안 복원·기한 연장은 없다. 생성 당시 판단 근거와 최신 프로필 표시를 구분한다.

**수락 전 프로필 확인(2026-10-21 확정):** 미수락 사용자가 수락을 누르면 최신 공개 프로필을 확인한다. 화면에서 확인한 정보와 같으면 바로 기존 수락 처리를 진행한다. 다르면 수락을 확정하지 않고 최신 프로필을 같은 화면에 표시하며 “상대방의 프로필이 변경됐어요. 최신 정보를 확인하고 수락해 주세요.”라고 안내한다. 별도 화면/팝업 없이 사용자가 다시 수락해야 처리한다. 조회 실패 시에는 수락 처리하지 않고 재시도 안내를 제공한다.

이 흐름은 변경된 사진/나이를 새 매칭 조건으로 재심사해 거절하는 것이 아니다. 이미 완료된 양쪽의 수락과 제안의 원래 기한은 유지하며 재확인/재조회로 연장하지 않는다. 처리 완료 후 응답 유실로 재시도하는 경우 기존 수락 결과를 복구하고 다시 확인/수락을 요구하지 않는다. 확인 중 만료·차단·탈퇴 등 기존 종료 사유가 발생하면 그 규칙을 적용한다. 재확인 중에도 상대의 응답/시각은 숨기며, 상대의 선행 거절 여부와 무관하게 동일한 확인 흐름을 거친 뒤 내 최종 수락 처리 때 기존 비성사 안내를 적용한다.

비교는 사진·현재 나이·흡연 정보 등 사용자에게 공개되는 프로필 기준으로 하며 비공개 설문/설정 변경만으로 재확인을 요구하지 않는다. 다시 누른 시점에도 새 변경이 있으면 최신 정보 확인 흐름을 적용한다. FE·BE는 실제 표시 정보와 서버의 공개 프로필 비교/버전, 조회-수락 사이 변경의 동시 처리·중복 요청을 38·43번에서 정의한다.
