# 팅글 MVP 필수 기능 명세서

갱신일: 2026-10-28 · 버전: 1.2-draft · 관리: 이재준

**최신 범위:** [ERD 기준 MVP 결정](reviews/erd-mvp-scope-20261028.md). 21테이블 ERD가 표현하는 기능을 MVP에 포함한다. 신고·운영 검토·신고 보관은 SAFE-01·CHAT-06에 다시 포함하며 CM09의 신고 제외를 대체한다. 과거 변경 주석/미합의 처리 방식과 실제 구현 완료는 구분한다.

## 1. 이 문서의 범위

이번 MVP에 포함하기로 확정한 **29개 필수 기능**의 개발 기준이다. 기능 ID는 기존 명세와 동일하게 유지한다. 기능 포함 결정과 실제 구현·테스트 완료는 다르다.

- 기준: 전체 기능 명세 v0.1.132, 정책 v0.1.136 및 압축 MVP 합의 CM01~16.
- 현재 동작만 기술한다. 변경 이력·과거 검토안·후속 기능 목록·277개 상세 검증 사례는 옮기지 않는다.
- 계산 수치·외부 AI 처리 등 확정되지 않은 부분은 §8에 모았다. 임의 기본값으로 구현하지 않는다.
- 데이터 항목은 필요한 정보의 의미다. **기능 1개 또는 데이터 항목 1개마다 테이블을 만들라는 뜻이 아니다.**
- 근거 확인: [전체 명세](functional-spec-v3.md), [정책](sources.md#personal-05), [계산 계약 검토](sources.md#personal-01). 원문에 옛 문구가 남은 경우 최신 사용자 합의를 적용한다.

전체 흐름: **소셜 로그인 → 동의 → 키링 등록 → 프로필 → 설문 → 희망 조건 → 키링 동기화 → 오프라인 만남·판단 → 양쪽 기록 확인 → 제안 → 상호 수락 → 7일 채팅**.

## 2. 계정·키링

### AUTH-01 소셜 로그인·로그아웃

- 구글·카카오·네이버 로그인 제공. 서버가 제공자 인증을 검증하고 신규 가입 또는 기존 계정의 현재 단계로 이동한다. 같은 이메일이어도 서로 다른 소셜 계정을 자동 통합하지 않는다.
- 로그인 취소·실패는 재시도 안내. 로그아웃한 휴대폰의 세션·푸시 연결을 해제하되, 준비된 키링의 매칭과 기존 제안·채팅은 유지한다. 재로그인은 최신 상태를 조회하며 누락 푸시를 일괄 재발송하지 않는다.
- 필요 정보: 소셜 제공자/고유 식별값, 서비스 가입 ID, 세션·푸시 연결. 이메일은 제공자 동의와 서비스 개인정보 동의 후 로그인부터 연락용으로 저장한다. 로그인 시 갱신하고 미제공 시 삭제하며 계정 식별/통합·상대 공개·인증/프로필 응답에 사용하지 않는다. 제공 거부만으로 로그인을 막지 않는다.

### AUTH-02 가입 단계 안내·재개

- 동의 → 키링 → 프로필 → 설문 → 희망 조건 → 동기화 순으로 서버가 확인한 미완료 단계에 안내한다. 저장한 입력을 복원하고 필수 단계 우회를 막는다.
- 최초 가입 완료 여부와 현재 새 매칭 준비 여부를 구분한다. 가입 완료 회원이 키링을 초기화하거나 AI 동의를 철회해도 처음 가입 화면으로 되돌리지 않는다. 기존 제안·채팅 권한은 각 기능 기준을 따른다.
- 필요 정보: 단계별 완료 상태, 현재 단계, 가입 완료 여부, 새 매칭 준비 여부, 동의 상태/버전. 상태 조회 실패를 완료로 처리하지 않는다.

### AUTH-03 회원탈퇴·재가입

- 등록 키링이 0개이면 최종 확인 후 일반 탈퇴한다. 1개이면 초기화를 안내하고, 분실이면 KEY-04로 연결한다. 소유 조회 실패를 0개로 판단하지 않는다.
- 탈퇴 성공 시 새 매칭 중지, 양쪽 유효 제안·활성 채팅 종료, 프로필 접근 차단, 모든 세션·푸시 연결 해제. 상대에게 탈퇴 사유를 공개하지 않는다. 데이터 삭제는 §7을 따른다.
- 탈퇴 완료부터 72시간 후 재가입 가능. 같은 소셜 계정이어도 새 가입 ID로 시작하며 과거 프로필·설문·제안·채팅을 복구하지 않는다. 제한 기간은 로그인·재시도로 연장하지 않는다.

### KEY-01 키링 등록·구매 안내

- 계정↔키링 연결 구조를 유지하며 **계정당 현재 등록 최대 1개**, 기기당 현재 소유자 1명을 보장한다. 꺼지거나 연결이 끊긴 키링도 등록 수에 포함한다.
- 버튼을 길게 눌러 등록 모드에 진입한 기기를 앱에서 탐색하고, 귀속·양도 전 초기화 안내에 동의하면 등록한다. 미보유자에게 구매 링크를 제공하되 구매만으로 등록 완료 처리하지 않는다.
- 서버 소유 연결 확인 후 완료. 타인 소유·영구 사용 불가 기기 거부, 동시 등록·중복 요청 방지. 필요 정보: 기기 고유번호, 소유 관계, 등록/초기화 상태, 사용 불가 상태.

### KEY-02 설정 동기화·이용 준비

- 현재 유효 성향 결과, 희망 조건, 사진 상태, 매칭·진동·LED 설정과 버전을 등록 키링에 전달한다. 기기의 실제 저장·적용 확인 후 준비 완료로 표시한다.
- 변경 시 자동 동기화, 사용자 수동 동기화, 한국시간 자정 자동 시도, 재연결 복구를 제공한다. 미연결·실패·반영 대기를 구분하며 자정 정각 완료나 오프라인 즉시 반영을 보장하지 않는다.
- 키링 재시작/방전 복구 후 신뢰할 시각·설정 확인 전 새 매칭 대기. 단순히 마지막 동기화 후 24시간이 지났다는 이유만으로 중단하지 않는다. 홈/설정에서 연결·배터리·펌웨어·최종 동기화·미업로드/상대 기록 대기 상태를 확인한다.

### KEY-03 키링 초기화

- 소유자가 로그인하여 실물 기기 초기화를 진행한다. **기기 초기화와 서버 소유 연결 해제 모두 확인한 뒤** 양도·재등록 가능으로 표시한다.
- 타인 계정이나 기기 버튼 단독 조작으로 소유권을 해제하지 않는다. 중단·부분 실패는 상태 조회·재시도로 복구한다.
- 마지막 키링 초기화 후 새 매칭 준비는 해제되지만 기존 유효 제안·채팅과 탈퇴 화면 접근은 유지한다.

### KEY-04 분실 문의·영구 사용 불가

- 앱에서 분실 문의 → 소셜 재로그인 → 서비스팀의 등록 관계 대조 → 사용자 대상 기기·영구 사용 불가·탈퇴 결과 확인 순으로 처리한다. 증빙 서류를 일괄 요구하지 않는다.
- 정상 보유 기기의 초기화 확인 후 분실 기기를 영구 사용 불가로 처리하고 탈퇴한다. 로그인 불가·등록 정보 불일치는 추가 확인 전 처리 보류. 문의 접수만으로 완료 표시하지 않는다.
- 분실 기기는 발견·초기화·재가입 후에도 어느 계정에서든 등록 불가. 문의 본문 삭제와 기기 사용 불가 상태를 분리하며 오프라인 즉시 중지는 보장하지 않는다.

### KEY-06 진동·LED·버튼 중지

- 충분한 정보를 교환해 조건을 통과했고 상대가 근처에 있을 때 안내한다. **양쪽 모두 진동 ON일 때만 양쪽 키링이 짧게 2회 진동**하며 같은 만남에는 한 묶음만 실행한다.
- LED는 각자 ON/OFF 적용. 만남별 같은 색을 사용하고 켜진 시점부터 30초 연속 점등 후 종료한다. 이탈 확인 시 즉시 끈다. 주변 다른 쌍과 색이 항상 다름을 보장하지 않는다.
- 버튼은 본인 키링의 현재/남은 진동과 LED를 즉시 중지한다. 설정·기록·제안은 유지하고 상대 기기를 중지시키지 않는다. 상대 이탈 후 지연 안내·재연결/업로드에 따른 지난 안내 재생은 하지 않는다.

## 3. 프로필·설문

### PRO-01 프로필 입력

- 최초 입력은 자동 임시 저장·복원. 최종 등록에서 필수값과 생년월일/성별을 재확인하고, 서버 성공 후 다음 단계로 이동한다. 초안 저장은 등록 완료가 아니다.
- 등록 완료 후 생년월일·성별은 사용자 직접 변경 불가이며 서비스팀 정정 요청을 안내한다. 서버도 우회 변경을 거부한다.
- 아래 입력 규칙을 적용하며 생년월일·소셜 식별값·설문 원응답·희망 조건은 상대에게 공개하지 않는다.

| 항목 | 입력 기준 | 상대 공개 |
| --- | --- | --- |
| 닉네임 | 필수. NFC 정규화·앞뒤 일반 공백 제거 후 2~20자. 완성형 한글·영문·숫자·일반 공백만 허용. 내부 공백 유지, 영문 대소문자 무시 중복 검사 | 공개 |
| 생년월일 | 필수. 한국 날짜 기준 만 19세 이상, 상한 없음. 2월 29일생은 평년 3월 1일에 나이 증가 | 계산한 나이만 |
| 성별 | 필수. 남성/여성 중 직접 선택, 기본 선택 없음 | 공개 |
| 흡연 | 필수 단일 선택. 비흡연 / 전자담배 / 술마실때만 가끔흡연 / 흡연 | 공개 |

| 종교 | 선택·별도 동의. 무교 / 개신교 / 천주교 / 불교 / 기타 / 공개하지 않음 | 미입력·비공개는 ‘종교 정보 비공개’ |

생활 항목이 겹치면 본인을 가장 잘 설명하는 하나를 선택한다. 음주는 술을 마신 날 기준으로 같은 날 1회, ‘중요한 자리’는 개인적으로 특별한 모임도 포함한다. ‘흡연’은 담배 종류와 무관한 포괄값이며 설문 Q055의 구체 종류로 자동 변환하지 않는다.

### PRO-02 사진 등록·교체·삭제

- 정사각형 자르기·위치 조정을 제공하고 HEIC는 앱에서 JPEG로 변환한다. 서버가 실제 형식·디코딩·용량을 검증하고 위치 등 메타데이터를 제거한다.
- 서버 처리와 프로필 연결 성공 후 등록 완료. 최초 업로드 실패는 미등록, 교체 중/실패는 기존 사진 유지, 삭제 성공은 기본 이미지로 표시한다.
- 현재 사진 URL과 등록 여부를 관리한다. 삭제 후 상대 재조회에서도 옛 사진을 표시하지 않는다. 업로드 진행 표시는 필요하지만 별도 사진 처리 상태 조회 API는 요구하지 않는다.

### PRO-03 프로필 수정·정정

- 일반 항목은 횟수·대기시간 제한 없이 수정한다. 가입 후 편집은 ‘저장’ 성공 시 공개하고, 미저장 이탈 확인·실패 시 입력 유지/재시도를 제공한다.
- 유효 제안에는 최신 공개 프로필을 표시한다. 조회 이후 정보가 바뀌었다면 갱신·안내 후 수락을 다시 확인한다. 이미 완료한 수락·기존 기한은 유지한다.
- 생년월일·성별은 앱 정정 요청 → 서비스팀 확인 → 결과 조회. 생년월일은 공식 증빙 대면 확인·사본 미보관, 성별은 계정 소유·본인 정정 의사를 확인하며 의료서류/신체 사진은 요구하지 않는다. 성인 정정은 기존 제안/채팅 유지, 연령 미달은 §6의 제한 절차를 적용한다.

정정 요청은 항목·요청값·필수 사유(최대 500자)를 받고 현재 값은 읽기 전용으로 표시한다. 첨부는 받지 않는다. 상태는 접수 → 검토 중 → 추가 확인 필요/정정 완료/반려/응답 없음으로 구분하며 실제 저장 성공 전 완료 처리하지 않는다.

### SUR-01 100문항 응답·이어하기

- 지원되는 100문항 설문 버전으로 회차를 생성하고 문항별 응답을 저장한다. 미응답·모름·상관없음을 구분하고 임의 중간값으로 바꾸지 않는다.
- 재진입 시 이어하기 ‘예’는 첫 미응답 문항, 전부 저장한 미제출 회차는 제출 단계로 이동한다. ‘아니요’는 응답을 보존하고 최초 가입은 가입 진행 요약, 재검사는 시작했던 홈/설정으로 복귀한다.
- 제출 성공과 계산 성공을 구분한다. 제출/저장 실패 시 완료 안내하지 않고 재시도를 제공한다. 지원 버전이 다른 응답을 순번만으로 섞지 않는다.

### SUR-02 내부 결과 계산·처리 상태

- 제출 응답의 검증·계산·저장 상태를 보여주되 개인 성향 점수/유형은 사용자에게 공개하지 않는다. 최초 유효 결과 저장 전 새 매칭을 시작하지 않는다.
- 입력 보완, 계산 대기, 기술적 실패, 상태 조회/버전 오류를 구분한다. 기술적 실패는 같은 제출 응답/버전으로 계산만 재시도하고 설문 재작성을 강요하지 않는다.
- Q97/Q98 재확인 기준은 §4. 완료 원응답을 덮어쓰지 않고 재응답이 필요하면 지원 버전의 별도 회차로 진행한다. 필요 정보: 회차·응답/규칙 버전·계산 상태·현재 유효 결과.

### SUR-03 재검사

- 횟수·대기 제한 없이 새 회차를 시작할 수 있다. 모든 문항을 미선택으로 두고 1번부터 시작하며, 진행 중 회차는 기존 이어하기 규칙으로 보존한다.
- 새 응답 작성·재확인·계산 대기/실패 중에는 **기존 유효 결과로 매칭을 유지**한다. 새 응답 검증·계산·저장이 모두 성공하면 별도 적용 버튼 없이 전환하고 키링 동기화를 시작한다.
- 새 결과로 기존 제안·수락·채팅·원래 기한을 바꾸지 않는다. 서버 전환 성공과 실제 기기 반영 성공을 따로 확인한다.

## 4. 매칭·제안

### MAT-01 상대 성별·희망 나이

- 상대 성별은 본인 성별의 반대로 자동 산출한다. 희망 나이는 상관없음/범위/상한 없음으로 설정하고, 범위는 양끝 포함·최소 19세·최소=최대 허용·상한 제한 없음이다.
- 범위 슬라이더와 숫자 직접 입력을 연동한다. 미선택을 상관없음으로 처리하지 않고 최소>최대·19세 미만·소수는 거부한다. 화면 표시 범위를 실제 나이 상한으로 사용하지 않는다.
- 양방향 희망 나이는 Q97과 무관하게 항상 검사한다. 저장 성공 후 새 매칭에 적용·동기화하며 기존 유효 제안은 유지한다.

### MAT-02 사진 있는 상대만 매칭

- 별도 옵션이며 기본 OFF. 각 사용자의 옵션과 상대의 사진 등록 여부를 양방향 검사한다. 한쪽이라도 ON이고 상대 사진이 없으면 새 매칭 불가다.
- 사진 등록 자체는 선택이다. 옵션 변경·사진 삭제로 기존 유효 제안·수락·원래 기한을 취소하지 않는다.
- 필요 정보: 본인 옵션, 상대 현재 사진 유무, 설정/기기 적용 버전.

### MAT-03 오프라인 매칭·만남 연결

- 준비된 키링끼리 **휴대폰·인터넷 없이 충분한 정보를 교환하고 양방향 적합도를 판단**한다. 발견만 하거나 서버에서만 판단하는 방식으로 대체하지 않는다.
- 기본 조건·관계 제한과 승인된 계산 규칙을 적용한다. 조건 확인을 마친 후보부터 처리하며 한 번에 한 상대를 안내한다. 계산 중 멀어지면 물리 안내를 생략하고 만남 기록을 남긴다.
- 양쪽의 유효한 동일 만남 기록이 서버에 모이면 최신 설정·소유·버전·관계 제한을 재검증해 제안 1건을 생성한다. 한쪽 기록만 있으면 대기이며 상대 프로필·수락 버튼을 제공하지 않는다.

**계산 정책**

- SIS-Q-1.1-100 참조 구조를 바탕으로 새 규칙 버전을 고정한다. 개인 유형과 두 사람의 매칭 점수는 다른 계산이다. 구버전과 신규 응답을 임의 혼용하지 않는다.
- 흡연·음주·종교는 일반 선호 점수에 반영한다. Q97에서 사용자가 선택한 흡연·자녀 계획·종교·문신 중 최대 2개는 허용 범위를 벗어나면 점수와 무관하게 제외한다. 음주·나이는 Q97 선택지가 아니다.
- Q97의 any는 제외 조건 없음. unknown/미응답은 재확인하며, 엄격 제외를 선택했는데 허용 범위가 any/unknown/미응답이면 구체 범위를 정하거나 제외 항목을 해제한다.
- Q98은 close/some/wide 명시 선택이 필요하다. unknown/미응답을 some으로 자동 계산하지 않는다. 재확인 전 새 응답 적용을 보류하고 기존 유효 결과는 유지한다.
- 방향별 50점·coverage 70%는 **검증 후보이며 최종 기준이 아니다**. 규칙 버전·정밀도·정보 출처와 실행 검증은 §8에 따른다.

**만남 수명·반복 억제**

- 만남 기회 마감은 만남 시각+7일. 상대 기록 대기 마감은 만남 기회 마감과 첫 유효 서버 접수+7일 중 빠른 시각이다. 기한 내 생성된 제안은 별도의 24시간을 가진다.
- 같은 상대의 미접수 만남·서버 기록 대기·유효 제안·활성 채팅 동안 같은 만남/안내를 반복 생성하지 않는다. 재전송·재연결로 기한을 다시 시작하지 않는다.
- 거절에는 기존 30일 제한을 적용한다. 응답 없이 자동 만료된 뒤 실제로 이탈·재접근한 새 만남은 다른 제한이 없으면 추가 대기기간 없이 허용한다. 옛 기록이나 지속 근접은 새 만남이 아니다.
- 차단 관계와 채팅 나가기/7일 종료/AI 철회 종료에 따른 재매칭 제한을 검사한다. 정책 기간 변경은 새 만남부터 적용하며 기존 만남의 약속한 기한을 유지한다.
- 기록 공간이 가득 차고 안전하게 지울 기록이 없으면 기존 유효 기록을 보존하고 새 매칭·출력을 대기한다. 업로드·공간 확보 후 조건을 확인해 자동 재개하며 저장된 스위치 값은 바꾸지 않는다.

### MAT-04 매칭 이유

- 제안 당사자에게 해당 만남의 실제 판단 근거·규칙 버전에 기반한 짧은 설명을 제공한다. 현재 프로필로 과거 매칭 이유를 새로 꾸미지 않는다.
- 상대 비공개 응답·희망 조건을 노출하거나 근거 없는 성공 확률을 만들지 않는다. 생성 실패는 확인된 근거의 규칙 문장으로 대체하며 제안 이용은 유지한다.
- 필요 정보: 당시 판단 근거/규칙 버전, 설명과 생성 버전. 상대가 먼저 거절했어도 미응답자의 설명 접근만 바꿔 응답을 드러내지 않는다.

### MAT-05 매칭 ON/OFF

- 매칭·진동·LED는 별도 스위치이며 모두 기본 ON. 저장값은 재접속·로그아웃·재연결로 초기화하지 않는다. 사진 필터는 별도로 기본 OFF다.
- 매칭 OFF 저장 후 서버 새 제안 생성을 중지하고 연결 기기에 반영한다. 기기 반영 후 새 매칭·진행 중 출력을 중지한다. 기존 제안 응답·채팅은 유지한다.
- 진동/LED OFF만으로 기록·제안·앱 제안 푸시를 중단하지 않는다. ON 복귀는 다른 준비 조건 확인 후 재개하며 종료된 제안을 복원하지 않는다. 미연결 기기의 물리 반영 여부를 구분한다.

### PROP-01 제안 목록·상대 프로필

- 수락 전에 사진·닉네임·소개·나이·성별·공개 생활 정보와 매칭 이유를 조회한다. 동일 만남은 각 사용자 목록에 한 건만 표시한다.
- 내 결정 전 상대 응답·응답 시각은 숨긴다. 상대 선행 거절만으로 목록·정렬·버튼·접근을 바꾸지 않는다. 단, 차단·탈퇴 등 독립된 접근 제한은 적용한다.
- 제안 생성 후 알림 권한·로그인/전달 조건에 따라 푸시를 제공한다. 옛 알림도 현재 계정·권한·기한을 재확인한다. 종료 이력 목록은 제공하지 않는다.

### PROP-02 수락·거절·24시간 만료

- **서버 제안 생성부터 24시간** 동안 미응답자는 수락/거절할 수 있다. 만남·푸시 수신·첫 조회 시각으로 기한을 바꾸지 않는다. 수락 후 취소나 거절 변경은 제공하지 않는다.
- 내 수락 시 상대 미응답이면 대기, 상대 수락이면 채팅 연결, 상대 거절이면 ‘매칭이 성사되지 않았어요’ 안내. 내가 거절하면 내 처리 결과만 안내한다.
- 양쪽 응답·만료·차단·탈퇴 경합을 서버에서 처리한다. 중복 요청/응답 유실은 저장 상태를 복구하며 제안·방을 중복 생성하지 않는다. 통신 실패를 거절/비성사로 표시하지 않는다.

## 5. 채팅·AI·신고·차단

### CHAT-01 상호 수락 후 채팅방 생성

- 유효 제안에 양쪽 수락이 확정되면 채팅방을 한 번만 생성한다. 한쪽 수락·거절·만료 상태에서는 생성하지 않는다.
- 방 수명은 생성부터 7일이다. 늦은 첫 입장·재접속·AI 재동의로 시작 시각을 바꾸지 않는다.
- 필요 정보: 연결 제안, 참여자, 생성/종료 예정 시각, 상태. 방 생성과 각 참여자의 실제 입장 가능 여부는 구분한다.

### CHAT-02 텍스트 메시지

- 활성 방의 권한 있는 참여자만 조회·전송한다. 원문 최대 1,000자(확장 그래핌 기준), LF 줄바꿈·이모지 허용, 공백뿐인 입력은 거부한다. 전송 성공/실패·재시도와 본인 목록의 새 메시지 표시를 제공한다.
- 원문 길이 검사 후 웹 주소를 서버에서 `[웹 주소 차단]`으로 치환해 저장·전달한다. 치환으로 길이가 늘어도 전체 결과를 보존하며 원래 URL을 미리보기·푸시로 노출하지 않는다.
- 상대 읽음 표시는 제공하지 않는다. 로그인·목록 조회·푸시 수신만으로 본인의 새 메시지를 확인 완료 처리하지 않는다. 재연결 순서·중복 전송 방지·본인 표시 해제 방식은 구현 계약으로 정한다.

주소 치환 대상은 HTTP/HTTPS·www·도메인/경로·단축 URL·국제화 도메인·IP 웹 주소다. 이메일·카카오톡 ID·일반 숫자는 제외하며 맛집/지도 등 서비스별 예외는 없다. 분할·변형 주소의 자동 치환은 보장하지 않는다. 첨부·보낸 메시지 수정/삭제·링크 열기/미리보기는 제공하지 않는다.

### CHAT-03 채팅 종료 상시 안내

- 첫 입장부터 상단에 실제 종료 예정 날짜·시각 또는 남은 시간과 종료 후 재조회 불가를 안내한다.
- 별도 첫 입장 확인 버튼이나 확인 저장 없이 채팅에 진입한다. AI 처리 안내는 제공하되 가입 동의를 대신하지 않는다.
- 기존 방의 종료 시각을 사용한다. 별도 안내 확인 상태나 종료 1시간 전 예약 알림을 요구하지 않는다.

### CHAT-05 채팅 자동 종료

- 방 생성 후 7일이 되면 양쪽 이용을 종료한다. 차단·나가기·탈퇴 등 조기 종료가 먼저 발생하면 실제 종료 상태를 따른다.
- 양쪽 목록에서 제거하고 조회·전송·AI 이용을 막는다. 열린 화면·옛 알림에는 일반 종료 안내 후 목록으로 이동하며 캐시·늦은 응답으로 내용을 다시 노출하지 않는다.
- 종료 방/대화 이력을 사용자에게 제공하지 않는다. 7일 종료·나가기 상대는 재매칭하지 않으며 다른 상대의 제안/채팅은 독립 처리한다.

### CHAT-06 채팅 보관·삭제

- 사용자 이용 종료와 서버 삭제를 구분한다. 채팅은 실제 종료부터 30일 보관 후 삭제하고, 이미 종료된 방의 기한을 탈퇴·재시도로 다시 시작하지 않는다.
- 본문과 연결된 AI 분석 기록은 원문 삭제 기한을 넘기지 않는다. 종료 후 서버 보관은 사용자 재조회나 지속 AI 분석을 허용하지 않는다.
- 신고된 방은 최초 신고부터 90일 보관하는 ERD retain_until 분기를 적용한다. 선택 메시지뿐 아니라 방 전체 메시지 보관이며 반복 신고/재시도로 기산을 연장하지 않는다. 보관 중 탈퇴의 참조 정리·일반 삭제와 우선순위·기각 시 처리 계약을 확인한다. 저장소별 삭제 실패 재시도·완료 확인·백업 복원 시 재삭제를 구현한다.

### AI-01 대화 시작 질문 추천

- 상호 수락한 활성 방에서 허용된 공개 정보로 AI가 질문 3개를 제안한다. 사용자가 선택·수정해 직접 전송하며 AI가 자동 전송하지 않는다.
- 질문을 쓰지 않고 바로 대화할 수 있다. 정보 부족·생성 실패는 일반 질문으로 대체하고 생성 지연 중에도 채팅을 막지 않는다.
- 비공개 설문·민감한 생활 정보를 추정해 소재로 사용하지 않는다. 종료된 방의 요청·늦은 결과를 차단한다. 허용 입력·생성 버전 계약이 필요하다.

### AI-02 위험 대화 감지

- 활성 방의 최소 문맥을 비동기로 분석한다. 사기/송금/위험 사이트 유도는 수신자 주의 안내, 욕설/모욕/성희롱/협박은 수신자 보호 안내와 발신자 존중 안내를 제공한다.
- 배너는 해당 사용자에게만 보이며 같은 방·사용자·유형별 최초 1회 표시한다. 수신자는 직접 차단으로 연결할 수 있다. 자동 메시지 차단·신고·상대 차단·제재는 하지 않는다.
- 정상·위험·판단 불충분·실패를 구분하고 분석 지연/실패로 기본 채팅을 막거나 안전 표시하지 않는다. 종료 방의 늦은 결과는 무시한다. 입력·동의·철회는 아래 공통 기준을 적용한다.

### SAFE-01 신고·상대 차단·채팅 나가기

- 신고 접수·사유/상세 입력·증거 메시지 선택·운영 검토를 MVP에 포함한다. chat_report/chat_report_message와 운영 감사에 대응하며 BE가 공개 요청/응답과 한도를 확정한다.
- 서버는 신고자 참여 권한과 증거 메시지의 같은 방 소속을 검사한다. FE는 실제 접수 성공을 확인하고 응답 유실/중복 요청을 복구한다. AI 안내만으로 자동 신고하지 않는다.
- 운영 조회·처리 상태와 신고 보관은 [ERD 범위 및 수용 기준](reviews/erd-mvp-scope-20261028.md)을 따른다. 신고 재도입은 차단 해제나 AI 신고 우선순위 분류 기능을 자동 추가하지 않는다.

- 차단 전 현재 제안/채팅 종료·향후 매칭 제한·이번 버전에서 해제 불가를 안내하고 확인받는다. 성공 시 양쪽 유효 제안·활성 채팅을 종료하고 차단 관계 중 새 매칭을 금지한다.
- 한 명이 채팅방을 나가면 양쪽 방 종료 및 해당 상대 재매칭 금지. 나가기 전에 대화 재조회 불가와 재매칭 불가를 안내한다.
- 상대에게 구체 종료 사유를 공개하지 않는다. 실패는 재조회/재시도하며 중복 처리로 종료 시각을 바꾸지 않는다. 차단 관계와 종료 사유는 보존하되 사용자 차단 목록/해제 기능은 제공하지 않는다.

## 9. 공통 완료 확인

- Android·iOS의 가입/권한·BLE·푸시/복구를 실제 기기에서 확인한다. 서버에 만남 위치를 저장하거나 상대에게 세부 위치·만남 시각을 공개하지 않는다.
- BLE는 회전 임시 ID·기기 인증·세션 보호·위조/재전송 방지와 최소 입력 교환을 적용한다. 고정 사용자 ID 광고·사진/소개 원문 교환은 하지 않는다.
- 대표 2대의 복구/출력과 완충 후 24시간 이상 동작을 측정하고, 완성 10대의 편차·혼잡/중복·출고/통합 시연을 확인한다. 빌드 성공이나 가상 결과가 실물 검증을 대신하지 않는다.
- 한국어 MVP에서도 문구/오류 코드·날짜/숫자 표현을 로직과 분리해 다국어 확장 가능한 구조로 둔다.
