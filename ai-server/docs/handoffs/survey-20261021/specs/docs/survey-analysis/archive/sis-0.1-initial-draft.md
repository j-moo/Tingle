# Suddenly I See 가입 설문과 매칭 설계 초안

작성일 2026년 10월 19일 · 설문 버전 SIS 0.1 · 추천 정책 버전 MATCH 0.1

이 설계는 72개 가입 문항으로 본인의 성향, 생활 방식, 상대에게 바라는 모습을 파악하고, 키링에서 넓은 범위의 만남 후보를 추천하기 위한 초기 구현안이다. 문항, 계산값, 유형 이름, 유형별 연결표는 모두 팀이 검증하고 조정할 초안이다. 검증된 심리검사나 연애 성공 확률을 제공하는 모델은 아니다.

결과는 **주 유형 + 보조 유형 + 생활 리듬 + 바라는 상대의 특징 + 연결 후보 유형**으로 구성한다. 생활 방식과 상대 선호도 같은 검사와 결과에 포함한다. 다만 상대에게 원하는 성격을 본인의 성격으로 계산하지는 않는다.

기존 기획서 v1.2의 오프라인 키링 판정, 양쪽 기록 검증, 상호 수락, 알림 설정, 차단과 관계 제한 정책을 유지한다. 이 문서는 그중 설문과 추천 규칙을 구체화한다.

## 연구에서 참고하는 부분과 직접 정하는 부분

| 구분 | 연구에서 가져오는 내용 | 이 설계에서 직접 정한 내용 |
|---|---|---|
| 사랑 태도 | LAS가 구분하는 사랑에 대한 태도, 특히 우정 기반 관계·현실적 고려·헌신의 관점 | 관계 속도 F, 현실적 조율 V, 행동으로 돕는 방식 H라는 자체 영역과 문항 |
| 사랑의 구성 요소 | TLS의 친밀감·열정·헌신이라는 구분 | 가입자의 평소 자기개방 I, 장기 관계 지향 C로 재구성. 애정 표현 E는 자체 영역 |
| 애착 | ECR-RS의 관계 불안과 회피를 구분하는 관점 | 관계 안심 확인 R을 탐색하는 자체 문항. 애착 유형이나 임상적 불안을 진단하지 않음 |
| 일반 성향 | IPIP 및 Big Five의 외향성·개방성·성실성 관련 개념 | 사교적 에너지 S, 새로운 경험 N, 계획 P라는 좁은 영역. Big Five 전체 점수로 부르지 않음 |
| 설문 개발 | 영역 정의, 문항 검토, 사전 조사, 구조·신뢰도·타당도 검토 절차 | 72문항, 12개 성향 영역, 각 4문항, 제외·보완 기준 |
| 양방향 추천 | 두 사람 각각의 선호를 고려하는 RECON의 접근 | 선호 범위, 기하평균, 45·30·25 가중치, 60점 기준 |
| 추천 설명 | 상호 추천에서 이유를 제공하는 연구 | 키링의 근거 코드와 검증된 응답에 연결된 한국어 설명 |

**아래 72문항은 모두 새로 작성한 자체 문항이다.** 기존 검사의 번역본이나 단축판이 아니다. 연구의 타당도·신뢰도가 이 문항들로 그대로 이어지지 않는다. 자율성 A를 회피 애착으로, 안심 확인 R을 집착으로 해석하지 않는다. 사랑 태도의 유희성이나 소유욕을 건강한 자율성·표현 선호로 바꾸어 같은 척도라고 주장하지도 않는다.

## 검사 구성과 응답 방식

| 문항 | 내용 | 결과에서 하는 역할 |
|---|---|---|
| 1~48 | 12개 성향 영역을 각 4문항으로 탐색 | 평소 관계 방식과 주 유형 |
| 49~60 | 연락·만남·시간·취미·데이트·예산·흡연·음주·관계 목적과 일부 상대 선호 | 생활 리듬, 관계 방향, 생활 관련 추천 근거 |
| 61~72 | 12개 성향에 대해 편하게 느끼는 상대의 모습 | 바라는 상대 특징, 선호 유형, 양방향 추천 |

총 72개이며, 복수 선택은 하나의 질문 안에서 답한다. 계정 정보, 성인 여부 확인, 만남 대상 설정, 사진과 알림 설정은 서비스 운영 설정이며 성향 점수에 섞지 않는다.

1~48번은 다음 답변을 공통으로 쓴다.

- 1 전혀 그렇지 않다
- 2 그렇지 않은 편이다
- 3 중간 정도다
- 4 그런 편이다
- 5 매우 그렇다
- 잘 모르겠다 또는 판단할 경험이 없다

사용자 안내: “좋은 답이나 나쁜 답은 없어요. 평소 가까운 관계에서의 모습을 떠올려 주세요. 연애에 대한 질문은 현재의 생각과 선호를 기준으로 답해 주세요. 판단하기 어려우면 ‘잘 모르겠다’를 선택할 수 있어요.”

‘잘 모르겠다’는 중간 점수가 아니다. 아래의 R 표시는 개발용 역채점 표시이며 사용자 화면에는 노출하지 않는다. 모든 질문은 비공개로 수집하며, 상대방에게 원문 답변을 공개하지 않는다.

## 성향 문항 48개

### F 관계가 가까워지는 속도

낮으면 시간을 두고 가까워지는 편, 높으면 호감이 생긴 뒤 빠르게 관계를 발전시키는 편이다. LAS의 관계 태도를 참고했지만 이 속도 축 자체는 팀 정의다.

| 번호 | 실제 문항 |
|---|---|
| Q01 | 관심이 생긴 사람은 이른 시일 안에 다시 만나 더 알아보고 싶다. |
| Q02 | 서로 호감이 확실해지면 관계를 발전시키는 결정을 미루지 않는 편이다. |
| Q03 | 서로 마음이 맞는다면 짧은 기간 안에 연애를 시작해도 편안하다. |
| Q04 | 연애를 시작하기 전에는 친구처럼 지내는 시간이 충분히 필요하다. R |

### E 애정을 드러내는 정도

낮으면 표현이 차분하거나 적은 편, 높으면 마음을 자주 드러내는 편이다. 애정의 깊이나 사랑할 능력을 평가하지 않는 자체 영역이다.

| 번호 | 실제 문항 |
|---|---|
| Q05 | 좋아하는 마음을 말로 자주 전하는 편이다. |
| Q06 | 작은 호감도 상대가 알아차릴 수 있도록 표현하는 편이다. |
| Q07 | 상대에게 고마움이나 애정을 느끼면 그때그때 표현한다. |
| Q08 | 마음이 커도 애정 표현을 자주 하지는 않는 편이다. R |

### I 속마음을 나누는 정도

낮으면 마음을 천천히 열거나 사적인 생각을 간직하는 편, 높으면 깊은 이야기를 나누는 편이다. TLS 친밀감 개념을 참고한 자기개방 영역이다.

| 번호 | 실제 문항 |
|---|---|
| Q09 | 가까운 사람에게 내 속마음을 구체적으로 이야기하는 편이다. |
| Q10 | 걱정이나 고민이 생기면 가까운 사람과 나누는 편이다. |
| Q11 | 나에게 중요했던 경험과 그 의미를 상대에게 이야기하고 싶다. |
| Q12 | 기쁨이나 걱정처럼 개인적인 감정은 혼자 간직하는 편이다. R |

### C 장기 관계 지향

낮으면 현재의 만남과 탐색을 중시하고, 높으면 관계의 지속 가능성을 중시한다. TLS 헌신 개념에서 출발한 현재의 지향이며, 성실성이나 도덕성 평가가 아니다.

| 번호 | 실제 문항 |
|---|---|
| Q13 | 누군가를 만날 때 장기적으로 함께할 수 있을지도 생각한다. |
| Q14 | 앞으로도 서로의 삶에 함께하는 관계를 만들고 싶다. |
| Q15 | 지금 즐겁더라도 오래 이어가기 어려워 보이면 관계 시작에 신중해진다. |
| Q16 | 지금은 오래갈지 생각하기보다 알아가는 경험 자체에 더 관심이 있다. R |

### A 개인 시간과 자율성

낮으면 함께 보내는 시간을 많이 원하고, 높으면 개인 생활을 따로 유지하는 것을 중시한다. 자체 영역이며 회피 애착을 측정하지 않는다.

| 번호 | 실제 문항 |
|---|---|
| Q17 | 연애 중에도 혼자 취미를 즐기는 시간이 필요하다. |
| Q18 | 연인과 별개로 친구를 만나거나 모임에 참여하는 시간을 유지하고 싶다. |
| Q19 | 쉬는 날에도 연인과의 일정 외에 내 시간을 따로 남겨두고 싶다. |
| Q20 | 여가 시간은 가능하면 대부분 연인과 함께 보내고 싶다. R |

### R 관계에 대한 안심 확인

낮으면 별도 표현 없이도 마음이 유지된다고 느끼는 편, 높으면 표현을 통해 관계를 확인하는 것을 중시한다. ECR-RS의 관계 불안 개념을 참고한 자체 영역이다.

| 번호 | 실제 문항 |
|---|---|
| Q21 | 관계가 익숙해져도 상대가 좋아하는 마음을 가끔 말해주면 좋겠다. |
| Q22 | 서로 바쁠 때도 마음은 변함없다고 알려주면 안심이 된다. |
| Q23 | 우리 관계가 잘 이어지고 있다는 이야기를 나누면 마음이 안정된다. |
| Q24 | 한동안 애정 표현이 없어도 상대의 마음이 이어지고 있다고 느끼는 편이다. R |

### S 사교적 에너지

낮으면 조용하거나 소수인 자리를 선호하고, 높으면 새로운 사람이나 여럿이 있는 자리에서 활기를 느끼는 편이다. IPIP 외향성 관련 개념을 참고한다.

| 번호 | 실제 문항 |
|---|---|
| Q25 | 새로운 모임에서도 여러 사람과 대화를 나누는 편이다. |
| Q26 | 여러 사람과 함께 시간을 보내면 에너지가 생기는 편이다. |
| Q27 | 처음 만난 사람에게 먼저 말을 거는 것이 비교적 편하다. |
| Q28 | 사람들과 모이는 자리보다 혼자 조용히 쉬는 시간이 더 편하다. R |

### N 새로운 경험 선호

낮으면 익숙한 경험을 선호하고, 높으면 새로운 경험을 선호한다. IPIP 개방성 관련 개념 중 일부를 참고한다.

| 번호 | 실제 문항 |
|---|---|
| Q29 | 익숙하지 않은 취미라도 흥미가 생기면 해보고 싶다. |
| Q30 | 쉬는 날에는 가보지 않은 장소를 찾아가는 것이 즐겁다. |
| Q31 | 평소와 다른 메뉴나 활동을 선택하는 편이다. |
| Q32 | 새로운 데이트 코스를 찾기보다 좋았던 코스를 반복하는 편이 좋다. R |

### P 약속과 활동의 계획 정도

낮으면 그때그때 정하는 편, 높으면 미리 계획하는 편이다. IPIP 성실성 관련 개념 중 계획성을 참고하며 책임감 전체를 판단하지 않는다.

| 번호 | 실제 문항 |
|---|---|
| Q33 | 약속의 시간과 장소를 미리 정해두는 편이다. |
| Q34 | 주말에 할 일을 며칠 전에 생각해두는 편이다. |
| Q35 | 데이트할 때 어느 정도 계획이 정해져 있으면 편하다. |
| Q36 | 그날의 기분에 따라 장소나 활동을 정하는 편이 좋다. R |

### T 갈등을 이야기하는 시점

낮으면 정리할 시간을 가진 뒤 대화하고, 높으면 빠르게 대화하는 편이다. 갈등 해결 능력의 우열이 아닌 자체 영역이다.

| 번호 | 실제 문항 |
|---|---|
| Q37 | 서운한 일이 생기면 가능한 한 그날 이야기하고 싶다. |
| Q38 | 의견이 다를 때 오래 기다리기보다 빠르게 대화를 시작하는 편이다. |
| Q39 | 갈등에 대한 이야기를 미루면 오히려 더 신경이 쓰인다. |
| Q40 | 다툰 뒤에는 감정이 가라앉을 시간을 가진 후 이야기하고 싶다. R |

### V 현실적인 생활 조율 중시

낮으면 끌림을 바탕으로 차이를 알아가는 편, 높으면 생활과 미래 방향을 먼저 고려하는 편이다. LAS의 Pragma 개념을 참고한 자체 영역이다.

| 번호 | 실제 문항 |
|---|---|
| Q41 | 서로의 생활과 미래 방향이 맞는지를 중요하게 생각한다. |
| Q42 | 시간을 쓰거나 돈을 쓰는 방식이 어느 정도 맞는 관계를 선호한다. |
| Q43 | 관계를 시작하기 전에 실제로 자주 만날 수 있는지 같은 현실적인 부분을 생각한다. |
| Q44 | 끌림이 있다면 생활 방식의 차이는 사귀면서 알아가도 괜찮다. R |

### H 행동으로 돕는 방식

낮으면 듣거나 곁에 있는 방식으로 돕는 편, 높으면 구체적인 행동으로 돕는 편이다. LAS의 Agape를 개념적 출발점으로 삼지만 희생·헌신 전체를 측정하지 않는다.

| 번호 | 실제 문항 |
|---|---|
| Q45 | 가까운 사람이 힘들어하면 내가 실제로 도울 수 있는 일을 찾는 편이다. |
| Q46 | 상대가 바쁠 때는 부담을 덜어줄 작은 일을 도와주는 편이다. |
| Q47 | 상대에게 필요한 지원이 떠오르면 해줄 수 있는 일을 먼저 제안한다. |
| Q48 | 누군가를 도울 때 직접 행동하기보다 이야기를 들어주는 쪽에 가깝다. R |

## 생활 방식과 관계 선호 문항 12개

아래 문항과 선택지는 모두 서비스 목적에 맞춘 자체 설계다. 단일 문항 생활 정보에는 심리척도의 신뢰도 해석을 적용하지 않는다. 선호 범위는 추천에 반영하는 부드러운 조건이며, ‘절대 불가’라는 표현을 사용하지 않는다.

## 점수 계산

이 절의 계산식·가중치·구간은 모두 팀이 정한 초기 규칙이다.

### 성향 점수

각 성향은 연속된 4문항에 연결한다. F=1~4, E=5~8, I=9~12, C=13~16, A=17~20, R=21~24, S=25~28, N=29~32, P=33~36, T=37~40, V=41~44, H=45~48이다.

```text
일반 문항 변환값 = 응답값
역채점 문항 변환값 = 6 − 응답값
성향 점수 = 25 × (유효 변환값의 평균 − 1)
```

역채점 번호는 4, 8, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48이다. 각 영역에서 유효 답변이 3개 이상이어야 점수를 만든다. 2개 이하면 해당 영역은 미측정이다. 답변 개수는 별도로 보존하며 통계적인 신뢰 확률로 표시하지 않는다.

예: Q05~08에 4, 5, 4, 2를 답하면 변환값은 4, 5, 4, 4다. 평균 4.25이므로 E=81.25이다. 81.25는 사랑할 능력, 상위 백분위, 검사 정확도를 뜻하지 않는다.

결과 설명을 위한 초기 구간은 0 이상 40 미만=낮은 쪽, 40 이상 60 이하=중간, 60 초과 100 이하=높은 쪽이다. 낮거나 높은 영역 중 50에서 가장 멀리 있는 두 영역을 보조 특징으로 쓴다. 동점이면 영역 코드 순서 F,E,I,C,A,R,S,N,P,T,V,H를 사용한다. 중간 영역뿐이면 양쪽 선호가 섞였다고 표현한다.

### 생활 정보

Q49, Q50, Q53, Q54의 ①~⑤를 각각 0,25,50,75,100으로 변환한다. 실제 횟수·금액 사이 간격이 같다는 가정이 아니라, 초기 추천용 순서 점수다. 원래 범주도 함께 보관한다.

Q51은 14칸 비트 집합, Q52는 10개 활동 비트 집합으로 저장한다. Q55와 Q59는 0,1,2의 범주 번호, Q57은 0,1,2,3의 범주 번호를 사용한다. Q56·58·60은 선택한 범주의 집합 또는 명시적인 ANY다. 모두 성격 점수에 더하지 않는다.

### 상대 성향 선호

Q61~72를 F,E,I,C,A,R,S,N,P,T,V,H 순서의 선호 범위로 저장한다.

| 선택 | 원하는 상대 점수 범위 |
|---|---|
| 가 | 0~40 |
| 나 | 30~70 |
| 다 | 60~100 |
| 상관없음 | ANY, 해당 조건에 가중치 없음 |
| 판단 어려움 또는 무응답 | UNKNOWN, 선호를 모름 |

범위가 일부 겹치도록 해 경계값에서 과하게 갈리지 않게 한다. ANY와 UNKNOWN은 서로 다른 상태이며, 둘 다 중간 선호로 바꾸지 않는다.

## 결과 유형

```text
성향 차이 d_core(k) = 측정된 성향별 |내 점수 − 유형 k 기준값|의 평균
생활 차이 d_life(k) = Q49·50·53 중 측정된 값의 |내 점수 − 기준값| 평균

유형 설명 점수 = 100 − d(k)
```

가장 가까운 유형을 주 유형으로 쓴다. 두 번째 유형의 설명 점수가 첫 번째와 3점 이내이면 보조 유형도 표시한다. 동점 순서는 표의 위에서 아래다. 가장 높은 설명 점수가 65 미만이면 주 이름 대신 ‘여러 성향이 섞인 모습’을 표시하되 아래의 연속 가중치는 유지한다.

유형 계산에는 성향 12개 중 9개 이상, Q49·50·53 중 2개 이상이 필요하다. 부족하면 입력을 저장하고 유형 확정을 보류한다. 이는 추천 조건을 많이 충족하라는 뜻이 아니라, 비교할 자료의 최소량이다.

### 유형 경계에서 추천이 갑자기 바뀌지 않게 하는 방법

주 유형 하나만 키링에 넣지 않는다. 앱에서 8개 유형 각각에 가까운 정도를 계산한다.

```text
raw(k) = exp(−(d(k) − 가장 작은 d) / 6)
w(k) = raw(k) / 모든 raw의 합
```

w는 유형에 대한 계산 가중치이며 ‘그 유형일 확률’이 아니다. 앱은 w×255를 먼저 내림한 뒤, 남은 값을 소수 부분이 큰 유형부터 1씩 배분해 합이 255인 8개 정수로 만든다. 소수 부분 동점이면 표 순서를 사용한다. 키링에서는 이 정수 가중치만 사용한다.

4. Q61~72에서 나온 바라는 상대 특징
5. 유형 연결표와 본인의 선호를 함께 반영한 연결 후보 유형 3개

예시 문구: “BLOOM · 천천히 피어나는 관계형. 차분하게 알아가며 속마음을 나누는 편이에요. 주말 저녁의 만남과 부담 없는 데이트를 선호하고, 마음을 자주 표현해 주는 상대를 편하게 느껴요.” 이는 표시 형식 예시이며 실제 응답이 뒷받침할 때만 사용한다.

연결 후보 유형을 표시할 때는 아래 T의 계산 방식을 이용해 내 유형 가중치와 후보 유형 한 개를 비교한 점수에 0.6을, 아래 선호 적합도 방식으로 내 Q61~72와 후보 기준값을 비교한 점수에 0.4를 준다. ANY는 제외한다. 사용할 선호가 없으면 유형 점수만 쓴다. 상위 3개를 보여주며, 실제 사람 추천은 상대의 선호와 생활 정보까지 계산하므로 이 목록 밖에서도 가능하다.

## 유형별 연결 기준

아래 연결은 모두 초기 제품 가설이다. 같은 유형이 무조건 잘 맞거나 다른 유형이 나쁘다는 의미가 아니다. 수치는 결과 화면의 궁합 퍼센트로 보여주지 않는다.

| 내 유형 | 기본 연결 후보로 넓게 보는 다른 유형 | 설계상 고려한 접점 |
|---|---|---|
| LUMI | BLOOM, SPARK, HAVEN, QUEST, MUSE | 표현, 교감 또는 함께하는 경험 |
| BLOOM | LUMI, HAVEN, MUSE, DUSK | 시간을 두는 관계, 깊은 대화 또는 차분한 일상 |
| SPARK | LUMI, ORBIT, QUEST | 표현, 새로운 경험 또는 빠른 접근 |
| ORBIT | SPARK, QUEST, MUSE, DUSK | 개인 시간 존중, 경험 또는 여유 있는 리듬 |
| HAVEN | LUMI, BLOOM, MUSE, DUSK | 일상의 공유, 지속성 또는 깊은 대화 |
| QUEST | LUMI, SPARK, ORBIT | 함께하는 활동과 새로운 경험 |
| MUSE | LUMI, BLOOM, ORBIT, HAVEN, DUSK | 깊은 대화, 개인 시간 또는 차분한 교류 |
| DUSK | BLOOM, ORBIT, HAVEN, MUSE | 느긋한 일상, 개인 시간 또는 편안한 교류 |

동일 유형도 후보에 포함한다. 표 밖의 유형은 제외 대상이 아니다. 생활 방식과 양방향 선호가 맞으면 충분히 추천될 수 있다.

|---|---|---|---|---|---|---|---|---|
| LUMI | 90 | 85 | 85 | 60 | 85 | 80 | 85 | 65 |
| BLOOM | 85 | 90 | 65 | 65 | 90 | 60 | 90 | 85 |
| SPARK | 85 | 65 | 90 | 85 | 55 | 90 | 60 | 60 |
| ORBIT | 60 | 65 | 85 | 90 | 60 | 90 | 85 | 85 |
| HAVEN | 85 | 90 | 55 | 60 | 90 | 60 | 85 | 85 |

80점 이상인 조합을 위 표의 기본 연결 후보로 정의한다. 주 유형만 쓴다면 표의 한 칸이지만, 실제 계산에서는 8개 유형 가중치를 모두 반영한다.

```text
T = Σi Σj [A의 정수 유형 가중치 i × B의 정수 유형 가중치 j × 연결표(i,j)] / 255²
```

T는 두 사람의 유형 조합 점수다. 대칭표이므로 A와 B의 순서를 바꿔도 같다. ‘불안한 사람과 거리를 두는 사람이 서로 보완한다’ 같은 근거 없는 보완 궁합 규칙은 두지 않는다.

## 양방향 추천 계산

유형 T, 생활 L, 상대 선호 P를 계산한다. 여기서 사용하는 모든 숫자와 유사도 함수는 초기 구현 규칙이다.

### 생활 조합 점수 L

생활·관계 영역은 총 9개다. 연락, 만남 빈도, 가능한 시간대, 함께할 활동, 데이트 활동성, 예산, 흡연 선호, 음주 선호, 관계 목적 선호다.

| 비교 영역 | 계산 |
|---|---|
| 연락 Q49 | 100 − 두 사람 순서 점수의 절댓값 차이 |
| 만남 Q50 | 위와 같음 |
| 시간 Q51 | 100 × 겹치는 칸 수 / 두 사람 중 선택 칸 수가 적은 쪽의 칸 수 |
| 활동 Q52 | 100 × 공통 활동 수 / 두 사람 중 선택 활동 수가 적은 쪽의 활동 수 |
| 데이트 활동성 Q53 | 100 − 순서 점수의 절댓값 차이 |
| 예산 Q54 | 위와 같음 |
| 흡연 Q55·56 | 아래의 범주 선호를 양방향 비교 |
| 음주 Q57·58 | 아래의 범주 선호를 양방향 비교 |
| 목적 Q59·60 | 아래의 범주 선호를 양방향 비교 |

시간과 활동은 많이 선택한 사람에게 불이익을 주지 않도록 작은 집합 기준의 겹침을 쓴다. 선택이 없거나 정보가 없으면 0으로 나누지 않고 해당 영역을 제외한다.

범주 선호는 다음과 같다.

```text
A가 B의 생활 습관을 편하게 느끼는 점수
= 100 × (1 − B의 범주와 A가 선택한 가장 가까운 범주 사이 거리 / (범주 수 − 1))
```

예: 흡연 범주가 0,1,2일 때 A는 0을 선호하고 B가 1이면 50점이다. 범위를 벗어났다는 이유만으로 전체 추천을 탈락시키지 않는다. 실제 서비스에서 사용자가 별도로 지정한 강제 제외 설정이 있다면 그 설정을 먼저 따른다.

각 영역에서 양쪽 방향 점수가 있으면 기하평균 `sqrt(A→B × B→A)`를 쓴다. 한쪽만 ANY이면 선호를 지정한 쪽의 점수만 쓴다. 양쪽 모두 ANY이면 해당 영역은 비교에서 제외한다. UNKNOWN이나 본인 습관 미응답은 일치·ANY로 취급하지 않으며 계산 가능한 방향만 사용한다. 두 방향 모두 비교 불가능하면 영역을 제외한다.

L은 계산 가능한 9개 영역 점수의 단순 평균이다. 최소 4개 영역이 계산 가능해야 한다. 어떤 생활 영역도 그것 하나만으로 탈락시키지 않는다.

### 상대 성향 선호 점수 P

각 성향에서 A가 원하는 범위와 B의 실제 성향 점수를 비교한다.

```text
B의 점수가 A의 선호 범위 안이면 거리 d = 0
범위 밖이면 d = 가장 가까운 범위 경계와 B 점수의 차이
해당 성향 선호 적합도 = max(0, 100 − 1.5 × d)
```

예: A가 표현이 많은 상대를 골라 범위가 60~100이고 B의 E가 50이면 85점이다. B의 E가 20이면 40점이다. 조금 다른 정도를 완전 불일치로 처리하지 않는다.

```text
P_A→B = A가 선호를 지정했고 B가 측정된 성향들의 적합도 평균
P_B→A = 반대 방향 적합도 평균
P = sqrt(P_A→B × P_B→A)
```

ANY는 평균에서 제외한다. 한쪽이 12개 모두 ANY를 명시했다면 상대 방향 점수만 P로 사용한다. 둘 다 12개 모두 ANY라면 P는 없으며 아래 최종식에서 가중치를 재배분한다. ANY가 아닌 선호의 존재를 UNKNOWN으로 추정하지 않는다.

입력 부족 처리: 각자 Q61~72 중 최소 9개는 가·나·다·ANY 중 하나로 답해야 한다. 지정한 선호가 있는 방향은 그중 최소 절반의 상대 성향이 측정되어야 P를 계산한다. 절반 미만이면 그 쌍은 자료 부족으로 판정을 보류한다. 알려진 선호가 하나도 없지만 UNKNOWN이 남아 있는 경우도 ‘모두 상관없음’으로 보지 않고 보류한다.

이 기하평균은 한쪽의 높은 선호 적합도가 다른 쪽의 낮은 적합도를 완전히 덮지 않도록 하는 팀 선택이다. RECON 논문의 공식을 그대로 구현한 것은 아니다. 두 방향 각각 70점 이상 같은 별도 통과 조건은 두지 않는다.

### 최종 추천 기준

```text
S = 0.45 × T + 0.30 × L + 0.25 × P
S가 60 이상이면 추천 후보로 연결
```

양쪽이 모든 상대 성향에 ANY를 명시하여 P가 없을 때만 `S = (0.45×T + 0.30×L) / 0.75`로 계산한다. T나 L의 최소 자료가 부족한 경우는 자료 보완 전까지 판정을 보류한다. 미응답 때문에 필요한 비교가 불가능한 상태와 성향이 맞지 않는 상태를 구분한다.

60점은 파일럿을 위한 시작값이다. 연애 성공 가능성 60%를 의미하지 않는다. 유형에는 생활 리듬 일부가 들어가므로 생활 정보가 T와 L 양쪽에 영향을 준다. 또한 C와 관계 목적처럼 관련된 정보가 있어, 45·30·25를 독립 요인의 과학적 기여율로 해석하지 않는다. 파일럿에서 유형 없는 비교안과 비교해 중복 영향도 확인한다.

| 예시 | T | L | A→B | B→A | 최종 S | 판단 |
|---|---|---|---|---|---|---|
| 한쪽 선호가 70 미만이어도 연결 | 80 | 70 | 80 | 60 | 약 74.32 | 추천 |
| 기본 연결 유형이고 일부 차이가 있음 | 85 | 40 | 40 | 40 | 60.25 | 추천 |
| 유형 접점은 적지만 생활과 선호가 맞음 | 55 | 85 | 85 | 85 | 71.50 | 추천 |
| 유형만 비슷하고 실제 원하는 방식은 크게 다름 | 85 | 20 | 20 | 20 | 49.25 | 이번에는 추천하지 않음 |

이 표는 계산 예시다. 실제 유형 가중치에서 해당 T가 반드시 발생한다는 뜻은 아니다. 점수는 사용자에게 ‘궁합 확률’로 보여주지 않고 추천 여부와 확인된 이유만 보여준다.

## 키링과 앱에서 적용하는 순서

1. 앱에서 문항 점수, 성향 범위, 생활 요약, 유형 가중치를 계산한다.
2. 시간·정책 버전·설정과 함께 키링에 전달하고 저장 완료 응답을 받는다.
3. 키링끼리 인증된 교환으로 필요한 요약값과 관계 제한 상태를 확인한다.
4. 기존의 강제 제외 정책을 통과하면 T, L, P, S를 계산한다.
5. 추천 기준을 통과하면 후보 처리 차례에 근접 상태를 다시 확인한다.
6. 양쪽이 같은 이벤트와 판정 근거를 합의하고 내구성 있게 기록한다.
7. 양쪽 알림이 모두 ON이면 같은 LED와 진동, 어느 한쪽 OFF이면 양쪽 모두 기록만 남긴다.
8. 서버가 기한 내 양쪽 기록을 수신·검증한 후 앱에 익명 제안과 추천 이유를 표시한다.
9. 두 사람이 모두 수락하면 프로필 공개와 채팅으로 이어진다.

매칭 OFF, 사진 미등록 상대 제외, 차단, 거절 제한, 활성 채팅, 영구 재매칭 제한, 처리 중인 동일 쌍 이벤트는 기존 정책대로 먼저 처리한다. 점수가 높아도 이 조건을 우회하지 않는다. 키링은 자신이 동기화한 제한만 알 수 있으므로 서버에서 최신 상태를 다시 검사한다.

여러 후보는 기존 기획대로 조건 확인 완료순으로 처리한다. S가 높은 순으로 대기열을 바꾸지 않는다. 만남 기한 7일, 양쪽 검증 후 제안 24시간, 명시적 거절 30일 등 기존 기한도 바꾸지 않는다.

### 키링에 필요한 정보

| 묶음 | 내용 |
|---|---|
| 판정 요약 | 12개 성향 점수와 유효 여부, 8개 유형 가중치, 12개 선호 범위 코드 |
| 생활 요약 | 연락·만남·데이트·예산 범주, 시간·활동 집합, 흡연·음주·목적 범주와 원하는 집합 |
| 운영 정보 | 매칭·알림·사진 설정, 관계 제한 상태, 만료에 필요한 시간 기준 |

원문 문항 답변, 이름, 사진, 자세한 위치를 키링 광고 패킷에 넣지 않는다. 성향 요약도 누구나 읽는 방송 데이터로 보내지 않는다. 개인정보 전송·보관의 세부 보안 계약과 실제 하드웨어 동작은 별도로 구현·검증해야 한다.

양쪽은 동일하게 지원하는 판정 버전으로 계산한다. 공통 지원 버전이 없으면 임의로 서로 다른 규칙을 쓰지 않고 동기화 후 처리한다. 서버는 만남 당시 버전과 당시 프로필 요약을 사용해 재검증하며, 이후 설문 수정으로 과거 추천 이유를 바꾸지 않는다.

### 계산 정밀도 계약

앱은 성향·생활 순서 점수를 0~100 정수로 반올림하여 키링에 보낸다. 정확히 .5이면 올림한다. 결과 화면의 소수 점수는 참고 표시일 뿐, 판정에는 전송된 정수만 사용한다. 유형 가중치도 이 전송 점수로 산출한다.

키링 내부 점수는 0~10000 정수로 표현한다. T는 `floor(100 × 합계 / 65025)`, 각 유사도와 평균은 중간 계산의 분수값을 유지한 뒤 해당 점수 단계에서 내림한다. 선호 범위식의 d는 0~100 정수 단위이고 결과를 100배 하여 내부 점수로 만든다. 기하평균은 두 내부 점수의 곱에 대한 정수 제곱근을 내림한다. 최종 S는 `floor((45×T + 30×L + 25×P)/100)`이며 6000 이상이면 통과한다. P 제외 시 분모는 75다.

표의 74.32처럼 소수로 제시한 예시는 설명용 근삿값이다. 경계 판정은 위 정수 계약을 기준으로 두 기기와 서버에서 동일하게 구현한다.

## 수락 전에 보여주는 추천 이유

키링에서 실제로 확인한 근거만 코드로 남긴다. 앱이 유형 이름만 보고 공통 취미나 생활 습관을 만들어내지 않는다. 상대의 원문 답변, 상세 점수, 신원, 구체적 시간·장소는 상호 수락 전에 공개하지 않는다.

| 근거 코드 | 생성 조건 | 앱 문구 |
|---|---|---|
| CONTACT_CLOSE | Q49 비교 점수가 75 이상 | 편하게 느끼는 연락 빈도가 비슷해요. |
| MEETING_CLOSE | Q50 비교 점수가 75 이상 | 원하는 만남 빈도가 비슷해요. |
| TIME_OVERLAP | Q51에 실제로 겹치는 칸이 1개 이상 | 만남을 잡을 수 있는 시간대가 겹쳐요. |
| SHARED_ACTIVITY | Q52의 공통 선택이 1개 이상 | 함께 즐겨보고 싶은 활동이 있어요. |
| OPEN_TALK | 두 사람의 I가 모두 65 이상이고 차이가 20 이하 | 속마음을 나누는 방식에 접점이 있어요. |
| EXPRESSION_WANTED | 양쪽 Q62가 ANY·UNKNOWN이 아니고 E 선호 적합도가 양방향 각각 80 이상 | 서로 편하게 느끼는 애정 표현 방식과 가까워요. |
| RELATION_DIRECTION | 양쪽 Q60이 구체적 선호이며 서로의 Q59가 각각 선택 범위 안에 있음 | 지금 알아가고 싶은 관계의 방향이 맞닿아 있어요. |
| TYPE_CONNECTION | T가 80 이상 | 여러 성향을 함께 봤을 때 연결 후보로 추천된 조합이에요. |

표의 위에서 아래 순서로 최대 3개를 노출한다. 더 나은 설명 우선순위는 파일럿에서 조정한다. 조건을 만족하는 근거가 없으면 “전체 응답 조합을 바탕으로 새로운 대화 상대로 추천했어요”라는 제한된 설명 하나만 쓴다. 서로 맞지 않는 점까지 모두 일치한다고 표현하지 않는다.

흡연·음주·예산·안심 확인 점수는 익명 단계의 추천 설명으로 드러내지 않는다. “상대가 불안해서 당신이 필요해요”, “당신이 상대를 안정시킬 수 있어요” 같은 해석은 하지 않는다.

## 검증과 개선 순서

설문 검증과 매칭 검증은 별개의 작업이다. 다음 절차는 [Boateng 등](https://www.frontiersin.org/journals/public-health/articles/10.3389/fpubh.2018.00149/full)의 개발·검증 단계를 참고하되, 작은 파일럿의 목적을 문항 개선으로 한정한다.

1. 대상 사용자 5~10명과 문항을 함께 읽으며 어떤 뜻으로 이해했는지 확인한다. 이 인원은 팀의 첫 사용성 점검 규모이며 신뢰도나 타당도 입증 표본이 아니다.
2. 72문항의 완료 시간, 중도 이탈, 판단 어려움, 응답이 한쪽으로 몰리는 문항을 확인한다. 이해하기 어려운 역문항은 고친다. 응답이 일관되지 않다고 거짓말로 판정하지 않는다.
3. 별도의 충분한 표본과 분석 계획을 마련해 12개 영역이 구분되는지, 각 4문항이 같은 내용을 측정하는지 검토한다. 특히 E와 R, C와 V, N과 활동성의 중복을 확인한다. 신뢰도 계수 하나만 높다고 검사가 완성됐다고 보지 않는다.
4. 재검사에서 점수와 유형이 얼마나 달라지는지 확인한다. 현재의 관계 목적과 생활 시간은 실제로 변할 수 있으므로 무조건 오류로 처리하지 않는다.
5. 매칭은 만나 본 서로 다른 사용자 쌍을 기준으로 추천 후보 발생률과 추천이 거의 없는 사용자의 비율을 본다. 반복 BLE 신호 수를 만남 수로 세지 않는다.
6. 익명 제안의 수락률, 상호 수락률, 실제 대화 시작·이어짐, 추천 이유의 납득도를 구분해 본다. 익명 수락률을 실제 호감이나 장기 관계 성공률로 부르지 않는다.
7. 유형 표가 도움이 되는지 확인하려면 유형 가중치가 없는 비교안과 비교한다. 범용적인 생활·선호 비교만으로도 비슷한 결과가 나는지 확인한다. 데이터가 쌓이기 전에 8개 유형이 자연적인 사람 집단이라고 발표하지 않는다.

개발 확인 항목은 72개 문항과 번호의 일치, 역채점, 결측과 ANY 구분, 유형 가중치 합 255, 유형 표의 대칭성, 양방향 순서 불변, 60점 경계, 서로 다른 정책 버전, 동시 후보 처리, 양쪽 기록 확인 전 비노출, 설명 근거와 원문 응답의 연결이다. 산술 규칙이 맞는 것과 실제 사용자에게 좋은 추천이 되는 것은 다른 검증이다.

이 초안에서 직접 확인한 것은 문항 구성과 계산 규칙의 내부 일관성이다. 심리 측정의 신뢰도·타당도, 실제 추천 효과, 키링 구현·배터리·통신 성능은 아직 검증되지 않았다.
