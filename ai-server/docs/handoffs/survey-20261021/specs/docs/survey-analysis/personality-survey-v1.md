## 선택적 나이 정보

ageProfile={age,min,max}. Q60에서 내 만 나이, Q97에서 상대의 최소·최대 만 나이를 입력하고 결과에서도 수정한다. 각각19~100 정수 또는 null이다. 이 범위는 목업의 입력 제한이며 가입 연령에 대한 팀 확정 정책을 대체하지 않는다. Q97 age를 고르면 포함 범위 밖은 제외, 범위 누락·min>max·상대 나이 미측정은 보류한다. 나이 정보는 성격·유형·점수 계산에 섞지 않는다.

## 결과의 참고 유형과 실제 상대 조건

SIS-TYPE-REF-1부터 검사 결과의 참고 유형은 나이·흡연·음주·종교·문신·자녀 계획 등 실제 상대 조건 때문에 숨기지 않는다. 원하는 성격·관계 방식과 기존25개 유형 정보를 비교하며, 관련 선호가 없으면 자기 유사성으로 구분해 제시한다. 정보가 모두 부족할 때만 정보 부족을 표시한다. 상세 규칙은 [계산·분석 정의서](personality-scoring-v1.md)의5절을 따른다.

Q97의 선택값과 나이 입력은 계속 보관하고 실제 두 사람 비교에서 적용한다. 나이 범위를 새로 답하게 하거나 제외 선택을 해제하는 방식으로 해결하지 않는다. 이번 수정은 문항·선택지·역채점·성향 점수·본인16유형·개인 분석을 바꾸지 않으며 재검사가 필요 없다.

| D07 | 미입력·비공개·모름과 상관없음을 어떻게 연결할 것인가? | 목업 unknown은 '판단하기 어려움·응답하지 않음'을 합치지만 서비스 종교에는 UNDISCLOSED와 null이 따로 있다. 원래 의미를 유지할지, 새 설문에서 선택을 분리할지와 각 상태의 공개·계산 규칙을 정한다. | 필수 프로필 완료와 설문 완료·분석 가능 여부의 구분, Q97 필수 비교값 부재 시 보류/재입력, ANY와 무교·비흡연을 혼동하지 않는 저장 규칙. |
| D08 | 실제 서비스가 사용할 매칭 규칙 묶음은 무엇인가? | 현재 목업은9영역·우선비중2/1·양쪽50점/coverage70%·조화평균이다. 옛 v8의60점 기준은 과거 기록이다. 현재 묶음을 서비스 검토안으로 유지할지, D02~D07 결정에 맞춰 새 계산 버전을 만들지 결정한다. | 생활 항목 제거 뒤 점수·정보충족 경계, 실제 만남 시간 겹침, 양방향 대칭성, 버전 파일과 API·키링의 일치. 참고 유형 추천 기준과 실제 쌍 판정을 섞지 않는다. |
| D09 | Q99·Q100을 현재 결과 화면에서 어떻게 설명할 것인가? | Q99 다양성은 현재 유형당 대표값 하나를 비교하는 참고 유형 순위에 추가 효과가 없다. Q100은 실제 쌍의 설명 선정에 쓰이며 참고 유형과 역할이 다르다. 적용 대상을 명시해 유지 / 실제 후보 기능까지 노출 보류 / 새 버전에서 문항 조정 중 결정한다. | 사용자가 현재 화면에 효과가 있다고 오해하지 않는 안내, 100문항 호환성, 과거 응답 보존. 선택만 저장된 것을 기능 구현 완료로 표시하지 않는다. |
| D10 | 정책 변경 시 어떤 응답을 다시 확인하고 언제 적용할 것인가? | 의미가 같은 값만 재사용하고 달라진 항목은 사용자 확인을 받을 범위를 정한다. 적용 대상을 새 검사·새 매칭·기존 제안별로 구분한다. 기존 제안의 유지/종료를 이번 정리로 결정하지 않는다. | 원본 보존, 새 version_code·회차, 과거 결과 재현, 변경 미동의·오프라인·구버전 키링 처리. 단순 문서 표기 정리는 재검사나 이관 대상이 아니다. |

### 결정 기록과 검토 기준

각 항목에 `선택한 안 / 이유 / 적용 대상 / 변경 문항·값 / 계산 영향 / 기존 응답 처리 / 검토자 / 승인 근거`를 남긴 후 관련 문항·계산·API 계약을 함께 변경한다. 검토 역할은 제품 정책 PM, 문항41번, 개인 분석42번, 실제 매칭36번 및 FE·BE·AI·IOT 영향 파트다. 이는 새 담당 배정이나 일정 확정이 아니다.

이번 변경에서 확정한 정책은 없으며 코드·문항 JSON·공개 목업·Jira·기존 응답을 변경하지 않았다.
