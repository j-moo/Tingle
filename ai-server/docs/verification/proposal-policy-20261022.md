## API와 저장 구조

- `POST /api/v1/match-proposals/{proposalId}/cancel`: 본인 수락·상대 미응답·기한 내에서만 취소. 최초 수락 시각·키를 보존하고 별도 취소 시각·키로 거절 효과를 기록한다. 최초 거절/취소부터30일 제한이며 반복 요청과 상대의 후속 결정이 제한을 연장하지 않는다.
- `PublicProfile.profileVersion`과 필수 수락 본문 `{ profileVersion }` 추가. 실제 공개 응답 필드만 비교하며 나이 변화도 반영한다. 개인정보 이메일·생년월일 원문·비공개 설정은 비교값에서 제외한다.
- 최초 수락은 프로필 행 잠금 후 비교한다. 변경이면409 `PROFILE_CHANGED`, 결정과 키는 저장하지 않는다. 같은 화면 최신 조회 후 사용자가 다시 수락해야 한다. 기존 성공 수락의 응답 유실 재시도는 재확인 없이 현재 결과만 복구한다.
- 미응답자에게는 상대 선행 거절/취소와 관계없이 원래 기한까지 동일한 PENDING·프로필·선택 경로를 제공한다. 후속 수락은200 REJECTED 비성사이며 방을 생성하지 않는다. 본인 거절/취소/비성사/만료는 목록에서 제외한 뒤 페이지 처리한다. 단건 조회는 처리 복구용으로 공개 상태만 반환한다.
- 취소와 상대 수락을 회원→쌍→제안 잠금으로 직렬화한다. 상호 수락이 먼저면 취소409, 취소가 먼저면 후속 수락은 비성사다. 기존 만료·소유·차단·계정·가입 단계 검사는 유지한다.
- ERD: `match_proposals.low_cancelled_at`, `high_cancelled_at`, `low_cancel_request_key`, `high_cancel_request_key` 추가. canonical SQL·가져오기 SQL·tables.json·Mermaid ERD를24테이블170컬럼으로 동기화했다. 물리 FK는 없다. 기존 공용 DB나 Docker 데이터에 변경을 실행하지 않았다.
