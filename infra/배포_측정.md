## 백업 복원 연습

계획: 구성 직후 1회, 이후 2주마다. 복원은 운영 DB 를 건드리지 않고 같은 PostgreSQL 의 임시 DB 에 되살려 비교한 뒤 지운다.

| 날짜 | 백업 파일 | 복원 대상 | 결과 | 복원 시간 |
| --- | --- | --- | --- | --- |
| 2026-10-22 | `daily-tingle-20261022.dump` (60KB) | 임시 DB | 테이블 24 = 원본 24, 행 0 = 원본 0 (운영 DB 가 아직 비어 있음) | 0.7초 |
| 2026-10-22 | 위 복원본 + 시험용 표 1만 행을 다시 `pg_dump` (284KB) | 임시 DB | 테이블 25 · 인덱스 63 · 제약 215 · 1만 행과 내용 해시 모두 원본과 같음 | 0.5초 |
| 2026-10-22 | `daily-uploads-20261022.tar.gz` | 임시 폴더 | 파일 0 = 원본 0 (업로드 아직 없음) | 0.01초 |

복원 명령 (실제 운영 복구 때):

```sh
# 1. 운영 back 을 멈춘다 (블루-그린 양쪽)
docker compose --env-file /srv/tingle/.env --env-file /srv/tingle/app.env -f /srv/tingle/repo/infra/docker-compose.yml stop back-blue back-green
# 2. 덮어쓰기 복원
docker exec -i tingle-db-1 sh -c 'pg_restore -U "$POSTGRES_USER" -d tingle --clean --if-exists --no-owner' < /backup/<파일>.dump
# 3. 업로드 사진
tar xzf /backup/daily-uploads-<날짜>.tar.gz -C /data
# 4. 운영 back 다시 배포 (Jenkins 재실행 또는 sh /srv/tingle/repo/infra/deploy-bluegreen.sh back)
```
