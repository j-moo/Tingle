# 앱 인증·토큰 연동 확인 사항

수정 2026-10-21 11:47 KST. 현재 문서 모델을 반영한 계약 검토이며 인증 담당의 미푸시 변경·최신 원격 코드·실제 소셜 로그인·운영 상태를 이번 작업에서 재검증하지 않았다.

## 유지하는 계약

- 앱은 구글ID token, 카카오/네이버access token을 token으로 전달한다. 서버가 제공자 증명을 검증하고 provider+providerSubject로 식별한다. 이메일·이름 기준 자동 계정 통합은 없다.
- 자체 access/refresh를 앱 OS 보호 저장소에 보관하고 토큰·소셜 증명을 로그/이슈에 남기지 않는다. 웹 세션 쿠키를 앱 인증의 전제로 삼지 않는다.
- 토큰 응답 필수4개(accessToken,refreshToken,accessTokenExpiresIn,signupCompleted), access30분/refresh14일 및 회전·유실 재시도30초는 기존35번 계약이다. 추가 onboardingStatus는 nextStep과 동일 값의 선택 확장으로 표시하며 기존 앱의 필수 응답을 임의 추가하지 않는다.
- 명시적 위조·폐기/403에서 자동 갱신하지 않는다. 동시에 만료된 요청은 갱신을 공유한다. 같은 refresh 유실 재시도와 후속 토큰 사용 여부를 구분한다.

## ERD 변경과 미확정 보장

현재는 app_users에 단일 소셜 연결을 저장하고 refresh_tokens에는 user_id·family_id·해시·만료·사용·폐기 시각을 둔다. login_sessions/sid 저장 구조는 보류다. 이 축소만으로 다음 보장이 구현됐다고 주장하지 않는다.

1. logout 후 기존 access를 즉시 거절할 서버 상태/조회 방법과 적용 범위. JWT sub만 검증하는 stateless 필터는 즉시 폐기를 보장하지 않는다.
2. refresh 회전의 부모/후속 관계, 재사용 탐지 범위, 응답 유실30초에 동일 후속 자격을 안전하게 재전달할 방법. 현재7개 컬럼만으로 모두 충족한다고 가정하지 않는다.
3. 현재 자격/family만 폐기하는 logout과 회원 전체 refresh/access 폐기는 별도 계약이다. 앱이 보낸 userId/sessionId를 소유 검증 대신 쓰지 않는다.
4. 가입 완료와 약관·키링·프로필·설문·희망 조건·동기화 READY는 구분한다. 약관/프로필 저장 분리 경로·DTO와 서버 단계 allowlist를 인증 담당·FE와 맞춘다.

## 현재 문서에 반영한 정책

- birthDate·한국 날짜 기준 만19세·평년 윤일생3월1일, 닉네임2~20자/공백, 소개 보이는 글자200개를 적용한다.
- 기존 signup DTO는 호환 검토용으로 유지하되 분리 API가 이미 구현됐다고 표시하지 않는다.
- 상대 공개 ID 형식과 현재 프로필 사진 URL 전달·소유 검증은 별도 확인 사항이다. 개인정보·토큰·원응답을 공개하지 않는다.

## 과거 코드 대조 기록의 위치
