## 양방향 기본 희망 조건 저장 (수정 2026-10-21 11:12)

`PUT /api/v1/users/me/preferences` / `setPreferences`

### 기존안

요청: application/json: desiredGenders, desiredAgeMode, desiredAgeMin, desiredAgeMax

응답: 200 desiredGenders, desiredAgeMode, desiredAgeMin, desiredAgeMax

성향 결과 준비 후 허용. ANY 경계null, RANGE min>=19/max=null 또는min이상. 성별 목록은 비어있지 않음. 실제 새 매칭에는 양방향 필수. settingsVersion 증가.

### 수정안

희망 성별·나이와 매칭 설정을 matching_settings 한 행에서 관리함. desiredAgeMode는 별도 저장하지 않고 나이 하한/상한 값으로 계산함. ANY는 양쪽 null, RANGE는 하한 19 이상·상한 null 또는 하한 이상이라는 기존 입력 검증을 유지함. 설정 저장은 settings_version(설정 변경 번호)을 원자 증가시키고 그 번호의 스냅샷을 생성함. 두 API가 같은 행을 수정하므로 변경 대상 필드만 갱신함.

## 인증 담당 연락 동기화 (2026-10-21 14:16 KST)

### 기존안

로그인·재발급은 accessToken/refreshToken/accessTokenExpiresIn/signupCompleted 필수, onboardingStatus 선택 확장이었다. POST /auth/signup으로 약관·프로필을 한 번에 처리하는 계약이 활성 목록에 남아 있었다. PROFILE_FIELD_LOCKED 전용 코드는 없고422 POLICY_UNRESOLVED만 기록했다.

### 수정안

약관부터 시작하는7단계를 유지하며 POST /api/v1/users/me/agreements를 추가했다. 통합 signup은 폐기 이력으로 옮기고 프로필 PATCH와 분리한다. 새 토큰6개 필드와 UTC 만료 시각 응답을 구현 기준 초안으로 반영했다. 로그인·토큰 코드와 ERD/DDL은 수정하지 않았다. 이전 TokenPair schema와 signup operation 원문은 OpenAPI 확장 이력에 보존한다.
