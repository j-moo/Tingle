## 5 참고 유형과 실제 두 사람 매칭의 분리

### 검사 결과의 참고 유형 - SIS-TYPE-REF-1

결과 화면은 typeRecommendations(a)를 사용한다. 내 상대 선호 중 기존 유형25정보에 연결되는 Q61~82·Q86·Q88·Q94만16개 초기 대표값과 비교하고, 기존 wishFit 및 정보가 있는 영역의 평균·우선영역 비중2/그 외1을 재사용한다. 점수가 계산된 유형을 내림차순으로 정렬해 최대3개 표시한다. 동점의 표시 순서는 영어 코드 순이며 자연적 우열이나 확률을 뜻하지 않는다.

나이·흡연·음주·종교·문신·자녀 계획·예산·만남 가능 시간 같은 실제 상대 조건이나 Q97의 제외 선택, 실제 매칭의 양쪽50점·coverage70% 기준으로 참고 유형을 제거하지 않는다. 단, 약속 시간·정리 방식 등 기존25개 유형 정보에 포함된 관계·행동 특성은 계속 비교한다. 모든 생활 관련 정보를 통째로 삭제했다는 뜻은 아니다.

유형에 연결된 상대 선호에서 비교할 정보가 없으면 기존 classifyAnswers 순위를 사용하고 ‘나와 비슷한 관계 방식의 유형’으로 명시한다. 이 경우 순위는 자기 유사성이고 상대 선호 충족도로 부르지 않는다. 상대 선호와 자기 유형 정보가 모두 부족하면 정보 부족을 표시하며 응답·상대 나이를 만들어 넣지 않는다.

추천 이유도 실제 사람의 답변처럼 서술하지 않는다. 내 선호와 유형의 초기 대표값을 비교해 fit≥0.7인 근거를 최대2개, 아직 사용하지 않은 특성 중 fit<1인 가장 큰 차이를1개 선택한다. 실제 사람의 양방향 매칭 이유와 별도다. 참고 점수는 단방향 선호의 가까움 또는 명시된 자기 유사성으로, 실제 상대가 나를 선호한다는 보장이나 매칭 성사 확률이 아니다.

기존 engine100.mjs의 recommendations는 과거 가상 양방향 사례용 함수로 남아 있으나 현재 결과 화면은 이 함수를 사용하지 않는다. 실제 팀원 파일 비교는 기존 pair(a,b,ageA,ageB)·direction을 그대로 사용한다.

### 실제 두 사람의 비교 - 기존 계산 유지

- A의 Q61~64를 B의 E,A,C,I와, Q65~95를 B의 Q30~60과 비교하고 반대 방향도 계산한다.
- 성격 선호 low=[0,40], mid=[30,70], high=[60,100]에 Q98 close/some/wide의 여유0/10/20을 적용한다. 순서 응답은 선호값±0/1/2이며 범위는1~5로 자른다. Q89 음주는 하한1·선호 상한으로 비교한다. 미응답 Q98은 계산상 some을 쓰되 응답을 만들어 넣지 않는다.
- 구간 밖 거리 d=max(L-x,0,x-U), M=max(L-min,max-U), fit=clamp(1-d/M,0,1). 구간이 전체 범위면 null(무제약). 범주는 수용 목록 포함이면1, 아니면0. 복수 활동은 교집합 유무다.
- Q87은 선호뿐 아니라 양쪽 자기 Q52의 구체 시간 겹침을 검사한다. irregular만 있으면 정보 부족, 실제 시간이 안 겹치면 해당 항목0이며 전체 자동 탈락은 아니다. 현재 코드에서는 선호가 irregular뿐이어도 양쪽 실제 시간이 구체적으로 알려져 있고 안 겹치면0을 먼저 적용한다.

- 추천 이유는 계산 rows의 내 선호 충족(fit≥0.7), 상대 선호 충족(fit≥0.7, 다른 특성), 조율 차이(fit<1)를 최대3개 뽑는다. Q100은 설명 선정·순서를 조정하며 점수는 바꾸지 않는다. 같은 유형 가산점은 없다.
- 위 양방향 계산과 실제 조건 검사는 팀원 파일 비교에 적용한다. 검사 결과의 참고 유형은 앞 절의 typeRecommendations로 제시한다. Q99의 유형 다양성 선택은 유형당 하나의 대표값을 비교하는 현재 참고 유형 순위에 추가 효과를 주지 않는다.
