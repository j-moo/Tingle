### AI-02 위험 대화 감지와 대응 연결

**압축 MVP CM15(2026-10-26 사용자 승인):** AI-02 위험 대화 감지를 P0 필수로 유지한다. 활성 채팅의 합의된 최소 입력을 비동기로 분석해 개인별 주의 안내와 사용자 직접 차단 경로를 제공한다. 자동 메시지 차단·자동 상대 차단·계정 제재는 하지 않으며 분석 지연/실패로 기본 채팅을 막거나 미분석 상태를 안전으로 표시하지 않는다. CM09의 신고 기능 제외는 유지한다. 기존 AI 분석 동의·철회/재동의와 이에 따른 채팅 접근 기준, 최소 마스킹 입력·보관/삭제 기준을 유지한다. 포함 여부 결정은 완료했으나 POL02/POL04/DES10의 제공업체 조건·적용 근거/최종 안내·입출력 계약·오탐/누락/지연 평가와 구현·실행 검증은 남는다. 외부 제공업체 조건과 적용 계약 확인 전 가상 대화로만 검증한다.

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 아래 입력/안내 원칙을 따르는 활성 방 메시지. 외부 제공업체 조건과 적용 계약 확인 전에는 가상 대화로만 테스트 |
| 실행·입력 | 메시지와 합의된 문맥 범위를 분석. 여러 메시지의 주소 분할/조합 유도·위험한 외부 사이트 유도도 검토 범위에 포함 |
| 정상 동작·결과 | 메시지는 기존 규칙대로 전달하고 AI가 비동기로 분석. 유형/대상에 맞는 개인별 주의 배너를 표시하며 수신자에게 기존 차단 진입 버튼 제공. 자동 전송 차단·신고·상대 차단·계정 제재 없음 |
| 예외 | 정상 금전 대화·인용·은어·약속/연락 방법 교환의 오탐과 우회/위험 유도 누락 검증. 분석 실패/지연만으로 채팅 중단 없음·안전 판정 표시 없음. 종료된 방에는 지연 결과 배너 표시/방 재노출 없음 |
| 완료 기준 | 정상·위험·애매·장애 사례의 기대/실제 결과와 응답 시간 기록. 불법 여부 확정이나 완전한 예방으로 안내하지 않음 |
| 데이터·검토 | 분석 입력·판정·버전·개인별 안내 표시 상태·보관/삭제 연결. 성현48·BE·PM·FE가 아래 확정된 최소 입력/목적/보관 상한을 기준으로 제공업체 조건·입력 한도·한국어 판단 기준·삭제/배너 표시 확인 계약을 검증. AI 감지만으로 신고 접수/90일 보관 시작 없음 |

**MVP 배너 동작(2026-10-21 확정):**

| 감지 유형 | 표시 대상 | 문구 |
| --- | --- | --- |
| 사기 의심·송금 요구·위험한 외부 사이트 유도 | 해당 메시지 수신자 | 금전이나 개인정보를 요구받으면 주의하세요. 의심스러운 대화는 상대를 차단할 수 있어요. |
| 욕설·모욕·성희롱·협박 의심 | 해당 메시지 수신자 | 불편하거나 위협적인 대화라면 상대를 차단할 수 있어요. |
| 위 공격적 표현 의심 | 해당 메시지 발신자 | 상대를 존중하는 표현을 사용해 주세요. |

배너는 대상 사용자에게만 보이는 UI로 상대에게 채팅 메시지로 전달하지 않는다. 수신자 배너의 차단 버튼은 SAFE-01의 기존 흐름으로 연결하며 자동 실행하지 않는다. 같은 방·같은 안내 유형은 사용자별 최초 1회만 표시한다. 반복 메시지·중복 분석·재접속에도 중복 표시하지 않으며 표시 상태/확인 응답 계약은 FE·BE가 정의한다. 상대를 사기범 등으로 단정하지 않는다. “밥값은 반씩 내자”, “카톡으로 연락할까?” 등 일상 대화는 안내하지 않도록 검증하며 우회 표기 자체만으로 위험을 단정하지 않는다.

이 기능은 메시지 도달 자체를 막지 않는다. 분석 지연/실패 시에도 기존 권한·길이·웹 주소 규칙에 따른 채팅과 수동 차단을 유지하고 미분석을 안전으로 표시하지 않는다. 종료된 방은 늦은 결과로 배너/방/대화를 복원하지 않는다. AI 감지·배너는 신고 접수가 아니며 90일 신고 보관을 시작하거나 기존 기한을 연장하지 않는다. CM09로 신고 접수와 신고 보관 연결은 제공하지 않는다. 분석 입력·목적·안내·기록 원칙은 아래 확정 기준을 따른다. 제공업체 조건 확인, 수치 검증·보관 구현·표시 확인 계약은 남아 있다. 성현이 한국어 정상/위험 사례의 오탐·누락 검증을 통해 안내 판단 기준을 마련한다.

**위험 대화 분석의 목적·입력·안내·기록 원칙(2026-10-21 확정):** 성현의 검토 의견을 바탕으로 아래 원칙을 채택한다. 이 절은 AI-02 위험 대화 감지에 적용하며, 공개 정보로 시작 질문을 만드는 AI-01이나 성향 매칭 알고리즘의 입력 정책을 변경하지 않는다.

| 구분 | 확정 기준 |
| --- | --- |
| 목적 | 위험 징후 감지와 개인 주의 안내에만 사용. 이 분석용 대화/결과를 광고·매칭 점수·자체 모델 학습에 재사용하지 않음 |
| 입력 범위 | 해당 채팅방의 필요한 최근 문맥과 신규 메시지만 사용. 외부 입력은 마스킹된 본문·발신자 A/B·순서·신규 메시지 구분·주소 마스킹 여부 등 최소 정보로 제한. 프로필·설문·다른 방 정보·실제 사용자 식별자는 제외. 서버 내부 메시지 참조와 외부 입력을 구분 |
| 주소와 위험 판단 | 주소 치환 전 원래 URL을 AI에 보내지 않음. 주소를 가린 주변 문맥의 송금 압박·수익 보장·인증번호 요구·설치 강요 등 요구 행동을 판단. 실제 사이트의 피싱/악성코드 여부를 확인하는 기능으로 설명하지 않음. 링크나 주소 차단 표시의 존재만으로 경고하지 않음 |
| 분석 상태 | 정상/위험 판정과 판단 불충분·처리 실패를 구분. 문맥 부족을 안전이나 위험으로 억지 확정하지 않고, 미분석/실패를 안전으로 표시하지 않음. 판단 불충분 자체만으로 상대를 위험 인물로 단정하는 안내를 하지 않음 |
| 사용자 안내 | 가입 과정·각 채팅방 첫 입장·설정에서 목적·범위·외부 전송·보관 방식과 오탐/위험 누락 가능성을 안내. 가입 단계의 별도 필수 동의 항목으로 두는 제품 요구를 채택하되 아래 적용 전 확인 조건을 충족해야 함. 채팅방 AI 안내는 CM05의 별도 확인 버튼/확인 저장 없이 제공하고 가입 동의를 대신하지 않으며 정확한 문구/계약은 FE·BE·PM이 구체화 |
| 실제 대화 사용 전 조건 | GMS 자체 로그/보관 및 실제 모델 제공업체의 저장 기간·학습 사용 조건을 각각 확인하고 입력/안내/보관 계약을 맞추기 전에는 가상 대화로만 테스트. 확인 전 외부 미저장·학습 미사용을 사실로 안내하지 않음 |
| 본문 복사와 로그 | 기존 채팅 저장소와 분석 대상 메시지 참조를 우선 사용. MVP에서 별도 분석용 본문 사본을 만들지 않고 일반 로그에 대화 본문·전체 요청/응답을 기록하지 않음. 별도 사본이 꼭 필요하면 목적·권한·최소 마스킹 문맥·기한을 다시 합의한 뒤 도입 |
| 분석 기록 | 판정 상태·위험 유형·근거 메시지 참조·모델/프롬프트/전처리 버전·처리 시간·토큰 사용량 등 필요한 최소 메타데이터를 기록하는 방향. 정확한 필드/조회 권한·배너 상태의 보관/삭제는 BE·AI·FE 계약에서 구체화. 모델 응답 전체나 본문 인용을 메타데이터에 숨겨 저장하지 않음 |
| 보관 상한 | 본문에 연결된 분석 기록은 해당 원문의 실제 삭제 기한을 넘기지 않음. 분석·재시도·사본 생성일부터 기한을 다시 세지 않음. 나중에 별도 합의할 사본에도 같은 상한 적용. 더 짧은 목적별 기간은 후속 계약이며 상한이 전 기간 보관 의무는 아님 |

**AI 대화 위험 감지 동의의 가입 단계 배치(2026-10-21 사용자 결정):** 첫 소셜 로그인 후 서비스 회원가입 완료 전에 별도 항목으로 '[필수] AI 대화 위험 감지를 위한 개인정보 처리 동의'를 제시하는 제품 요구를 채택한다. 미동의 시 가입을 완료하지 않는 흐름이 목표이며, 채팅 진입 때 선택 동의를 받는 안은 채택하지 않는다. 일반 이용약관에 숨기거나 기본 체크로 동의한 것으로 처리하지 않는다. 실제 동의 항목·버전·시각·언어·화면은 기존 동의 기록 기준으로 저장한다. 가입 동의는 해당 방 최소 문맥 분석 범위에만 적용하며 광고·매칭 점수·자체 학습 재사용을 허용하지 않는다.

적용 전 확인: 안전 기능이라는 이유만으로 가입 필수 동의의 적법성·필요성이 확인된 것은 아니다. PM·BE·AI는 필수 처리의 필요성, 실제 GMS/제공업체와 처리위탁·제3자 제공·국외 이전 여부, 전송 항목/국가/수신자/목적/보관 기간 및 필요한 별도 동의를 확인해 최종 문구와 적용 근거를 확정한다. 일반적인 AI 동의 하나로 별도 동의가 필요한 처리를 포괄하지 않는다. 이 확인 전 실제 사용자 대화는 전송하지 않고 기존 가상 대화 테스트 원칙을 유지한다. 가입 필수 방식이 적용 가능하지 않으면 실제 가입 제한 배포 전에 정책을 재검토한다.

이미 가입한 사용자의 동의를 소급 생성하지 않으며, 양쪽 참여자의 유효한 동의와 적용 근거가 확인되지 않은 대화를 분석하지 않는다. 다른 가입·프로필·종교·마케팅 동의 분류/배치는 §2.7을 따르고 AI 동의로 대신하지 않는다.

**AI 동의 철회 시 채팅 이용 제한(2026-10-21 사용자 결정):** 가입 시 별도 필수 동의 요구를 유지하되, 가입 후 철회 요청은 허용한다. 철회가 반영되면 해당 사용자는 대화방을 이용할 수 없도록 하는 제품 요구를 채택한다. 해당 사용자에 대한 채팅방 진입·대화 조회·메시지 전송을 제한하고, 열려 있던 화면이나 직접 API 요청에서도 서버의 최신 동의 상태를 확인한다. 철회와 동시에 해당 동의에 의존하는 신규 AI 분석·외부 전송을 중단한다. 그 사용자의 메시지가 포함된 문맥을 상대방의 동의만으로 계속 분석하지 않는다. 예약/재시도 분석과 전송 직전 동의 확인, 처리 중 요청과 철회가 겹친 경우의 정리·삭제는 BE·AI 계약에서 구체화한다.

철회는 자동 회원탈퇴가 아니며 키링 초기화나 탈퇴 완료를 철회 접수/반영의 선행 조건으로 삼지 않는다. 철회 안내에는 채팅 이용 제한과 분석 중단을 설명한다. 기존 분석 기록은 확정된 목적 종료/삭제 및 예외 보관 근거에 따라 처리하고, 철회 또는 이후 재동의로 보관 기한을 다시 시작하지 않는다. 가입 필수화와 채팅 이용 제한의 필요성·적용 근거는 실제 적용 전 확인 사항으로 유지한다. 근거/제공업체 조건 확인 전 실제 사용자 대화를 분석하지 않는다.

**철회에 따른 기존 방 종료와 재매칭 금지(2026-10-21 확정):** 철회한 사용자가 현재 참여 중인 각 활성 채팅방에서 나간 것으로 처리하고, 해당 방을 양쪽 모두 종료한다. 양쪽 목록에서 제거하며 대화 조회·메시지 전송·재입장을 허용하지 않는다. 열린 채팅방이나 이전 알림/링크로 접근하면 대화 내용 없이 "더 이상 채팅방을 이용할 수 없어요."를 표시하고 목록으로 이동한다. 종료된 방을 목록에 이력으로 남기지 않는다. 상대방에게 AI 동의 철회라는 구체적 사유를 공개하지 않으며 기존 나가기의 일반 종료 안내 원칙을 유지한다.

종료된 방의 두 계정은 나가기와 동일하게 이후 재매칭하지 않는다. 같은 공간에서 다시 감지되거나 다른 조건이 맞아도 서로 새 매칭·제안·키링 매칭 진동을 발생시키지 않는다. 설정/키링 변경·AI 재동의로 종료된 방을 복원하거나 해당 상대와의 재매칭 금지를 해제하지 않는다. 이 결정은 종료된 방의 계정 쌍에 대한 것이며 다른 모든 사용자와의 새 매칭을 일괄 중지하는 결정은 아니다. 탈퇴 후에는 재가입하더라도 최소 대조/관계 기록을 탈퇴 완료부터 1년간 유지하는 기준을 적용한다. 구체적인 식별/삭제 계약은 POL03·DES12에서 확인한다.

사용자 화면의 종료와 서버 기록 삭제를 구분한다. 채팅은 실제 종료부터 30일 보관 후 삭제한다. 철회 이전에 이미 종료된 방의 종료 시각/삭제 기한을 다시 시작하지 않으며, 채팅 보관을 이유로 AI 신규 분석을 계속하지 않는다. 철회 및 방 종료의 중복/동시 요청·메시지 전송·상호 수락에 의한 방 생성 경합, 일부 방 처리 실패/재시도에서도 이용 제한·분석 중단과 재매칭 금지가 누락되지 않도록 FE·BE·AI가 계약하고 실제 상태로 완료 여부를 확인한다.

**철회 중 매칭·제안 및 채팅 재동의(2026-10-21 확정):** AI 동의를 철회한 동안에도 다른 자격/설정/관계 조건을 충족하면 새 매칭과 키링 매칭 진동·새 제안 생성을 계속 허용한다. 철회 자체로 매칭 ON/OFF 저장값을 변경하지 않는다. 기존 유효 제안과 새로 받은 제안의 프로필 확인·수락/거절은 가능하며, AI 미동의를 이유로 제안을 취소하거나 수락을 거부하지 않는다. 기존 차단·나가기/7일 종료·AI 철회로 종료된 계정 쌍의 재매칭 금지와 제안 만료 등 별도 조건은 유지한다.

상호 수락 시 방을 생성하는 기존 기준을 유지하되, 철회한 사용자는 재동의 전까지 채팅방 진입·대화 조회·메시지 전송을 할 수 없다. 해당 사용자가 채팅 이용을 시도하면 AI 동의가 필요하다고 안내하고 동의 내용을 확인할 경로를 제공한다. 수락·채팅방 생성·진입 시도만으로 동의한 것으로 처리하지 않는다. 미동의 상태가 계속된다는 이유로 철회 이후 새로 생성된 방을 과거 철회 사건의 나가기 대상으로 반복 종료하지 않는다. 철회 시점의 활성 방 종료와 철회 후 새 방의 이용 제한을 구분하고, 두 사건이 경합할 때 서버 처리 순서/동의 버전 기준은 BE가 정의한다.

재동의를 실제로 완료하고 서버 저장이 확인되면 철회 이후 다른 상대와 새로 생성된 유효한 방을 이용할 수 있다. 종료·만료·차단 등 기존 이용 제한은 그대로 적용한다. 철회로 이미 종료된 방은 재동의로 복원하지 않고 해당 상대와의 재매칭 금지도 해제하지 않는다. 새 방의 생성 후 7일 수명은 그대로 흐르며 재동의를 기다린 시간만큼 연장하거나 재동의일부터 다시 세지 않는다. 재동의 실패/응답 유실은 서버 상태를 재조회하고 확인 전 채팅을 허용하지 않는다. AI 분석 재개에도 양쪽의 유효 동의·외부 전송 적용 근거와 기존 최소 입력/목적/삭제 기준을 적용한다.

**철회 중 새 방의 상대방 화면·메시지 전송(2026-10-21 확정):** AI 동의가 유효한 상대방에게는 철회/재동의 대기 상태를 별도 배너·문구·시스템 메시지로 알리지 않는다. 상대방은 유효한 새 방에 평소처럼 입장하고 메시지를 보낼 수 있다. 수신자가 AI 재동의를 하지 않았다는 이유만으로 상대방의 정상 메시지 전송을 거부하지 않는다. 메시지는 기존 길이/웹 주소 치환·저장·전달 규칙을 적용하며 서버 저장 성공 여부에 따라 전송 상태를 표시한다. 기존 만료·차단·나가기 등 전송 제한은 유지한다. 이 규칙은 철회 이후 새로 생성된 방에만 적용하며 철회로 이미 종료된 방의 전송을 다시 허용하지 않는다.

철회한 사용자는 재동의 전까지 그 방에 입장하거나 대화를 조회/전송할 수 없다. 상대방이 보낸 메시지는 저장하되 철회자에게 채팅 내용·목록 미리보기·알림 본문/캐시 등으로 내용을 우회 노출하지 않는다. 저장·전달·푸시 수신만으로 철회자 본인의 새 메시지를 확인 완료로 처리하지 않는다. 상대에게 읽음 상태를 전달하지 않으며 재동의 후 유효한 방의 본인 목록 표시는 CM06 기준을 따른다. 재동의 당시 방이 유효하면 그동안 저장된 메시지를 볼 수 있으며 이미 만료/종료된 방은 복원하지 않는다. 메시지가 쌓이거나 재동의를 기다려도 생성 후 7일과 기존 서버 보관 기한은 연장하지 않는다.

상대방의 전송 허용은 AI 분석 허용을 뜻하지 않는다. 한쪽이라도 유효한 동의가 없으면 해당 방의 신규 AI 분석·외부 전송을 하지 않는 기존 기준을 유지한다. AI 분석이 중단돼도 상대방의 기본 전송·차단 기능은 기존 조건대로 제공한다. 양쪽 모두 미동의 상태라면 각자 채팅 이용 제한을 적용하며, 상대방에게 별도 표시하지 않는다는 이유로 미동의 사용자 본인의 전송을 허용하지 않는다.

기존 회원의 동의 전환 흐름은 POL02·POL04의 후속 결정이다. 이번 확정으로 자동 탈퇴·상대방 제재·전체 서비스 이용 제한을 추가하지 않는다. 필수화/채팅 제한의 적용 근거 확인은 유지하며 문서 확정을 구현/테스트 완료로 보지 않는다.

채팅 본문은 실제 방 종료부터 30일 보관 후 삭제한다. 차단은 이미 양쪽 방 종료로 확정돼 있으며 서버에서 조기 종료가 확정된 시각을 기준으로 한다. 정상 7일 종료는 원래 만료 시각을 기준으로 한다. AI 기록의 보관 기한을 임의로 확대하지 않는다. 분석 기록의 필요성을 구분하고 원문 삭제 시 연결된 기록/참조를 정리한다. 종료 후 보관은 사용자의 재조회나 AI-02의 계속된 자동 분석을 허용하지 않는다. AI 감지만으로 신고 접수·90일 보관을 시작하지 않으며, 외부 제공업체의 보관은 우리 서버의 삭제 정책과 별도로 확인한다.

수신자 보호 안내와 공격적 표현 발신자 안내는 위의 기존 유형별 기준을 유지한다. 같은 방·사용자·안내 유형별 최초 1회이며, 서버 전송과 실제 화면 표시를 구분하여 FE·BE가 확인/중복 방지를 설계한다. 종료된 방의 늦은 결과는 안내하거나 방을 되살리지 않는다.

입력이 상한을 넘으면 오래된 분석용 문맥부터 조정하되 새로 분석할 메시지를 조용히 버리지 않는다. 신규 미분석 메시지가 많으면 묶음을 나누는 등 누락 없이 처리할 방법을 설계한다. 입력 제한 처리는 사용자에게 전달/저장하는 원래 채팅을 자르거나 수정하는 근거가 아니다. 무한 대기·중복 처리·미분석 누락을 검증하고 실패해도 채팅은 기존 규칙대로 유지한다.

평가에는 식사비 정산/일반 투자 이야기와 수익 보장+즉시 송금 압박, 동의한 연락처 교환과 거절 후 강요, 피해 경험 인용과 직접 협박, 농담/성적 표현과 반복 괴롭힘을 대조해 넣는다. 같은 문장의 앞뒤 문맥·요구 대상·거절/동의에 따라 결과가 달라지는지 확인한다. 실제 시험 결과는 아직 없으며 문서 시나리오 추가를 모델 성능 검증으로 보고하지 않는다. 이번 회신은 AI-02 검토이며 POL01의 v8 생활 점수/중복 문항 검토를 완료한 것으로 처리하지 않는다.

### AI-03 신고 검토 우선순위 지원(MVP 이후)

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 운영팀. 사용자 신고 접수 후 허용된 대화 문맥과 신고 사유를 분석할 수 있는 경우 |
| 실행·입력 | 신고 사유·상세 내용·분석 범위에 합의된 해당 대화. MVP에서는 실행하지 않음 |
| 정상 동작·결과 | AI가 신고 사유와 대화 근거를 비교해 부합하는 건을 우선 검토하도록 제안. 근거 메시지·판단 요약·불확실 여부를 운영팀에 제공하는 방향. 최종 판단과 제재는 운영팀 수행 |
| 예외 | 근거 부족·분석 실패·사칭/허위 프로필 등 대화만으로 판단 불가한 신고도 수동 검토 대상으로 유지. 자동 기각·목록 제외·자동 제재 금지. AI 지연/장애가 신고 접수를 막지 않음 |
| 완료 기준 | MVP 완료 기준에서 제외. 후속 도입 시 사유 부합/불일치/판단 불가·오탐/누락·분석 장애 사례와 검토 누락 방지 확인 |
| 데이터·검토 | 분석 범위/권한/보관·출력/버전·근거 연결·우선순위 기준 및 심각도/접수 시각 반영은 후속 계약. 신고 증거 보관 기한 임의 연장 금지. 구현 작업 미생성 |

비동기 위험 대화 감지인 AI-02와 별도 범위다. 사용자 신고 접수·증거 연결은 최신 MVP에 포함하며 과거 CM09 제외를 대체한다. 운영 처리 API·자동 AI 신고 및 AI-03 신고 검토 지원은 별도 후속 구현으로 구분하고 다른 AI 기능의 범위는 유지한다.
