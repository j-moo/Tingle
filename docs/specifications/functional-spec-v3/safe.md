### SAFE-01 차단·퇴장

**압축 MVP CM11(2026-10-26 사용자 승인):** 차단한 사용자 목록과 사용자 차단 해제 기능을 MVP에서 제외한다. 목록/해제 화면과 해당 사용자용 조회·해제 API는 요구하지 않는다. 상대 차단 자체는 CM10의 P0로 유지하며, 차단 후 MVP에서는 사용자가 직접 되돌릴 수 없다. 차단 확정 전에 이 점을 안내하고 확인을 받는다. 단순 화면 숨김이 아니라 사용자 요청으로 차단 상태를 해제할 수 없도록 서버 권한/동작도 맞춘다. 차단 관계 저장·새 매칭/제안/채팅 제한·중복 요청/응답 유실 상태 확인은 유지한다. 운영자 수동 해제나 외부 문의를 통한 해제 절차는 이번에 추가하지 않는다. 이 결정은 영구적인 무기한 데이터 보관 승인이 아니며 탈퇴 후 최소 관계 기록의 기존 보관/삭제 기준은 유지한다. 기존 종료 방/제안 복원 없음, 차단과 자발적 나가기 사유 구분도 유지한다.

**압축 MVP CM10(2026-10-26 사용자 승인):** 상대 차단 기능(SAFE-01 일부)은 P0 필수로 유지한다. 차단 확정 시 두 사람의 유효 제안·활성 채팅을 종료하고 차단이 유지되는 동안 새 매칭을 금지한다. 상대에게 차단 사유를 공개하지 않으며, 실패/응답 유실은 재조회·재시도로 실제 상태를 확인한다. 신고 기능은 CM09 후속을 유지한다. 나가기는 유지하며 차단 목록/해제는 이후 CM11로 후속 이관했다. 기존 범위 재확인이므로 정책 .130/명세 .126 및 P0 28/P1 1/후속3 분류는 그대로다. 실제 API/기기 전파·화면 구현 및 실행 검증은 미완료다.

차단 전 “상대를 차단하면 현재 제안과 채팅이 종료되고 서로 매칭되지 않아요. 이번 버전에서는 차단을 해제할 수 없어요.”, 나가기 전 “채팅방을 나가면 대화 내용을 다시 볼 수 없고, 이 상대와 다시 매칭되지 않아요.”를 안내하고 확인 후 처리한다.

**[CM11 후속 참고 — 현재 MVP 제외]** 설정 → 차단한 사용자 → 대상 선택 → “차단을 해제하면 이 상대와 다시 매칭될 수 있어요. 이전 제안과 채팅은 복구되지 않아요.” 안내 → ‘취소’ / ‘차단 해제’를 제공한다. 성공 시 내가 설정한 차단만 해제하고 상대에게 알리지 않는다. 기존 제안·채팅·기록은 복구하지 않으며 새 제안을 자동 생성하지 않는다. 다른 조건을 충족하면 새 매칭 가능하지만 상대의 차단·자발적 나가기/7일 자동 종료의 재매칭 금지·기존 재제안 제한은 유지한다. 차단 종료를 자발적 나가기로 잘못 기록하지 않는다. 실패/응답 유실은 재조회·재시도로 실제 상태를 확인한다.

차단된 상대와의 제안은 양쪽 목록에서 제거하고 후속 수락으로 채팅 생성 불가다. 일반 거절의 미응답자 비공개 규칙을 차단 관계의 접근 유지 근거로 사용하지 않는다. 상대에게 차단 사유를 공개하지 않는다. 차단/나가기로 닫힌 채팅방에 접근하면 대화 내용 없이 “이 대화는 종료됐어요.”라고만 안내하고 목록으로 이동한다. 캐시/미리보기·지연 응답의 재노출 방지는 CHAT-05와 동일하다. AI 동의 철회에 따른 나가기의 안내 문구는 AI-02의 "더 이상 채팅방을 이용할 수 없어요."를 적용한다.

서버 채팅 기록은 일반 방 실제 종료+30일 이상, 신고 방 최초 성공 신고+90일 이상 보관하며 기존 더 긴 경계는 보존한다. 실제 삭제·탈퇴·기각 스케줄러와 외부 사본 정리는 별도 구현·검증 대상이다. 7일 자동 종료와 자발적 나가기는 사유를 구분하되 두 경우 모두 해당 상대와 재매칭을 금지한다.

### 106 후속 차단 관리 착수 결정

2026-11-03 사용자 승인으로 CM11 후속인 본인 차단 목록·해제를 개발한다. 현재 유효한 차단은 본인/상대별 고유한 영속 UUID 관계로 저장하며 기존 차단도 한 번만 이관한다. 해제 시 본인 소유의 현재 차단 관계만 삭제한다. `matching_participant.blocked_at`은 이미 종료한 제안·방의 접근 제한 증거로 보존하고 과거 제안·방·기존 영구 재매칭 금지를 복원하지 않는다. 임시 UUID나 matching ID를 blockId로 치환하지 않는다. 기존 차단 생성 응답은 유지한다. 이 결정은 이전 압축 MVP의 당시 제외 이력을 보존하며 앱 화면 구현·공유 DB 적용·배포·실기기 검증 완료를 뜻하지 않는다. 공개 API 계약은 기존 팀 공유 목록·해제 페이지와 Jira 106에서 관리한다.

### 안전 기능 실제 연결 확인

2026-10-29 BE 86·87·88은 신고 접수·차단·퇴장의 서버 저장 및 재시도 처리를 구현했다. 공개 요청·응답의 원본은 팀 [신고 명세](https://app.notion.com/p/3ffc91ccb6608022a4a6cc3db7ebd9a7)·[차단 명세](https://app.notion.com/p/3ffc91ccb66080f58379c56dcf6e12de)·[퇴장 명세](https://app.notion.com/p/3ffc91ccb6608074b7b4d4964c5a6656)와 Jira 86·87·88을 따른다. 저장소 안의 AI 보존 사본을 최신 BE 계약으로 사용하지 않는다.

FE 172의 수신 초안과 공개 FE 코드 `435d70d`를 정적으로 대조했다. FE는 차단·퇴장 실제 호출을 비활성화했고 차단 응답 필드를 아직 소비하지 않으므로, BE의 관계 번호·최초 차단 시각 응답을 유지한다. FE 담당자의 승인·실제 서버 연결·두 계정 검증을 완료했다는 뜻은 아니다.

FE 연결 시에는 기존 버전 경로 조립과 안전 기능 경로의 차이, 문자열 방 번호와 숫자 JSON의 차이, 문맥 하나만 전달하는 입력, 응답 유실 뒤 같은 UUID 요청 키 재사용을 반영한다. 종료 오류만으로 차단 성공을 표시하지 않고 실제 성공 응답을 확인한 뒤 양쪽 목록·열린 화면·캐시 접근 종료를 검증한다. 차단 관계 번호·최초 시각을 읽는 응답 모델도 함께 연결한다. FE 코드와 미커밋 작업은 이번 BE 변경에서 수정하지 않는다.

이전 통합 기준 `49d4ee2`의 `c04a519`에서 로컬 전체 빌드·테스트 564개(안전 기능 59개, 실제 JWT·HTTP·PostgreSQL 통합 24개)와 Checkstyle을 통과했다. `418125a`의 [Jenkins #204](https://k15e106.p.ssafy.io/jenkins/job/tingle/204/)와 `46bb7df`의 [Jenkins #208](https://k15e106.p.ssafy.io/jenkins/job/tingle/208/)도 백엔드 전체 빌드·테스트·Checkstyle을 통과했다. 이번 후속 통합 기준은 develop `5bfd8b5`이며 기존 인증·사진·채팅 상대 공개 프로필·설문과 MR !112의 설정 입력 보존·버전 연동에 MR !115의 미성년 즉시 탈퇴 후 사진 파일 정리를 함께 반영한다. 스냅샷 보유 상태의 차단·동일 요청 재시도·설정 조회에서 양쪽 버전과 기존 입력·키링 확인 정보가 보존되는지도 교차 검증한다. 사용자 요청에 따라 사람 리뷰를 기다리지 않고 이 결합 결과를 검증하며, 실제 리뷰 승인과 develop 병합은 별개다. 조가을(BE)에게 MR 리뷰어로, 이재준(FE172)에게 MR 멘션으로 검토를 요청했다. 새 통합 커밋의 검증 결과·리뷰 요청·승인 현황은 [MR !111](https://lab.ssafy.com/s15-final/S15P31E106/-/merge_requests/111)에서 source별로 확인한다. 이전 검증을 새 통합 결과로 간주하지 않으며 실제 승인·FE 연결·공유 DB 적용·실제 기기·배포·일반 삭제 작업은 아직 완료하지 않았다.
