### CHAT-01 상호 수락 후 채팅방 생성

**현재 구현과 FE 연결(2026-10-23 소스 재확인):** 원격 develop `c90e570`에는 상호 수락 시 실제 채팅방 연결을 호출하는 코드가 있으며, 제안 응답의 `chatAvailable`과 `chatRoomId`는 방 존재와 해당 이용자의 접근 조건으로 계산한다. 더 이상 모든 응답을 false/null 고정 또는 방 생성 미구현으로 설명하지 않는다. [제안의 방 연결·응답](https://lab.ssafy.com/s15-final/S15P31E106/-/blob/c90e57090c81b14adc95c8176916235fa1054ef4/back/src/main/java/com/e106/tingle/proposal/ProposalService.java#L257)과 [방 생성·접근 검사](https://lab.ssafy.com/s15-final/S15P31E106/-/blob/c90e57090c81b14adc95c8176916235fa1054ef4/back/src/main/java/com/e106/tingle/chat/ChatService.java#L56)를 정적으로 확인했다. 제안 수락 요청 성공은 내 선택 저장을 뜻하며 상대 수락·방 생성·내 입장 가능을 한 번에 의미하지 않는다. FE는 제안 상태/내 응답과 채팅 입장 가능 여부를 구분하고, `chatAvailable=true`·유효한 `chatRoomId`·본인 이용 권한을 확인한 뒤 입장한다. false/null 등 입장 조건 미충족 시 임의 방 ID나 만료 시각을 만들지 않는다. 상호 수락 상태에서 아직 입장할 수 없으면 서버 상태/권한에 맞는 안내를 표시하고 재확인한다. 방 생성일부터 7일 정책은 유지한다. 이번 확인은 저장소 코드 확인이며 실제 API 응답·DB 적용·모바일 통합·배포·기존 테스트 재실행을 검증한 것은 아니다.

| 사용자·조건 | 유효한 제안에 양쪽이 수락한 두 회원 |
| 실행·입력 | 상호 수락 완료 이벤트 |

| 예외 | 중복 수락·재시도는 같은 방으로 연결하고 생성 시각을 초기화하지 않음. 생성 지연은 준비 안내, 실패는 재시도 제공. 완료된 상호 수락 재요구 금지. 알림 미수신에도 채팅 목록에서 입장/복구 가능 |
| 완료 기준 | 한쪽 수락 때 생성 불가. 동시·중복 수락에도 활성 방 중복 없음. 재접속으로 7일 기한 연장 없음 |
| 데이터·검토 | 방·참여자·최초 생성 시각·종료 시각. 제안 수락 상태와 방 종료 상태는 별개. 38·43 연결 후 채팅 구현 별도 |

내 수락으로 성사되면 “서로의 마음이 연결됐어요!”와 ‘대화 시작하기’ / ‘나중에’를 표시한다. 먼저 수락하고 앱을 이용하던 사람에게는 현재 화면에 성사 알림을 표시하고, 누르면 해당 방으로 진입한다. 다른 작업 중인 화면을 강제로 이동시키지 않는다. 로그인 상태에서 앱이 꺼져 있으면 알림을 허용한 경우 푸시를 보내고 누르면 해당 방으로 진입한다. 로그아웃 중인 수신 대상에는 상호 수락/채팅방 생성 알림을 보내지 않으며, 방 생성 자체를 보류하지 않는다. ‘나중에’ 선택·알림 누락·알림 권한 없음에도 채팅 목록에서 입장할 수 있다.

재로그인 시 로그아웃 중 생성된 활성 방도 채팅 목록에 표시하고 기존 대화·안 읽은 메시지를 조회한다. 종료된 방과 대화는 복원하지 않는다. 첫 입장 여부와 무관하게 CHAT-03의 상단 종료 안내를 표시한다. 일반 로그인은 홈, 새 제안 알림 로그인은 최신 대상 상태에 따른 AUTH-01의 이동 기준을 따른다.

방 생성 중에는 “채팅방을 준비하고 있어요.”를 표시하고 완료 후 입장한다. 실패 시 같은 성사 건의 생성/조회 재시도를 제공하며, 채팅 목록에서도 준비/복구 상태를 확인할 수 있게 한다. 입장 선택·재시도·중복 알림으로 새 방이나 새로운 이용 기한을 만들지 않는다. 알림 진입 때에도 현재 권한/종료 여부를 재확인한다. 알림 표시 방식·전달/재시도·목록 준비 상태의 API 계약은 FE·BE가 정한다.

### CHAT-02 메시지 조회·전송

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 상호 수락한 활성 채팅방의 참여자 |
| 실행·입력 | 대화 조회 또는 텍스트 메시지 전송. MVP 비텍스트 첨부 미지원 |
| 정상 동작·결과 | 권한·방 종료 시각·입력 한도를 확인해 메시지 저장·전달·조회. 입력 원문 한 건 최대 1,000자, 전송 성공/실패 및 본인 목록의 새 메시지 표시 유지. 상대의 읽음 여부는 표시하지 않음 |
| 예외 | 비참여자·종료된 방의 접근 차단. 전송 실패를 성공으로 표시하지 않음. 재시도 중복·재연결 순서 계약 필요 |
| 완료 기준 | 참여자만 이용, 상대 방 접근 차단, 종료 시각 이후 조회/전송 불가. 전송 실패·재시도·재연결 검증 |
| 데이터·검토 | 메시지·발신자·방·전송 시각/상태·본인 목록의 새 메시지 관리용 최소 상태. 최대 1,000자·이모지/줄바꿈 확정, 상대 읽음 표시는 CM06 후속. MVP 텍스트만 허용·사진/동영상/음성/파일 등 비텍스트 첨부 전송 및 보낸 메시지 수정/삭제 미지원, 웹 주소 원문 전달 제한·링크 열기/미리보기 미제공 확정. 페이지 처리·본인 새 메시지 표시 해제/동기화 계약은 검토. 상대에게 읽음 판정/이벤트 전달 요구 없음 |

로그아웃 중인 해당 휴대폰 앱에는 새 채팅 메시지 알림을 보내지 않는다. 알림 미발송으로 메시지를 삭제하거나 본인의 새 메시지를 확인 완료로 처리하지 않는다. 로그아웃 전 이미 발송된 알림의 지연 도착은 FE·BE 계약에서 정한다. 재로그인 시 놓친 알림을 일괄 재발송하지 않고 최신 목록과 안 읽은 메시지로 안내한다.

메시지 길이는 공백·줄바꿈을 포함한 확장 그래핌 클러스터 기준으로 계산하고 줄바꿈은 LF로 통일한다. 키보드 유니코드 이모지·줄바꿈은 텍스트로 허용하고 이미지형 스티커·GIF 첨부는 제외한다. 첨부/촬영/녹음 UI를 제공하지 않으며 서버도 비텍스트 메시지·첨부 전송 요청을 거부한다. 빈 입력 또는 공백·줄바꿈만 있는 메시지는 전송 불가다. FE와 BE가 같은 기준을 사용한다. 1,000자 초과 입력은 잘라내지 않고 유지하며 “메시지는 1,000자까지 보낼 수 있어요.” 안내·전송 버튼 비활성화를 제공하고 서버도 거부한다. 2026-10-21 확정: FE는 웹 주소를 치환하기 전 입력 원문으로 글자 수를 표시·검사하고, BE도 줄바꿈 LF 통일 및 기존 글자 계산 기준에 따라 원문이 1,000자 이하인지 먼저 검증한다. 통과한 메시지에만 웹 주소 치환을 적용한 뒤 처리 결과를 저장·전달하고 양쪽 사용자에게 표시한다. 원문이 1,001자 이상이면 치환 후 짧아져도 거부한다. 원문이 1,000자 이하이고 짧은 주소가 `[웹 주소 차단]`으로 바뀌면서 1,000자를 넘으면 전송을 허용하고 처리 결과 전체를 보존한다. 치환에 따른 길이 증가만으로 재거부하거나 사용자 문장/대체 문구를 자르지 않는다. BE는 유효한 입력에서 발생 가능한 치환 후 길이를 수용하도록 저장 필드·응답·실시간 전달 계약을 설계하고 FE는 그 전체 결과를 표시한다. 정확한 저장 용량/바이트 상한과 실패·재시도 처리는 구현 계약으로 검증한다. 원문 길이 검사는 원문 별도 보관을 승인하는 정책이 아니다.

**CM06(2026-10-26 사용자 승인):** 상대에게 보여주는 메시지 읽음 표시를 압축 MVP에서 제외하고 후속으로 옮긴다. 상대 화면에 개별 메시지가 실제 표시됐는지 판정해 발신자에게 전달하는 읽음 이벤트·표시·전용 동기화 요구도 후속이다. 내 채팅 목록의 새 메시지 표시와 전송 성공/실패·재시도 안내는 유지한다. 본인 목록 관리에 필요한 최소 확인 상태는 별도로 설계하며 상대에게 노출하지 않는다. 이 결정만으로 모든 메시지 확인 관련 필드/테이블을 삭제하지 않는다. 로그인·목록 조회·푸시 수신만으로 본인의 새 메시지를 확인 완료로 처리하지 않고, 접근 불가·종료된 방을 복원하지 않는다. 본인 새 메시지 표시의 해제/동기화 계약은 FE·BE가 구체화한다.

채팅 웹 주소는 서버에서 상대 전달 전에 검사해 해당 주소 부분을 `[웹 주소 차단]`으로 대체하고 나머지 메시지는 유지한다. 주소 대체에 대한 발신자 별도 안내 문구·팝업·토스트는 제공하지 않는다. MVP 인식 범위는 아래 확정 기준을 따른다. 조회/실시간 전달·목록 미리보기·푸시에서도 원래 주소를 노출하지 않으며, 링크 클릭만 비활성화하는 것으로 끝내지 않는다. 주소 분할/조합 유도 등 우회는 AI-02의 문맥 기반 위험 감지 검토 범위에 포함하되 AI 감지만으로 자동 차단/계정 제재를 확정하지 않는다. 별도 안내 미제공은 주소 대체에 한정하며 전송 실패 안내·AI 위험 감지 대응은 별개다. 서비스의 키링 구매 링크와는 별개다.

**MVP 주소 인식 범위(2026-10-21 확정):** HTTP/HTTPS 주소, www 시작 주소, 프로토콜 없는 도메인/경로, 단축 주소, 한글 등 국제화 도메인, IP 기반 웹 주소를 가린다. 일부 도메인 확장자의 고정 목록에 한정하지 않는다. 주소의 경로·쿼리·프래그먼트까지 하나의 `[웹 주소 차단]`으로 바꾸고 주변 문장·문장부호는 유지한다. 맛집·지도·카카오 오픈채팅 등 서비스별 허용 예외는 두지 않는다.

일반 대화·숫자(“네이버에서 검색해”, “버전 1.2”, “10.21에 만나”)와 이메일·카카오톡 ID는 이번 치환에서 제외한다. `hello@example.com` 내부 도메인만 따로 가리지 않는다. `example 닷 com` 같은 변형이나 여러 메시지로 나눈 주소는 MVP 자동 치환 범위 밖이며 정상 문장/공백을 강제로 합치지 않는다. 위험한 사이트 유도·사기·금전 요구 문맥은 AI-02에서 별도 검토하고, 우회 표기의 존재만으로 자동 차단/제재하지 않는다. 형식별 예시는 기준 정책 §5의 인식 범위 표를 따른다. 주소 경계·도메인 판별 및 치환 후 전체 결과를 수용하는 저장/전달 용량은 FE·BE 계약으로 검증한다. 원문 기준 1,000자 검사 후 주소 치환 순서를 적용한다.

### CHAT-03 채팅 종료 상시 안내
