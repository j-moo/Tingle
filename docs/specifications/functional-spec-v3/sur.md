### SUR-01 성향테스트 응답

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 프로필 단계 완료 회원 |
| 실행·입력 | 성향테스트 `SIS-Q-1.1-100` 총 100문항에 응답. [문항 catalogue](https://lab.ssafy.com/s15-final/S15P31E106/-/blob/74b2ed6/docs/contracts/survey/questionnaire-SIS-Q-1.1-100.json) 기준, 문항별 응답 방식은 41번. 과거 v8/80문항 응답을 순번으로 자동 이관하지 않으며 계산 규칙·응답 버전 대응은 41·42번에서 확인 |
| 정상 동작·결과 | 문항별 응답을 회차·문항 ID·설문 버전과 함께 임시 저장. 작성 화면에는 중단 버튼 없음. 강제 종료 후 진행 중 테스트가 있으면 “진행 중이던 테스트가 있어요. 이어서 진행할까요?” 안내. ‘예’이면 최초 검사·재검사 모두 해당 회차의 첫 미응답 문항으로 이동. ‘아니요’이면 답변 보존·재개 보류. 최초 가입은 가입 진행 요약 화면으로 이동해 설문 이어하기를 제공하며 필수 단계 우회 금지(A안). ‘제출하기’에서 유효성 검사·최종 저장 성공 후 수고/매칭 활용 안내 표시, 점수·유형 결과 화면 없음 |
| 예외 | 미응답·모름·상관없음을 구분. 지원하지 않는 선택값을 중간값이나 0점으로 바꾸지 않음. 저장 실패를 저장 완료로 표시하지 않고 재시도 안내. 일부 응답 저장만으로 설문 완료 처리하지 않음 |
| 완료 기준 | 1~10번 저장 후 앱 강제 종료·재로그인 시 ‘예’ 선택 후 응답 복원·11번 재개. ‘아니요’ 후 다시 진입해도 응답 유지. 최초 검사·재검사 모두 해당 회차의 모든 답변을 저장한 미제출 상태는 제출 단계로 이동. 이미 제출한 계산 대기/시스템 실패 상태는 설문 이어하기 대신 계산 복구. Q97/Q98 재확인 필요 상태는 SUR-02의 입력 보완 경로로 구분. 응답 수정값 복원·저장 실패·누락·허용되지 않은 값 확인. 저장 중 종료된 답변까지 복원을 보장하지 않음. 제출 실패 시 완료 안내 금지. 제출 완료와 계산 완료 구분 |
| 데이터·검토 | 설문 버전·문항·응답·저장 상태. 저장 위치·호출 시점·오프라인 재시도·설문 버전 변경 시 복원 방식은 41번과 FE 계약에서 확정. 새 프로필 흡연/음주 선택지를 v8에 임의 변환하지 않음. 중복 질문·변환 책임은 36·41·42번 |

**재검사 이어하기 거절의 복귀 화면(2026-10-23 사용자 확정):** 기존 회원이 진행 중 재검사에 다시 진입해 이어하기를 거절하면 재검사를 시작했던 화면(홈 또는 설정)으로 복귀한다. 저장된 회차/답변과 기존 적용 결과·유효 제안/채팅을 유지한다. 최초 가입은 기존 가입 진행 요약(A안)으로 복귀하고 필수 단계 우회는 금지한다. 앱 종료/재로그인 뒤 진입 출처를 보존·복구하는 방법과 출처가 없는 예외 처리는 DES03·DES13의 화면 계약에서 정한다. 출처 정보 유실을 답변 삭제나 새 회차 생성으로 처리하지 않는다.

### SUR-02 성향 결과 내부 산출·처리 상태 확인

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 해당 설문 버전에서 계산 가능한 응답을 가진 회원 |
| 실행·입력 | 응답으로 개인 성향 점수와 유형 산출 요청 |
| 정상 동작·결과 | 42번의 성향 결과·16유형과 계산 버전을 내부 매칭 입력에 연결. 제출 후 사용자에게 점수·유형을 보여주지 않고 수고/매칭 활용 안내 및 필요한 처리 상태만 표시 |
| 예외 | 응답 부족이면 해당 영역 보완. 유효 응답 제출 후 계산 실패면 기존 응답·버전으로 계산만 재시도하며 설문 재작성 요구 금지. 최초 계산 성공 전 매칭 준비 완료 금지. 재검사 계산 대기/실패 중에는 기존 유효 결과 유지, 유효하지 않은 새 결과 동기화 금지 |
| 완료 기준 | 같은 응답·규칙 버전에 재현 가능한 결과, 입력 부족·계산 실패 구분. 결과와 원응답 버전 연결. 계산 중/실패 상태에서 앱 종료·재진입해도 제출 응답 유지·계산 복구 경로 제공, 처음 설문으로 되돌리지 않음 |
| 데이터·검토 | 제출 상태·계산 상태·성향 점수·유형·계산 버전. 유형이 두 사람의 매칭 점수 자체는 아님. 자동/수동 재시도·횟수·간격·중복 처리·응답 유실 확인은 41·42번/FE 계약. 상세 공식·수치 검증은 42번, 쌍 비교는 36번. 재검사 응답 편집은 SUR-03 |

**Q97·Q98 재확인 및 적용 보류(2026-10-26 사용자 확정):** “Q97·Q98의 미확인·충돌 응답은 재확인하고, 새 응답으로의 매칭 적용은 보류한다. 재검사 중인 기존 회원은 유효한 기존 결과를 유지한다.”

- Q97 `any`는 사용자가 제외 조건 없음을 명시한 유효 응답이므로 엄격 제외 검사 없이 일반 매칭을 진행한다. 다른 기본 조건·점수·정보 충분성 검사는 유지한다.
- Q97 `unknown` 또는 미응답은 제외 의사가 미확인된 상태다. 사용자가 제외 조건 또는 ‘없음’을 명시하기 전에는 해당 새 응답으로 매칭하지 않는다. `unknown`을 `any`로 자동 변환하지 않는다.
- Q97에서 특정 엄격 제외 항목을 선택했지만 해당 항목의 상대 허용 범위가 `any`/`unknown`/미응답이면 재확인한다. 사용자가 구체 허용 범위를 정하거나 해당 엄격 제외 선택을 해제하도록 안내하고, 임의 통과·임의 불일치 판정은 하지 않는다.
- Q98 `unknown` 또는 미응답은 사용자가 `close/some/wide` 중 하나를 직접 선택하기 전까지 해당 새 응답의 매칭 적용을 보류한다. 기존 엔진의 `some` fallback을 신규 MVP 정책으로 채택하지 않는다.
- 최초 가입 등 기존 유효 결과가 없는 사용자는 재확인·검증·계산 성공 전 매칭 준비 완료로 처리하지 않는다. 재검사 중인 기존 회원은 재확인·계산 대기/실패 동안 기존 유효 결과와 그에 따른 매칭을 유지하며, 기존 제안·채팅도 유지한다. 매칭 OFF·차단 등 다른 제한을 우회한다는 뜻은 아니다.
- 새 응답은 재확인 후 검증·계산·저장이 정상 완료된 때 현재 결과로 전환하고 KEY-02의 기기별 동기화/적용 확인 기준을 따른다. 미확인 새 결과로 기존 결과·키링 사본을 덮어쓰거나 무효화하지 않는다.
- 재확인은 입력 보완이며 시스템 계산 오류 재시도와 구분한다. 원래 완료 응답을 조용히 덮어쓰지 않으며, 재응답의 회차/버전·API·안내 사유 코드·구버전 지원/전환 방식은 담당 계약에서 구체화한다. 이 결정으로 구버전 결과의 무기한 지원이나 미지원 조합 강제 허용을 승인하지 않는다.

이 정책 결정은 코드·27개 fixture 기대값 갱신/실행·서버/키링 동일 판정 검증 완료가 아니다. 다른 문항의 모든 unknown 처리를 일괄 변경하지 않으며 최종 50점/.7·입력 출처·정밀도는 별도 잔여다.

#### SUR-02 화면 상태와 재진입 명세 (2026-10-26 보완)

**이탈·복구·경합:** 작성 화면에 별도 ‘중단’ 기능을 추가하지 않는다. 뒤로 이동/이어하기 거절/앱 종료는 기존 단계 규칙을 따르고 저장 성공한 초안·진입 출처를 보존한다. 재진입 시 계정·회차·설문 버전·제출/처리 상태·현재 유효 결과·기기별 반영 상태를 확인해 복원한다. 제출 전 보완 중이면 미확인/충돌 항목을 다시 보여주고, 제출/계산 중이면 진행 상태를 복원한다. 재확인 안내를 닫거나 앱을 재시작해도 재확인 완료로 바꾸지 않는다. 오래된 회차 응답·이전 계정 콜백·늦은 기기 확인으로 최신 결과/화면을 되돌리지 않는다. 제출 응답이 유실되면 접수 상태부터 조회하고 중복 처리 방지는 API 계약에서 보장한다.

**FE에 필요한 정보(필드명 미확정):** 같은 계정의 회차/문항/설문·계산 버전 식별, 수정 가능/완료 여부, 제출 접수·계산 작업·결과 유효성·현재 적용 결과, 본인 재확인 사유와 관련 문항/허용 행동, 지원 버전·재응답 필요 여부, 현재 결과에 연결된 기기별 사본 적용 상태, 가입/매칭 제한과 진입 출처. FE가 answeredCount=100 또는 HTTP 성공 하나로 모두 유효/적용 완료로 추정하지 않는다. 여러 사유의 우선순위·필드/오류 코드·재시도 중복 처리·호환/회차 API는 성현·BE와 대조할 구현 계약이며 이 문서가 해당 API의 존재를 확인한 것은 아니다.

**설계 연결:** 기존 가입 문항/처리 화면과 M05~M07·M11~M12를 재사용할 상태 요구사항이다. Figma의 재확인 목록·충돌 안내·미제출/완료 분기·기기별 반영 상태 화면은 반영/검토 대기다. 이번 작업은 화면 흐름·상태 명세이며 Figma·앱 코드·실행 테스트 완료가 아니다.
