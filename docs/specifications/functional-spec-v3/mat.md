### MAT-01 상대 성별 자동 확정·희망 나이 설정

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 성향 결과를 갖추고 기본 조건을 설정하는 회원 |
| 실행·입력 | 상대 성별은 본인 남성이면 여성·본인 여성이면 남성으로 자동 확정, 선택/수정 화면 없음. 희망 나이는 ‘나이 상관없음’ 또는 범위 설정 선택. 범위는 양쪽 손잡이 슬라이더로 1세 단위 조절하고 표시 숫자를 눌러 직접 입력도 가능 |
| 정상 동작·결과 | 왼쪽 최소·오른쪽 최대 드래그 시 숫자 실시간 갱신, 유효한 직접 입력값과 슬라이더 일치. 상관없음이면 범위 입력 비활성화. 별도 상한 없음 선택 시 최대 입력/손잡이 비활성화·최소 조절 가능. ‘저장하고 다음’에서 저장 성공 후 다음 단계. 나이 최소 19세·양 끝 포함·최소=최대 허용, 양쪽 조건 충족 필요. BE는 본인 성별 기준 대상 검증·동성 쌍 제외 |
| 예외 | 미선택을 상관없음으로 자동 처리하지 않음. 드래그 시 손잡이 교차 방지. 직접 입력의 19세 미만·소수·최소>최대는 오류 안내·저장 불가. 표시 범위 밖 유효값을 화면 끝값에 맞춰 자르거나 거절하지 않음. ‘상관없음’도 성인 회원 내 적용. 저장 실패 시 입력 유지·재시도, 다음 단계 이동 금지 |
| 완료 기준 | 본인 성별별 자동 확정, 별도 성별 입력 없이 다음 단계 진행, API에서 다른 성별·복수·제한 없음 전송으로 우회 불가. 반대 성별이어도 나머지 조건 검사. A 27세·희망 25~32, B 30세·희망 28~35이면 제외. 단일 나이·상한 없음·경계값·나이 미선택 사례 확인 |
| 데이터·검토 | 서버 산출 대상 성별·나이 모드·범위·조건 버전. 슬라이더 초기 표시 범위·직접 입력에 따른 범위 확장/재표시는 FE 설계, 화면 끝값을 실제 입력 상한으로 사용하지 않음. 기존 desiredGenders 필드 유지/응답 형식은 35·36번에서 확정. 별도 상대 성별 설정은 실제 서비스 단계 재검토. 희망 나이 변경 및 생일에 따른 실제 나이 갱신 후에도 기존 유효 제안 유지 확정. 새 매칭은 갱신된 나이로 판단 |

이용 중 희망 나이 수정은 ‘저장’ 성공 시 새 매칭에 즉시 적용한다. 드래그/직접 입력 중이거나 저장에 실패했다면 기존 저장 조건을 유지한다. 나이 상관없음·범위·상한 없음 변경 모두 동일하다. 연결된 키링에는 최신 조건/버전을 즉시 동기화하고, 미연결 기기는 재연결 후 동기화한다. 기기별 반영 확인·구버전 참여 보류는 KEY-02를 따른다.

이미 받은 유효 제안은 새 범위 밖 상대라도 기존 유효 기간 내 수락 가능하며, 먼저 한 수락·생성/만료 시각·기존 채팅을 유지한다. 기존 제안을 새 조건으로 재심사하지 않고, 거절/만료 제안을 되살리지 않는다. 조건 저장과 매칭/제안 생성의 동시 처리·구버전 지연 이벤트 경계는 35·36·37·38·43번 계약 검토 대상이다.

### MAT-02 사진 있는 상대만 매칭

**압축 MVP CM07(2026-10-26 사용자 승인):** MAT-02 ‘사진이 있는 상대만 매칭’ 옵션은 P0 필수로 유지한다. 기본 OFF, 양쪽 옵션과 상대 사진 등록 상태를 각각 검사하며 한쪽이 ON이고 상대 사진이 없으면 새 매칭에서 제외한다. 옵션 변경 전 받은 제안은 유지·수락 가능하다. 프로필 사진 등록 자체를 필수로 바꾸지 않으며 사진 조건은 점수와 별도다. 기존 정책 재확인으로 버전·기능 수(P0 28/P1 1/후속3)는 변경하지 않는다. 서버/키링 동기화·설정 경합과 실제 구현/검증은 기존 잔여로 유지한다.

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 키링 설정을 사용하는 회원 |
| 실행·입력 | ‘사진이 있는 상대만 매칭’ ON/OFF 변경 |
| 정상 동작·결과 | 초기 OFF. ON이면 새 매칭에서 사진 미등록 상대 제외. 양쪽 옵션을 각각 검사하고 기존 저장값 유지 |
| 예외 | 옵션 OFF→ON 변경 전 받은 제안은 유지·수락 가능. 조회 실패를 OFF로 간주하지 않음 |
| 완료 기준 | 둘 다 OFF·사진 없음은 사진 조건 통과. 어느 한쪽 ON이고 상대 사진 없으면 새 매칭 제외. OFF 때 받은 제안은 ON 변경 뒤에도 수락 가능 |
| 데이터·검토 | 사진 옵션·등록 상태·설정 버전·제안 당시 판단 기준. 저장/매칭 동시 처리와 기기 전달 방식은 계약 검토 |

사진 미등록 안내: “사진을 등록하지 않으면 ‘사진이 있는 상대만 매칭’을 켠 사용자와는 매칭되지 않아요.” 사진 조건 통과만으로 최종 매칭을 보장하지 않는다.

### MAT-03 매칭 후보 판단과 만남 연결

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 필요한 등록·입력·성향·조건·동기화가 준비되고 양쪽 모두 매칭 ON인 두 회원. 로그아웃 여부만으로 제외하지 않음 |
| 실행·입력 | 기기 만남 정보와 같은 버전의 매칭 입력을 이용한 판단 |
| 정상 동작·결과 | 별도 성별·나이·사진 등 대상 조건과 차단/재매칭 제한을 검사하고 36번의 승인·검증된 새 제품 규칙에 따른 쌍 비교 결과를 만남·제안 흐름에 연결. 직접 나갔거나 AI 동의 철회로 나가기 처리됐거나 채팅방이 7일 자동 종료된 상대는 새 매칭·제안·진동 대상에서 제외 |
| 예외 | 불완전/오래된 입력·기록 불일치·중복 이벤트를 정상 신규 제안으로 처리하지 않음. 반복 감지·재전송·양쪽 동시 요청으로 들어온 같은 계정 쌍의 동일 만남은 서버에서 하나의 제안으로 연결. 만남 식별·동시성 세부는 36·37·38번 |
| 완료 기준 | 가상 입력의 통과·나이/사진 불일치·구버전·중복 사례와 실물 키링의 휴대폰/인터넷 없는 계산·진동·이탈·후속 양쪽 기록 반영을 검증하고 당시 입력/규칙 버전을 기록(V218~222) |
| 데이터·검토 | 만남·기회·판단 결과·근거·버전. 키링 자체 오프라인 계산은 MVP 필수. 거리/체류·최신성·양쪽 기록 대조·기한 경계 계약은 잔여 |

흡연·음주·종교의 선호 부합도는 일반 점수에 반영한다. Q97에서 선택한 흡연·자녀 계획·종교·문신의 불일치는 점수와 무관하게 제외하며, 음주는 점수에만 반영한다. 미선택이어도 일반 점수 미달로 매칭되지 않을 수 있다. 아래 2026-10-25 후속 결정과 POL01을 따른다. 만남 기회 7일·제안 기한·채팅 수명은 구분한다.

**오프라인 매칭과 제안 생성(2026-10-23 사용자 확정):** 필요한 가입·설정·계산 입력을 미리 반영한 준비된 키링 두 대는 휴대폰 연결·인터넷·서버 응답 없이 BLE로 필요한 데이터를 교환하고 각 키링에서 두 사람의 적합도를 계산해야 한다. 이 경험은 P0 MVP 필수이며 앱/서버 계산으로만 대체하지 않는다. 개인 성향 결과 산출(SUR-02)과 만남 시 두 사람의 적합도 계산(MAT-03)은 구분한다. BLE 연결 성공만으로 충분한 입력 교환이나 매칭 성공을 간주하지 않는다.

계산 완료 후 상대가 아직 근처이고 매칭 요건을 충족하면 양쪽 모두 진동 ON일 때만 양쪽의 실제 감지 키링이 진동한다. 한쪽이라도 OFF이면 양쪽 무진동이며 LED는 본인 설정을 적용한다. 스쳐 지나가 계산 중 이미 멀어졌다면 진동 ON이어도 뒤늦게 울리지 않는다. 만남 기록은 이후 동기화하여 앱 제안 흐름에 연결한다. 재연결·기록 업로드·서버 제안 생성 자체로 지난 만남의 물리 진동을 재생하지 않는다.

서버는 **양쪽의 유효한 동일 만남 기록이 모두 업로드되고 대조된 뒤** 공통 제안을 생성한다(B안). 한쪽만 업로드했다면 기록 대기이며 유효 제안이나 수락/거절 대상이 아니다. 제안 응답 기한은 **서버 제안 생성 시각부터 24시간**이다. 만남 시각·첫 업로드·푸시 수신·앱 최초 확인으로 기산하거나 재시작하지 않는다. 제안 생성 후 알림 권한·전달 조건에 따라 앱 제안 푸시를 제공하고 상대 프로필 확인·수락/거절로 이어진다. 오프라인 상태에서 앱 푸시 수신까지 보장하는 것은 아니다.

같은 두 계정의 기존 제안이 유효한 동안은 다시 만나도 재진동하지 않는다. 반복 감지·업로드 재시도로 제안을 중복 생성하거나 기존 응답/만료 시각을 초기화하지 않는다. 서버 반영 시 기존 매칭 OFF·차단·탈퇴 등 제한을 검사하며, 오래된 기록으로 제한이나 종료된 제안을 우회하지 않는다.

**기록 대기 기한 — 기획서 v1.2 기존 결정 확인(2026-10-23):** 로컬 원문 `Tingle팅글_최종기획서_v1.2_E106.md`(2026-10-16) §3·§4.5·§6.1·§7·§11에서 만남 발생부터 최대 7일, 첫 유효 기록 서버 접수부터 최대 7일 대기하되 만남의 기한을 넘기지 않는 기준을 확인했다. 이번에 새로 정한 기간이 아니며 기존 결정을 명세에 명확히 연결한다.

```text
만남 기회 마감 = 만남 기준 시각 + 적용 정책의 기회 유지 기간(현재 7일)
상대 기록 대기 마감 = min(만남 기회 마감, 첫 유효 기록 서버 접수 시각 + 상대 기록 대기 기간(현재 7일))
제안 응답 마감 = 서버 제안 생성 시각 + 24시간
```

만남 6일 후 첫 기록이 도착하면 약 1일만 기다린다. 기한 내 양쪽 기록 검증으로 생성된 제안은 만남의 7일 기한이 지나도 자신의 24시간을 유지한다. 기회/대기 자동 만료는 새 제안 없이 종료하며 명시적 거절의 30일 제한을 부과하지 않는다. 재전송·늦은 연결·재시작으로 기한을 연장하거나 만료 이벤트를 되살리지 않는다. 한쪽 기록 대기 중에는 양쪽에 수락/거절 제안·매칭 푸시를 노출하지 않는다.

기간은 설정값과 정책 버전으로 관리하며 이벤트의 적용 기한을 보존한다. 위 기간은 제안 생성 기회의 유효성 기준이며 모든 원본 기록·서버 로그의 삭제 기한을 뜻하지 않는다. 마감 직전 접수/검증·기기 시각 오차·정책 버전 적용/전파와 기록 보존/정리는 별도 계약에서 구체화한다.

**만남 기회 기간 변경의 적용(2026-10-23 사용자 확정):** 변경된 만남 기회 기간은 변경 후 새 만남부터 적용하고, 기존 만남은 당시 적용된 정책 버전과 원래 기한을 유지한다. 예를 들어 월요일 만남의 기회 기한이 다음 주 월요일까지 7일이었다면 수요일에 새 기준을 3일로 변경해도 기존 만남의 기한은 줄이거나 다시 계산하지 않는다. 새 기준이 적용되는 수요일 이후 새 만남부터 3일을 사용한다. 기간을 늘리는 변경도 기존 만남의 기한을 연장하거나 만료된 기록을 되살리지 않는다. 현재 만남 기회 7일·상대 기록 대기 최대 7일(만남 기한 상한)·서버 제안 생성 후 24시간은 변경하지 않는다. 기존 이벤트의 재전송·늦은 업로드·재연결은 새 만남으로 취급하지 않는다. 정책 변경 시점, 오프라인 키링의 구버전 처리·양쪽 버전 불일치·적용 확인은 DES06·DES07에서 검증하며 미연결 기기에 새 기준이 즉시 반영됐다고 간주하지 않는다. 데이터 보관·삭제 기간이나 다른 제재 정책의 소급 변경을 이번 결정으로 허용하지 않는다.

**기획서와 후속 결정의 우선순위:** 원문 §2·§3·§4.2·§10.1에도 휴대폰/인터넷 없는 키링 매칭이 MVP로 명시돼 있다. 기존 기능 명세에서 이를 미정으로 둔 부분을 정정한다. 진동은 2026-10-26 재확인에 따라 두 사람 모두 ON일 때만 양쪽 실행한다. 한쪽 진동 OFF이면 양쪽 무진동이지만 LED에는 같은 양쪽 ON 제한을 적용하지 않고 본인 설정을 따른다. 충분한 입력을 교환한 뒤 계산 중 멀어진 만남은 물리 진동을 생략하되 기록/후속 제안 경로를 유지한다는 이번 결정과, 제안에서 상대 공개 프로필을 먼저 확인한다는 후속 정책을 우선하며 원문의 익명 제안/수락 전 프로필 비공개로 되돌리지 않는다. 충분한 입력이 없는 단순 발견/대기 후보를 매칭 성공으로 간주하지 않는다.

**남은 정책·구현 경계:** 진동 기본 ON과 위 기록 대기 기한은 확정했다. 거리·시간 판정, 짧은 만남의 충분한 BLE 교환, 로컬 기록 보존·만남 식별·양쪽 기록 대조·시계 차이·중복 방지, 설정/차단/유효 제안 상태의 최신성 및 오프라인 전파는 DES04·DES06·DES07에서 설계하고 실물 검증한다. 앱에서 저장한 변경이 미연결 키링에 즉시 전달됐다고 표시하지 않는다. 이번 결정은 사용자 요구와 수용 기준 반영이며 구현·실물 검증 완료가 아니다.

**후보 처리·중복 억제·서버 검증(기획서 v1.2 §3~6·8 및 원본 Req.5~14 대조):** 조건 확인을 먼저 마친 후보부터 처리하고 궁합 점수순으로 재정렬하지 않는다. 한 키링은 한 번에 한 상대의 매칭 안내를 진행한다. 단순 발견·불완전한 데이터 교환을 매칭 성공으로 취급하지 않는다. 대기 중 떠난 상대에게 물리 안내를 하지 않으며, 충분한 입력을 이미 교환해 후속 계산이 가능한 스쳐간 만남은 이번 사용자 결정대로 기록/제안 경로를 유지한다. 다시 근접하면 현재 조건·중복 상태를 확인한다.

동일 상대의 로컬 미접수 만남·서버 상대 기록 대기·유효 제안·활성 채팅은 각각 새 이벤트/추가 매칭 안내 억제에 연결한다. 기존 기록 전송 재시도는 허용하지만 새로운 만남 생성으로 바꾸지 않는다. 활성 채팅 중인 동일 쌍은 새 제안/매칭 안내를 만들지 않고 다른 상대의 제안·채팅은 독립 처리한다. 거절·차단·나가기/자동 종료 제한으로 상태가 바뀔 때 기존 억제를 먼저 지워 반복 안내의 틈을 만들지 않는다. 오프라인 최신 상태 전파의 한계는 유지하며 서버가 최신 관계를 재검증한다.

양쪽 기록의 동일 이벤트/소유 관계·기기 증명·서명/인증·중복·입력 버전/유효성·활성 채팅·제한 관계를 검증한다. 한쪽 기록만 대기하는 상태를 검증 탈락으로 표시하지 않는다. 검증 실패 시 제안·상대 프로필을 만들거나 공개하지 않고 “이번 만남은 매칭 제안으로 이어지지 않았어요”라는 공통 안내를 사용한다. 상세 탈락 이유·차단/거절 여부·상대 정보는 노출하지 않는다. 이는 PROP-02에서 사용자가 수락한 뒤 보는 비성사 결과와 별도 상태다. 메시지 형식/암호 방식/원자적 저장·시계 오차/복구 계약은 DES04·DES06·DES07에서 확정한다.

**매칭·진동 스위치 분리(2026-10-23 결정, 2026-10-26 재확인 반영):** 매칭 ON/OFF와 진동 ON/OFF를 별도 제공한다. 각자의 진동 설정 값은 본인 키링에 저장하지만, 실제 진동은 양쪽 모두 ON일 때만 양쪽 키링에서 실행한다. 한쪽이라도 OFF이면 양쪽 모두 진동하지 않는다. 상대의 저장 설정을 변경하지 않으며 매칭 참여·서버 제안 생성·앱 제안 푸시는 유지한다. LED는 본인 설정을 독립 적용한다. 아래 표는 양쪽 모두 매칭 ON이고 그 밖의 매칭·근접·준비 요건을 충족한 경우이며 물리 진동만 나타낸다.

| 내 진동 | 상대 진동 | 물리 진동 |
| --- | --- | --- |
| ON | ON | 양쪽의 실제 감지 키링이 각각 울림 |
| ON | OFF | 양쪽 모두 울리지 않음. 매칭·제안·앱 제안 푸시는 유지 |
| OFF | ON | 양쪽 모두 울리지 않음. 매칭·제안·앱 제안 푸시는 유지 |
| OFF | OFF | 양쪽 모두 울리지 않음. 매칭·제안·앱 제안 푸시는 유지 |

매칭 OFF의 기존 신규 매칭/제안 중지 기준은 유지한다. 진동 ON으로 매칭 OFF를 해제하지 않는다. 진동 스위치와 현재 한 묶음만 멈추는 키링 버튼도 구분한다. 진동 초기 기본값은 ON이며 사용자가 끌 수 있다(2026-10-23 사용자 확정). 진동 설정 저장과 기기 반영 상태를 구분하며 구체적인 저장/반영 계약은 담당 파트에서 정한다.
