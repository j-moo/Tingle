# 팅글 기능 명세 — 키링

공통 범위는 전체 목차의 §1·§2.1을 함께 적용한다. 최신 CM01~16이 과거 문구보다 우선하며, 연령 미달 24시간 자동 처리·신고 등 후속 범위는 원문에 남아 있어도 현재 MVP 필수 요구가 아니다. 원문 절 번호·기능 ID·사례 ID를 보존했으며, 완료 기준과 검증 사례는 실제 구현·테스트 통과를 뜻하지 않는다.

### KEY-01 키링 등록과 구매 안내

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 서비스 가입 ID가 있는 로그인 회원. 프로필 이후 단계 진입 전에 등록 필요. 기존 회원도 기기 추가 가능 |
| 실행·입력 | 앱에서 주변 탐색. 버튼을 길게 눌러 등록 모드에 진입한 키링 발견 시 ‘키링을 찾았어요’ 안내. ‘등록하기’ → 계정 귀속·양도 전 초기화 안내 → ‘동의하고 등록’. 미보유자는 구매 링크 확인 |
| 정상 동작·결과 | 현재 등록 키링이 없을 때만 신규 등록 허용. 이미 1개면 두 번째 다른 기기 등록 거절·기존 관계 보존.  등록 모드·기기·소유 상태를 검증하고 서비스 가입 ID와 고유번호 연결. 서버 연결 성공을 확인한 뒤 등록 완료 및 다음 단계 허용 |
| 예외 | 동의 취소·등록 모드 아님·다른 계정 소유·영구 사용 불가인 기기는 결속하지 않음. 구매 링크 방문·결제 성공만으로 등록 완료 처리하지 않음. 실패 안내·재시도와 동시 등록 충돌 처리 |
| 완료 기준 | 동시 등록/중복 클릭/응답 유실 재시도에도 현재 등록 최대1. 꺼진 기존 키링도 등록 수에 포함.  동의 이전 연결 없음, 동의 후 정상 결속, 타인 소유/영구 차단 거절, 두 계정 동시 등록에도 소유자는 하나. 이미 소유한 기기의 재요청으로 중복 연결 생성 없음 |
| 데이터·검토 | 서비스 가입 ID·키링 고유번호·소유 관계·등록 모드·동의·차단 상태. 버튼 시간·모드 만료·실물 증명·여러 기기 식별 방식은 종무·BE·FE 계약. 고유번호 직접 입력이나 버튼 조작만으로 소유권을 넘기지 않음. 식별자는 상대 미공개 |

### KEY-02 설정 동기화와 이용 준비

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 키링 등록과 필수 입력을 완료한 회원 |
| 실행·입력 | 매칭에 영향을 주는 설정 저장/유효 결과 적용 시 최신 성향 결과·희망 조건·사진 상태·매칭/진동/LED ON/OFF·버전을 등록 기기들에 자동 동기화. 연결 기기는 즉시 전송, 미연결 기기는 최신 반영 필요 상태를 유지하고 재연결 시 자동 전송 |
| 정상 동작·결과 | 새 결과 적용/설정 변경 후 등록 키링 1개에 최신 데이터·버전 동기화 시작. 실제 반영 확인 후 준비 조건 평가. 화면은 내 키링 하나의 완료·대기·실패·재시도 상태 표시 |
| 예외 | 전송 요청만으로 저장 완료라 하지 않음. 구버전·반영 미확인 기기는 새 매칭 참여 보류 후 재연결·최신 동기화 확인 시 참여. 준비된 기기가 하나도 없으면 새 매칭 보류. 설정 변경으로 구버전이 된 기기도 동일 처리 |
| 완료 기준 | 단일 등록 키링의 최신 반영 성공/구버전/미확인/재연결 분기. 반영 전 완료 안내 금지, 늦은 버전 응답 무시. 가상 검증과 실물 검증은 별도 |
| 데이터·검토 | 기기별 적용 버전·동기화 상태·확인 시각. 한 기기의 성공을 전체 완료로 표시하지 않음. 준비된 키링의 휴대폰/인터넷 없는 자체 매칭은 MVP 필수. 최신성 확인·BLE 형식·오프라인 전파는 36·37번 설계/검증 대상 |

진행 중 “동기화 중이에요.”, 해당 기기의 최신 반영 확인 후 “동기화가 정상적으로 완료됐어요.”를 표시한다. 매칭 ON이면 수정된 설정으로 매칭됨을 안내하고 OFF이면 현재 꺼져 있음을 안내한다. 변경이 있는데 기기 미연결이면 “키링이 연결되어 있지 않아요. 동기화가 필요해요.”로 두 상태를 함께 표시한다. 재연결 시 자동 전송 후 동일 안내를 제공한다. 실패/도중 연결 끊김/과거 버전 완료 응답을 최신 동기화 완료로 처리하지 않는다. 표시 위치·지속 시간·재시도 및 확인 메시지 형식은 FE·BE·IOT 계약에서 정한다.

**기획서 대조로 복원한 동기화·기록 기준(2026-10-23):** 최종기획서 v1.2 §5와 원본 Req.4·8·9의 기존 요구다. 자동 전송만으로 수동 동기화 기능을 대체하지 않는다.

| 계기·상태 | 동작·완료 기준 |
| --- | --- |
| 설정·거절·차단·채팅 등 관계 변경 | 연결된 등록 키링에 최신 설정/관계 반영을 즉시 시도. 서버 처리 성공과 기기 저장/적용 확인을 따로 표시 |
| 설정 화면의 수동 동기화 | 사용자가 실행 가능. 전송 중·완료·부분 완료·실패/미반영을 구분하고 재시도 제공 |
| 매일 한국시간 00시 | 자동 동기화를 시도하는 목표. 운영체제·권한·BLE/인터넷 상태로 지연될 수 있으며 정각 완료를 보장하지 않음. 실패 시 수동/재연결 복구 경로 유지 |
| 키링 전원 재시작·방전 복구 | 보존된 만남 기록은 유지. 신뢰할 시간·설정 동기화 완료 전 해당 기기의 새 매칭은 대기. 휴대폰만 재시작한 경우나 다른 준비된 키링까지 같은 이유로 차단하지 않음 |
| 단순히 마지막 동기화 후 24시간 경과 | 경과 시간만으로 모든 매칭을 일괄 중단하지 않음. 확인된 설정 변경/제한·기기 재시작에 따른 대기와 구분 |
| 설정 반영 완료 | 기기가 비휘발성 저장소에 저장하고 적용 버전을 확인한 상태. 앱 전송/수신 성공만으로 완료 처리 금지 |
| 만남 기록 접수 완료 | 서버의 내구성 있는 저장 확인. 앱이 읽었거나 BLE 수신을 확인했다는 이유만으로 기기 원본을 지우지 않음 |

유효하거나 만료 여부가 확인되지 않은 미접수 기록은 전원 차단·재시작 후에도 복구하며, 만남 식별·기기 증명·알고리즘/설정/정책 버전·기한을 연결한다. 서버의 내구성 있는 저장 완료 응답을 해당 키링까지 확인하면 원본을 즉시 자동 삭제하되 동일 상대의 미처리 억제 상태를 함께 지워 새 이벤트/추가 알림을 만들지 않는다. 기록 만료가 임의 영구 보관을 허용하는 것은 아니며 서버 원본의 문의·오류 확인 목적은 아래 기준으로 확정하되 보관 기간/기산점/항목·최소 억제 상태 수명·용량 상한/공간 확보 판정은 POL06·DES06·DES12에 남긴다. 만료가 확인된 로컬 원본은 아래 자동 정리 기준을 따른다.

**저장 공간 부족 시 동작(2026-10-23 사용자 확정):** 안전하게 정리할 수 있는 기록이 없고 새 만남을 저장할 공간이 부족하면 기존 유효한 미접수 기록을 덮어쓰거나 버리지 않는다. 해당 키링의 새 매칭 참여·새 만남 기록 생성·이에 따른 진동/매칭 LED 안내를 일시 대기한다. 기록을 남길 수 없는 만남을 정상 매칭 성공으로 안내하지 않는다. 기존 기록의 업로드/재시도·설정 동기화는 계속 가능하며, 사용자의 매칭·진동·LED 스위치 저장값과 기존 제안·채팅은 유지한다. 공간 부족은 해당 기기의 상태이며 다른 준비된 등록 키링까지 일괄 중단하지 않는다. 앱이 기기 상태를 확인하면 공간 부족으로 매칭 대기 중임과 키링 연결/동기화 안내를 표시한다. 미연결 기기의 상태를 추정해 표시하거나 연결 전 알림 수신을 보장하지 않는다. 서버 접수 확인 후 정리 또는 아래 만료 확인 후 자동 정리로 실제 저장 공간이 확보되면 현재 설정·제한·준비 상태를 재확인해 자동 재개한다. 앱이 기록을 읽은 것만으로 공간 확보 완료를 처리하지 않으며, 매칭 OFF나 다른 제한을 무시하고 강제로 재개하지 않는다. 재개하면서 대기 중 지나간 만남의 물리 안내를 뒤늦게 재생하지 않는다. 용량/예약 공간·저장 도중 실패·양쪽 기기 확정 순서·부분 업로드/정리 실패와 반복 대기/재개 방지는 DES06·DES07에서 구현·실물 검증한다. 공간 부족 자체를 유효한 기록의 삭제 사유로 사용하지 않는다. 만료 원본은 아래 기준으로 정리하며 서버 기록 보관기간은 별도다.

**서버 접수 확인 후 키링 원본 정리(2026-10-23 사용자 확정):** 서버가 해당 만남 기록을 내구성 있게 저장한 완료 응답을 해당 키링까지 확인하면, 키링의 해당 원본은 즉시 자동 삭제한다. 상대 기록 도착·양쪽 검증·제안 생성이나 만남 기회 기한까지 기다리지 않는다. 서버에 접수된 기록과 상대 기록 대기 상태·원래 기한은 유지하며, 상대의 유효 기록이 기한 내 도착하면 기존 절차로 제안을 생성한다. 같은 상대의 중복 알림/이벤트 생성을 막는 최소 상태는 원본과 분리해 유지한다. 앱/BLE 수신 성공만으로 서버 저장을 추정하지 않으며, 서버 저장 실패나 완료 응답이 키링에 도달하지 않아 확인되지 않은 경우에는 유효한 원본을 보존하고 확인/전송을 재시도한다. 기회 만료가 신뢰 시각으로 확인된 원본에는 별도의 만료 자동 정리 기준을 적용한다. 지연·중복 응답은 해당 계정·기기·만남 기록과 정확히 대응시켜 다른 새 기록을 삭제하지 않는다. 실제 삭제가 실패하면 원본 정리/공간 확보 완료로 표시하지 않고 재시도한다. 재전송·응답 재확인·원본 삭제는 제안 중복 생성·대기 기한 연장·재진동/재점등을 유발하지 않는다. 실제 공간 확보 후에는 기존 공간 부족 정책대로 현재 설정·제한·준비 상태를 확인해 자동 재개한다. 기존 제안·채팅과 서버 기록 보관기간은 변경하지 않는다. 서버 저장 증명 전달·삭제/업로드 경합·전원 차단 복구는 DES06·DES07에서 구현·실물 검증한다.

| 사용자·조건 | 해당 키링을 소유한 계정으로 로그인하고 초기화할 실물 기기를 보유한 회원 |
| 실행·입력 | 자신의 등록 키링을 선택하여 서비스 초기화 절차 진행 |

| 예외 | 타인 계정·기기 버튼 단독 조작으로 소유권 해제 불가. 중단·통신 실패를 초기화 완료로 처리하지 않고 복구·재시도 안내 |

마지막 키링을 초기화해 등록 기기가 0개가 되어도 미탈퇴 기존 회원은 유효 제안 목록/상대 프로필 조회·수락/거절와 활성 채팅 기능을 계속 이용한다. 기존 제안의 상호 수락으로 채팅방 생성도 허용한다. 초기화로 계정/프로필/설문을 삭제하거나 제안·방을 종료하지 않으며 기존 응답/만료 시각·채팅방 수명을 유지한다. 종료 항목 복원은 금지한다. 등록 기기 0개이면 새 매칭/키링 진동은 진행하지 않고, 재등록·최신 동기화 등 준비 완료 후 저장된 ON/OFF에 따라 참여한다. 계정 설정 자동 초기화는 하지 않는다. 재진입·재로그인·기존 알림 접근에도 AUTH-02의 기존 기능 허용을 적용한다.

### KEY-04 분실 문의와 영구 사용 불가 처리

**분실 문의 기본 확인 절차(2026-10-23 사용자 확정):** 소셜 재로그인으로 요청 계정에 대한 접근을 확인하고, 권한 있는 서비스팀이 현재 서버의 해당 계정·대상 키링 등록 관계를 대조한 뒤 사용자가 대상 기기와 영구 사용 불가·탈퇴 결과를 최종 확인한다. 기존 로그인 상태나 기기 고유번호를 알고 있다는 사실만으로 처리를 승인하지 않는다. 재로그인 결과가 요청 계정과 다르거나 로그인 불가·등록 관계 불일치·조회 실패·최종 의사 미확인이면 차단/탈퇴를 보류하고 추가 확인 필요로 안내한다. 기본 절차에서 모든 요청자에게 증빙 서류를 일괄 요구하지 않는다. 예외 확인 방법·필요 자료는 별도 운영 계약으로 정하며 이번 결정으로 특정 신분증/구매 증빙 수집을 추가하지 않는다. 이 절차는 계정 접근과 등록 관계·처리 의사 확인이며 실제 분실 사실이나 실명/연령 전체를 입증한 것으로 표시하지 않는다. 정상 보유 키링은 먼저 초기화하고, 처리 직전 등록 상태를 다시 조회해 정상 기기가 남아 있으면 보류하는 기존 순서를 유지한다. 대상 계정·기기가 변경되면 종전 최종 확인을 다른 대상에 재사용하지 않는다. 문의 접수/최종 확인만으로 완료를 표시하지 않고 실제 영구 사용 불가 처리와 탈퇴 성공을 확인한다. 최종 확인 취소 시 해당 요청으로 차단/탈퇴를 실행하지 않는다. 재인증 결과의 요청 연결·유효성, 운영자 권한·처리 기록, 확인과 처리 사이 등록 변경·부분 실패/재시도는 DES05·DES11 및 인증 계약에서 검증한다.

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 분실 때문에 초기화·일반 탈퇴가 불가능한 회원과 처리 권한을 가진 서비스팀 |
| 실행·입력 | 회원 문의 → 소셜 재로그인·서비스팀 등록 관계 대조·사용자 대상/결과 최종 확인 → 정상 보유 기기 초기화 확인 후 분실 키링 영구 사용 불가/탈퇴 처리 |
| 정상 동작·결과 | 해당 계정 탈퇴 처리와 함께 분실 고유번호를 재사용 불가로 관리. 이후 발견되어도 어느 계정에서도 등록·서비스 사용 불가 |
| 예외 | 문의 접수만으로 차단/탈퇴 성공 처리하지 않음. 계정 삭제로 차단 정보가 함께 사라지거나 미등록 기기가 되면 안 됨. 처리 실패는 운영자에게 미완료 상태로 표시 |
| 완료 기준 | 강제 탈퇴 뒤 기존/신규 계정의 해당 키링 재등록 거절, 재시도·기기 초기화 시도에도 차단 유지. 오프라인 차단 전파는 합의된 계약에 따라 별도 실물 검증 |
| 데이터·검토 | 차단 고유번호·서비스팀 처리 기록·권한·탈퇴 상태. 하드웨어 물리 파괴를 뜻하지 않음. 오프라인 기기의 즉시 중지는 미보장이며 차단 확인/전파·보존 정보·혼재 기기 부분 실패/동시 처리 계약은 추가 합의. 정상 기기 초기화 후 분실 기기 차단/탈퇴 순서는 확정 |

정상 보유 기기와 분실 기기가 함께 있으면 정상 보유 키링을 모두 직접 초기화한 뒤 분실 키링만 남은 상태에서 서비스팀이 영구 사용 불가 처리와 탈퇴를 완료한다. 화면에는 “보유한 키링은 먼저 초기화해 주세요. 분실한 키링은 서비스팀 확인 후 처리할 수 있어요.”와 키링 관리하기/서비스팀 문의하기를 제공한다. 문의는 초기화 전에도 가능하지만 문의 접수·일부 초기화만으로 탈퇴/제안/채팅 종료를 실행하지 않는다. 탈퇴 완료 전 기존 유효 제안/활성 채팅은 유지한다.

정상 기기는 기기 초기화와 서버 소유 연결 해제가 모두 끝나야 완료이며 연결 실패/중단 시 재시도한다. 서비스팀은 본인·분실 대상을 확인하고 처리 직전 등록 상태를 재조회한다. 신규 정상 기기가 남아 있으면 먼저 초기화하도록 안내하고, 조회 실패는 진행 가능 상태로 간주하지 않는다. 정상 초기화한 기기는 재등록 가능하게 유지하며 분실 기기와 일괄 영구 차단하지 않는다. 분실 기기는 탈퇴 후 발견돼도 어느 계정에서도 재등록 불가다.

영구 차단/탈퇴가 일부 실패하면 전체 완료로 안내하지 않고 서비스팀에 미완료 상태를 표시하여 확인/재시도한다. 공통 탈퇴 완료 효과는 AUTH-03을 따르고, 부분 처리 상태·동시 기기 등록·재시도·정상 기기 오차단 방지·오프라인 전파는 BE·IOT·FE/운영 계약에서 검증한다. 재시도 전에 실제 처리 상태를 확인하고 이미 완료된 처리를 중복 실행하거나 일부 실패를 전체 성공으로 간주하지 않는다.

### KEY-05 복수 키링 등록·동시 사용 — MVP 이후

CM01 사용자 승인으로 이번 MVP에서 제외한다. 여러 키링 동시 참여·독립 상태 비교·일부 기기 초기화 시 다른 기기 유지·동일 계정 다중 기기 안내는 후속 범위다. 과거 결정/검증 이력은 삭제하지 않는다.

MVP 등록 상한은 KEY-01의 현재 등록1개, 준비 상태는 KEY-02를 따른다. 키링 고유정보와 계정 연결 구조는 유지하며 소유자 최대1·자기 매칭 금지·단일 만남 재전송 중복 방지는 지금도 필요하다. 실제 ERD 제약/등록 트랜잭션은 담당 설계다. 복수 기능 재도입은 등록 제한 해제 외에도 동기화/동시 감지/중복 처리를 검증한 뒤 별도 결정한다.

### KEY-06 진동·LED 안내·버튼 중지·지연 알림 처리

| 구분 | 기준 |
| --- | --- |
| 사용자·조건 | 실제 상대를 감지하고 매칭·준비 조건을 충족한 키링 사용자. 진동은 양쪽 모두 ON일 때만 양쪽 감지 기기에서 실행. LED는 본인 LED ON일 때 실행하며 로그아웃 중에도 같은 요건 적용 |
| 실행·입력 | 유효한 매칭 안내 수신·실행. 안내 중 사용자가 해당 키링의 버튼을 누를 수 있음 |
| 정상 동작·결과 | 짧은 진동 2회를 한 묶음으로 같은 만남당 해당 기기에서 한 번 안내. LED는 켜진 시점부터 30초 연속 점등 후 자동 종료가 UX 목표. 버튼을 누르면 현재/남은 진동과 현재 LED를 즉시 중지. 제안 응답·매칭/진동/LED 설정은 유지 |
| 예외 | 반복 감지·재전송으로 안내를 재시작하지 않음. 수동 중지한 안내도 재울림 금지. 지연 시 상대가 아직 근처·매칭 유효·미안내이면 안내 가능하나 상대가 떠났으면 진동 생략. 이미 생성된 유효 제안은 앱에 유지 |
| 완료 기준 | 정상 2회 묶음, 지속 근접 시 반복 없음, 첫 진동 중/두 진동 사이 버튼 누름 시 잔여 취소, 중복 명령에도 재시작 없음. 앱/서버 응답 없이 버튼 중지. 상대 이탈 후 지연 진동 없음·제안 유지. 중지 버튼이 등록 모드·제안 거절·매칭 OFF로 동작하지 않음 |
| 데이터·검토 | 만남·감지 기기·알림 식별과 시작/완료/수동 중지 상태. 진동 길이·간격·버튼 지연 허용값·근접 거리/시간·버튼 길게 누르기 충돌·재부팅/재연결 시 상태 보존은 36·37·38 계약 및 실물 검증. 기존 제안 유효 중 재만남도 재진동 금지. 제안 자동 만료 후 새 만남은 추가 대기기간 없이 허용. 새 만남 판정/만료 상태 반영·앱 푸시 횟수는 별도 검토 |

로그아웃만으로 매칭 진동을 중지하거나 재로그인까지 안내를 지연하지 않는다. 감지한 기기만 울리고 동일 만남의 2회 묶음·버튼 중지·중복 재울림 금지·상대 이탈 후 지연 진동 생략 기준은 유지한다. 사용자 세션 종료와 기기/서버 인증·전달 경로를 구분하고, 키링 자체 매칭/진동을 전제로 앱 연결 상태별 통신 유지·실패 복구를 35·36·37·38 계약에서 정해 실물 검증한다. 로그아웃 중 동작 요구사항 확정은 오프라인 기기 통신 구현 완료를 뜻하지 않는다.

**매칭·진동·LED 설정과 양쪽 진동 조건(2026-10-26 사용자 재확정):** 세 스위치는 별도이며 초기 기본값은 모두 ON이다. 저장된 본인 설정은 상대의 설정 값을 바꾸지 않는다. 실제 매칭 진동은 두 사람 모두 진동 ON일 때만 양쪽의 실제 감지 키링에서 실행하며, 어느 한쪽이라도 OFF면 양쪽 모두 무진동이다. LED는 본인 설정만 적용하므로 본인 LED OFF는 본인의 매칭 LED만 끈다. 진동 또는 LED OFF여도 매칭 ON 및 다른 요건을 충족하면 만남 기록·제안·앱 제안 푸시는 유지한다. 매칭 OFF의 신규 매칭/안내 중지 기준은 출력보다 우선한다. 이전 문서의 각자 진동 독립 실행 해석을 이 기준으로 정정하며, 두 사람 모두 ON이라는 최초 대화의 조건을 유지한다.

| 내 진동 | 상대 진동 | 양쪽 매칭 진동 | 내 매칭 LED |
| --- | --- | --- | --- |
| ON | ON | 양쪽 실제 감지 키링에서 진동 | 내 LED 설정 적용 |
| ON | OFF | 양쪽 무진동 | 내 LED 설정 적용 |
| OFF | ON | 양쪽 무진동 | 내 LED 설정 적용 |
| OFF | OFF | 양쪽 무진동 | 내 LED 설정 적용 |

위 표는 양쪽 진동 조건을 나타내며 LED는 각자 설정을 적용한다. 같은 만남에서 양쪽 LED가 모두 ON이면 같은 색으로 안내한다는 기존 요구를 유지하고, 한쪽만 ON이면 그쪽만 켠다. LED는 켜진 시점부터 30초 동안 연속 점등한 뒤 자동으로 꺼지는 UX 목표로 확정한다(2026-10-23 사용자 결정). 두 사람이 계속 근처에 있고 사용자가 버튼으로 중지하지 않은 정상 안내 기준이다. 점멸·밝기 반복 변화 방식은 적용하지 않는다. 진동 종료나 앱 확인 시점부터 30초를 다시 세지 않으며 같은 안내의 중복 명령·재연결로 점등 시간을 연장하거나 재시작하지 않는다. 버튼은 30초가 되기 전에도 현재 진동/LED를 즉시 중지한다. LED 점등 중 상대의 이탈을 확인하면 남은 시간과 관계없이 해당 키링의 LED를 즉시 끈다(2026-10-23 사용자 확정). 이탈 확인 시점이 점등 후 10초라면 남은 20초를 유지하지 않는다. 만남 기록과 후속 앱 제안 경로는 유지한다. 이탈 종료 후 같은 안내를 재점등하거나 30초 타이머를 다시 시작하지 않는다. 순간적인 BLE 끊김만으로 실제 이탈을 확정하지 않도록 판정 기준·지연·기기별 판정 차이는 DES06에서 실물 검증한다. LED 색은 만남별로 배정하고 동일 만남의 양쪽 키링이 같은 색을 사용한다(2026-10-23 사용자 확정). 모든 매칭에 하나의 고정 브랜드 색을 사용하지 않으며, 주변의 다른 매칭 쌍과 구분할 수 있게 하는 방향이다. 한쪽 LED OFF이면 다른 쪽만 해당 만남의 색을 표시한다. 한정된 색 목록 때문에 주변의 서로 다른 만남에 같은 색이 배정될 수 있으며 서로 다른 쌍의 색상 고유성이나 색만으로 상대를 확정할 수 있음을 보장하지 않는다. 휴대폰/인터넷 없이도 두 키링이 동일 만남의 색에 합의할 수 있어야 한다. 개별 키링이 독립적으로 다른 색을 선택하지 않도록 색 목록/버전·공통 배정 방식·재전송 일관성·복수 후보/기기 동작을 DES06에서 설계한다. 구체적인 색 목록·주변 색 중복 완화 방식·밝은/어두운 환경과 색 구분성은 실물 검증 후 확정한다. 30초 구현의 시각 오차·밝기·배터리·다음 후보 안내 대기 영향은 IoT 실물 검증 대상으로 두며 검증된 성능으로 표시하지 않는다. 본 절은 매칭 LED 기준이며 충전/고장 등 별도 상태등 정책을 새로 정하는 것은 아니다.

상대 이탈 후 지연 안내 생략·동일 만남/유효 제안의 반복 억제·실제 감지 기기만 안내 조건은 LED에도 적용한다. 설정 ON 전환·기록 업로드/재연결만으로 지난 만남의 LED/진동을 재생하지 않는다. 저장된 각 스위치 값과 기기별 반영을 구분하며 재진입/재연결로 사용자의 OFF를 초기 ON으로 덮어쓰지 않는다. 설정 필드/API·전파 및 OFF와 진행 중 안내의 경합은 DES06에서 검증한다.

**매칭 안내 버튼 중지(2026-10-23 사용자 확정):** 해당 키링 버튼을 누르면 현재 진동·남은 진동과 현재 매칭 LED를 함께 즉시 중지한다. 진동이 끝나 LED만 켜져 있는 경우와 진동 OFF·LED ON인 경우에도 현재 LED를 끈다. 앱·서버 응답 없이 해당 기기에서 처리하며 상대 키링에는 중지 명령을 전파하지 않는다. 매칭·진동·LED 스위치의 저장값, 만남 기록 및 제안/응답 상태는 유지한다. 같은 안내의 중복 명령이나 재연결로 중지한 출력을 재생하지 않는다. 등록 모드와의 버튼 충돌 및 실제 중지 지연은 펌웨어 계약/실물 검증 대상이다.

**제안 자동 만료 후 새로운 만남(2026-10-23 사용자 확정):** 이전 제안이 상호 수락 없이 24시간 자동 만료된 뒤 두 사람이 실제로 헤어졌다가 다시 만난 것으로 확인되면, 별도 재알림 대기기간 없이 현재 매칭 조건을 다시 검사한다. 거절에 따른 30일 제한, 차단, 채팅 종료 후 재매칭 금지 및 다른 유효한 제한은 그대로 적용한다. 조건을 충족하면 새 만남 기록을 만들고, 상대가 아직 근처일 때 각자의 진동/LED 설정에 따라 감지 키링이 다시 안내한다. 충분한 입력 교환 후 이탈한 경우에는 지연 물리 안내 없이 기록/후속 제안 경로를 유지한다. 새 만남의 양쪽 유효 기록을 서버가 대조하면 새 제안을 생성하고 그 생성 시각부터 24시간을 부여한다. 옛 제안·응답을 복원하거나 옛 기한을 연장하지 않는다. 계속 같은 공간에 머무르는 상태, 앱 재진입·재연결 및 옛 기록 재전송은 새 만남이 아니며 추가 안내/제안을 만들지 않는다. 이탈·재접근을 인정하는 시간/거리 기준과 종료 상태의 기기 반영·반복 억제 해제는 DES06·DES07에서 실물 검증한다. 오프라인 키링이 서버의 만료 상태를 즉시 안다고 가정하지 않는다.
