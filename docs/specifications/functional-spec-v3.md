## 1. 읽는 방법과 적용 범위

**압축 MVP CM16(2026-10-27 사용자 확정):** 가입 후 연령 미달 안내부터 24시간 뒤 자동 탈퇴하는 절차를 MVP에서 제외한다. 이 절차에 종속된 최초 유효 안내 시각/표시 확인 기산, 24시간 초기화 마감·카운트다운, 기한 도달 예약 탈퇴 및 기한 미준수에 따른 키링 영구 사용 불가 처리도 MVP 필수 요구가 아니다. `notice_at`이나 대체 타이머 컬럼을 추가하지 않는다. 가입 시 만 19세 이상 확인, 서비스팀이 연령 미달을 확인한 뒤 일반 이용 제한·초기화/문의 접근, 상대 사유 비공개, 실제 탈퇴 성공 시 공통 종료·삭제 효과는 유지한다. 자동 처리 제외를 즉시 강제 탈퇴·즉시 기기 차단·일반 이용 허용으로 바꾸지 않는다. 이후 운영 처리의 시점/완료 조건은 별도 협의하며 이 결정으로 새 기한을 만들지 않는다.

**기존 문구 적용 범위:** 아래 본문·완료 기준·검증 사례·DES/POL에 남아 있는 연령 미달의 ‘24시간 탈퇴/초기화 기한·기산 증거·기한 초과 차단’은 과거 합의 이력 및 후속 범위이며 이번 MVP 의무에서 제외한다. V161~V167·V187·V251 중 해당 부분과 POL07/DES12의 해당 타이머 구현 요구에도 동일하게 적용한다. 일반 이용 제한 등 유지한 부분은 계속 유효하다. 제안 응답 24시간, 키링 배터리 목표 24시간, 분실 기기 처리와 다른 보관/탈퇴 정책은 변경하지 않는다. 기능 ID의 P0 29개 분류는 유지한다. 문서 반영과 구현/실행 검증은 별개다.

- **확정:** 사용자와 합의한 서비스 동작. 구현 담당자가 임의로 바꾸지 않는다.
- **계산 기준:** SIS-Q-1.1-100 참조 엔진 기반 새 제품 규칙 채택. 50점·coverage 70%는 재검산 후보이며 최종 운영값은 미확정. 과거 v8은 비교 자료로 남긴다. 변경 범위·검증/버전 연결은 POL01·DES03~04를 따른다.
- **검토:** 아직 결정하지 않은 정책 또는 구현 방식. 예시를 확정값으로 사용하지 않는다.
- 아래 **완료 기준은 앞으로 확인할 기대 결과**다. 통과한 테스트 결과가 아니다.
- 목록의 P0는 테스터 제공 전 필수, P1은 이번 MVP 추가 목표를 뜻한다. 가입 입력의 필수/선택 여부와는 다르다. 우선순위와 목표 일정은 사용자와 확정했으며, 실제 구현 완료·담당별 계획·팀 승인은 별도로 확인한다.
- 기능별 ‘협업/작업’은 검토·연결 관계이며 구현 담당의 기준은 §2.2다. 사용자와 확정한 담당 범위와 팀원별 공수 확인·Jira 배정·실제 구현 완료는 구분한다. 종료 안내 BE 영빈(49)·FE 순철(50)의 기존 배정도 유지한다.

공통 데이터 이름은 API·ERD에서 다뤄야 할 정보의 예시다. 엔드포인트, 필드명, 테이블명, DB 타입과 인덱스는 각 담당 계약에서 정한다. 상세 입력 규칙은 기준 정책의 §2, 진입 상태는 §4, 제안·채팅은 §5, AI 범위는 §7을 함께 확인한다. 규칙 변경 시 정책과 이 명세를 함께 갱신한다.

원본 DOCX의 Req.1~16, 기획안 v1.1의 수용 테스트 23개, 최종기획서 v1.2의 25개 수용 기준을 [전체 대조표](reviews/requirements-reconciliation-20261023.md)에 각각 연결했다(2026-10-23). 서로 다른 문서의 번호를 같은 목록으로 취급하지 않는다. 후속 합의로 변경된 기준·복원한 누락·미정 계약을 구분하며 비기능 기준은 §1.2를 따른다.

### 1.1 다국어 확장을 위한 공통 개발 요구사항 (2026-10-21 확정)

MVP는 한국어로 제공한다. 모든 파트는 향후 다국어 지원을 고려해 사용자 표시 문구와 서비스 로직을 분리하고, 언어별 리소스·공통 포맷 처리·기본 언어 대체가 가능한 구조로 개발한다. 이 국제화(i18n) 기반은 현재 MVP의 공통 개발 기준이며 기능 목록의 P1 추가 목표와 구분한다. 실제 추가 언어·번역 범위·언어 선택 화면·사용자 채팅 자동 번역은 후속 결정한다.

| ID | 공통 기준 | 설계·확인 대상 |
| --- | --- | --- |
| I18N01 | 버튼·안내·오류·입력 검증·접근성 문구 등 서비스가 제공하는 사용자 표시 문구는 공통 키와 언어별 리소스로 관리. 각 화면/로직에 한국어 문구를 직접 흩어 쓰지 않음 | FE·BE. 기존 명세의 한국어 안내는 기본 언어 문구로 보존. 사용자 작성 닉네임/자기소개/메시지를 번역 리소스로 취급하지 않음 |

| I18N08 | 푸시·서버 안내·AI 주의 배너/대체 문구도 번역 대상에 포함. AI 요청/출력 처리에 언어 정보를 전달할 수 있는 확장점을 설계하고 원문 언어와 UI 언어를 혼동하지 않음 | AI·BE·FE. 현재 검증 기준은 한국어이며 다른 언어 감지/생성 품질은 별도 평가. 문구 대체 성공을 해당 언어 위험 감지 지원으로 표시하지 않음. 키링 메시지는 언어 독립 상태/명령과 표시 문구를 분리 |

각 파트는 DES14에 따라 화면 정의·API·ERD·AI/키링 계약과 코드 리뷰 기준에 위 ID를 연결한다. 실제 코드 검증에서는 문구 리소스 분리, 오류 코드 처리, 긴 문구/변수/기본 언어 대체, 언어와 무관한 정책 계산을 확인한다. 현재 문서 추가가 라이브러리 도입·번역·구현 테스트 완료를 의미하지 않는다.

설문 번역은 질문/선택지 의미·점수 호환을 확인한 뒤 적용한다. 다국어 AI 위험 감지는 언어별 오탐/누락 검증 후 지원 범위를 정한다. 닉네임의 다른 문자권 허용, 실제 지원 언어, 언어 설정 UX와 채팅 자동 번역은 LATER05에서 별도로 결정하며 이번 공통 기준만으로 확정하지 않는다.

설계 참고: [W3C 국제화 지침](https://www.w3.org/International/quicktips/), [Microsoft 문장 연결과 국제화 지침](https://learn.microsoft.com/en-us/globalization/internationalization/concatenation). 라이브러리 선택은 파트별 기술 스택에 맞춰 설계한다.

## 2. 전체 흐름과 기능 목록

**압축 MVP CM09(2026-10-26 사용자 승인):** 신고 기능 전체를 MVP에서 제외한다. 신고 진입·사유/상세·메시지 선택·접수/내역·중복 신고 검사·운영팀 신고 목록/검토/기각·신고 대화 조회·신고 전용 90일 보관 및 기각 시 단축 요구는 후속이다. 신고 접수/처리/선택 메시지 연결 데이터와 API는 현재 MVP 설계에서 요구하지 않는다. 외부 일반 문의(CM08)를 신고 접수·증거 수집·90일 보관을 대신하는 기능으로 만들지 않는다.

부품 도착 전에는 가상 키링으로 개발할 수 있지만, 테스터 제공 전 실제 키링 매칭·진동은 실물 검증이 필요하다. 가상 통합 시연 성공을 실물 검증 완료로 보고하지 않는다. AI-02는 제공업체 보관/학습 조건과 적용 계약 확인 전 가상 대화로만 테스트하며, 목표일을 이유로 실제 대화 분석을 먼저 켜지 않는다. 국제화 공통 기준 I18N01~I18N08은 처음부터 적용하고 실제 추가 언어·자동 번역 등은 LATER05의 후속 범위를 유지한다.

목표 일정과 §2.2 업무 분담은 사용자와 확정했지만 현재 코드 진척도·부품 도착일·담당자별 소요 시간과 달성 가능성은 아직 검증하지 않았다. REVIEW01에서 팀원별 공수·세부 작업 일정과 순철의 인프라/배포 준비를 확인하고 재준의 운영 창구·운영 화면 및 테스트 버전 전달 준비를 확인한다. 마감 시 P0 미완료나 필수 검증 미충족이면 임의로 완료 처리하거나 P1으로 낮추지 않고 일정/범위를 재협의한다. 문서 승인·테스터 배포·팀 공유·Jira 변경은 각각 별도 실행이며 이번 확정만으로 완료되지 않는다.

**압축 MVP CM01 — 계정당 등록 키링 1개(2026-10-26 사용자 승인):** 키링 고유정보와 계정의 소유/등록 연결 구조는 유지한다. MVP에서 한 계정에 현재 등록 가능한 키링은 최대 1개이며, 여러 개를 등록해두고 하나만 활성화하는 방식은 채택하지 않는다. 꺼짐·미연결·매칭 OFF여도 소유 연결이 유지되면 등록된 1개로 센다. 두 번째 다른 키링 등록은 서버에서 거절하고 기존 등록을 보존한다. 중복 클릭·동시 등록·응답 유실 재시도에서도 현재 등록 관계가 2개 생기지 않아야 한다. 동일 기기 재요청은 실제 등록 상태를 확인해 복구하며 추가 소유 관계를 만들지 않는다.

화면은 ‘내 키링’ 하나의 등록·연결·반영·오류 상태를 제공한다. 키링 식별자·현재 소유자·설정/규칙 버전·원본 만남 기록과 동일 만남 재전송 중복 방지는 유지한다. 정상 소유 해제가 완료된 뒤의 등록은 KEY-01/03 기준을 따르되, 분실·교체·강제 처리의 MVP 축소 여부는 별도 질문으로 정한다. 이 승인만으로 기존 기기를 자동 해제하거나 분실 상태를 해소하지 않는다. 기존에 복수 등록된 데이터가 있으면 무단 삭제/하나 임의 선택 없이 별도 전환 계획이 필요하다.

복수 등록·동시 참여·여러 키링 상태 비교는 KEY-05 후속 범위로 옮긴다. 계정/키링의 식별·연결 구조를 사용자 테이블의 단일 문자열로 합치거나 테이블 삭제를 지시하는 결정이 아니다. 구체적인 제약/트랜잭션·등록 처리 방식은 BE/ERD 설계이며 실제 DB·API·펌웨어 변경 완료와 구분한다. 준비된 단일 키링의 휴대폰/인터넷 없는 자체 매칭은 MVP 필수로 유지한다.

**압축 MVP 결정 목록:** CM01 확정 — 복수 등록/동시 사용 후속, 등록 상한1. CM02 확정 — 가입 후 자발적 재검사(SUR-03)는 P0 유지. CM03 확정 — 매칭 이유 설명(MAT-04)은 P0 필수로 포함. CM04 확정 — 종료 1시간 전 별도 알림(CHAT-04)은 후속 이관, 화면의 종료 예정 시각/남은 시간과 7일 자동 종료는 유지. CM05 확정 — CHAT-03 첫 입장 확인 단계/확인 저장 제거, 상단 종료 시각·재조회 불가 상시 안내로 단순화. CM06 확정 — CHAT-02 상대 읽음 표시 후속, 본인 새 메시지 표시·전송 상태 유지. CM07 확정 — MAT-02 사진 필터 P0 유지. CM08 확정 — 일반 문의 외부 창구 대체. CM09 확정 — 신고 전체 후속, 차단/퇴장·일반 30일 보관 및 정정·분실/탈퇴 유지. CM10 확정 — 상대 차단 P0 유지. CM11 확정 — 차단 목록/해제 후속, MVP 사용자 직접 해제 불가. CM12 확정 — 내 수락 취소 후속. CM13 변경 확정 — 구글/카카오/네이버 3종 유지. CM14 확정 — AI-01 시작 질문 추천 P0 필수. 언제든 빈 회차로 재검사·문항 저장/이어하기·기존 유효 결과 유지·새 유효 결과 성공 후 교체 기준을 유지한다. CM15 확정 — AI-02 위험 감지 P0 유지. 이번 압축 후보 CM01~15의 포함/제외 결정을 완료했으며 세부 구현 계약·검증은 남는다. 기능 ID32개를 보존하며 현재 P0 29·P1 0·후속3다.

## 4. API와 ERD 설계에 넘길 정보

아래는 설계 확인 목록이다. API와 DB 구조를 확정한 표가 아니다. 한 기능이 여러 API·테이블을 사용할 수 있고, API 응답은 DB 행을 그대로 공개하지 않는다.

| 기능 묶음 | 필요한 API 동작 | ERD에서 관계를 검토할 정보 | 확인할 경계 |
| --- | --- | --- | --- |
| AUTH·KEY | 로그인·단계 조회·등록·초기화·탈퇴·차단·기기별 동기화 확인 | 회원↔소셜 연결, 회원→키링 연결 구조 유지·MVP 현재 등록 최대1, 키링 고유번호·현재 소유자 최대 1명, 귀속 동의·초기화 상태·영구 사용 불가·기기별 설정 버전 | 동시 등록/탈퇴·초기화 중단 복구·계정 삭제 후 차단 유지·단일 기기 재전송/중복 안내와 등록 상한 경합 |
| PRO | 본인 저장·사진 처리·제안용 공개 조회 | 회원↔프로필/사진, 공개 응답과 원본 구분 | 생년월일 비공개·삭제 사진 캐시 |
| SUR | 문항/응답 저장·결과 조회 | 설문 버전↔문항↔응답↔성향 결과 | 새 프로필 값과 v8 원응답 분리 |
| MAT | 조건 저장·판단·근거 전달 | 회원 선호, 만남/판정·사용한 버전/근거 | 양방향 조건·오프라인·중복 |
| PROP | 목록/상세·수락/거절·만료 | 제안↔당사자별 응답↔채팅 연결 | 응답 동시성·24시간 경계·이전 사진 옵션 유지 |
| CHAT | 방 생성/조회·메시지·신고·종료·삭제 | 방↔참여자↔메시지↔신고/선택 메시지, 생성/종료/최초 신고/보관 시각 | 사용자 이용7일·일반 종료 후30일·최초 신고90일. 탈퇴/삭제 참조 경합 검증 |
| CHAT 안내 | 방의 실제 종료 시각·현재 상태 | 기존 방 정보 활용, 안내 확인 상태/예약 상태는 MVP 불필요 | 첫 입장/재입장 모두 상단 안내, 종료 후 내용 접근 불가 |
| AI·SAFE | 근거 설명·질문·위험 판정·차단 | AI 요청/결과 버전, 차단·접근/보관 범위 | 원문 사본 삭제·장애 동작·제재 분리 |

API 담당자는 기능 ID를 API 문서에 연결하고 요청·응답·권한·오류 샘플을 적는다. ERD 담당자는 데이터의 소유자·관계·유일성·시간 기준·삭제 순서를 검토한다. CM05의 상단 종료 안내는 방의 종료 시각을 활용하며 **사용자별 안내 확인 상태를 요구하지 않는다**. 본인의 새 메시지 표시·가입 동의 기록은 별개로 유지하고 상대 읽음 표시는 CM06으로 후속 이관한다.
