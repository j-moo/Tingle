## 1. 한 줄 요약

- 기존 컬럼은 **타입·NULL 허용 여부·이름이 하나도 바뀌지 않았다.** 지운 컬럼도 없다.
- 컬럼 13개와 테이블 1개(`chat_message_reads`, 컬럼 4개)를 **추가**했다.
- 추가한 컬럼 대부분이 `uuid`인 이유: 앱에 보내는 ID(API의 `sessionId`·`chatRoomId`·`messageId`·`noticeId`)를 내부 번호(bigint)와 따로 두기 위해서다. 내부 번호를 그대로 내보내면 "몇 번째 회차/방/메시지인지"가 드러나고 다른 사람 것을 번호로 추측할 수 있다.
- 확인: 저장소 SQL 185개 컬럼의 타입·NULL 허용이 ERDCloud와 모두 같다. 이 SQL로 `./gradlew clean build`(테스트 168개, 엔티티 검증 포함) 통과.

## 6. ERDCloud와 다르게 둔 것

- ERDCloud 내보내기에는 CHECK 제약·부분 인덱스가 없다. 저장소 SQL의 기존 CHECK·부분 인덱스는 그대로 둔다.
- 유일 조건 이름(`uq_...`)은 저장소 SQL 규칙에 맞춰 새로 붙였다.

## 8. 공용 DB 반영 SQL (참고)

개발 서버(`tingle_dev`)는 `ddl-auto: update`라 앱이 새 컬럼·테이블을 자동으로 추가한다(유일 조건은 엔티티가 생길 때). 운영(`tingle`)은 `validate`라 아래를 master 머지 전에 인프라가 백업 후 실행한다(`infra/infra-plan.md` 8절).
NOT NULL 컬럼에 기본값이 없는 것(`chat_rooms`·`chat_messages`)은 **테이블이 비어 있을 때만** 그대로 실행된다. 행이 있으면 값을 먼저 채운 뒤 NOT NULL을 건다.

```sql
    ADD COLUMN low_cancelled_at timestamptz, ADD COLUMN high_cancelled_at timestamptz;

ALTER TABLE chat_rooms ADD CONSTRAINT uq_chat_rooms_public_id UNIQUE (public_id),
    ADD CONSTRAINT uq_chat_rooms_source_proposal UNIQUE (source_proposal_id);

ALTER TABLE chat_messages ADD COLUMN public_id uuid NOT NULL, ADD COLUMN request_key uuid NOT NULL,
    ADD COLUMN request_hash text NOT NULL;
ALTER TABLE chat_messages ADD CONSTRAINT uq_chat_messages_public_id UNIQUE (public_id),
    ADD CONSTRAINT uq_chat_messages_request UNIQUE (sender_id, request_key);

CREATE TABLE chat_message_reads (
    receipt_id bigint GENERATED ALWAYS AS IDENTITY NOT NULL,
    message_id bigint NOT NULL,
    user_id bigint NOT NULL,
    read_at timestamptz NOT NULL,
    CONSTRAINT pk_chat_message_reads PRIMARY KEY (receipt_id)
);

ALTER TABLE push_installations ADD COLUMN binding_id uuid, ADD COLUMN linked_at timestamptz;

ALTER TABLE background_jobs ADD COLUMN public_id uuid;
ALTER TABLE background_jobs ADD CONSTRAINT uq_background_jobs_public_id UNIQUE (public_id);
```

## 9. 기능 명세 v2 반영 (2026-10-22 오후)

기능 명세 v2(`functional-spec-v2.md`, v0.1.84)와 ERD를 대조해, **명세는 정해져 있는데 ERD에 저장할 곳이 없거나 ERD 제약이 명세와 어긋난 곳**을 고쳤다. 다른 값에서 계산할 수 있거나 기능에 쓰이지 않는 값은 넣지 않았다(9.2).
**25개 테이블·185개 컬럼 → 28개 테이블·204개 컬럼.** 기존 컬럼 이름·타입은 바꾸지 않았다. 바꾼 것은 `app_users.provider_subject`의 NULL 허용, `matching_settings.matching_enabled` 기본값, 기존 CHECK 5개(허용 값 추가·보관 기한 완화)다.

### 9.4 공용 DB 반영 SQL (참고)

개발 서버는 `ddl-auto: update`라 엔티티가 생기면 컬럼이 추가되지만 **CHECK·기본값·NULL 허용 변경은 자동으로 바뀌지 않는다.** 운영은 master 머지 전에 인프라가 백업 후 실행한다.

```sql

    ADD COLUMN withdrawal_due_at timestamptz, ADD COLUMN withdrawn_at timestamptz,
    DROP CONSTRAINT ck_app_users_1,
    ADD CONSTRAINT ck_app_users_1 CHECK (status IN ('ACTIVE','SUSPENDED','WITHDRAWAL_PENDING','WITHDRAWN')),
    ADD CONSTRAINT ck_app_users_2 CHECK ((status='WITHDRAWAL_PENDING')=(withdrawal_due_at IS NOT NULL)),
    ADD CONSTRAINT ck_app_users_3 CHECK (withdrawn_at IS NULL OR status='WITHDRAWN'),
    ADD CONSTRAINT ck_app_users_4 CHECK (status='WITHDRAWN' OR provider_subject IS NOT NULL);

ALTER TABLE user_consents ADD COLUMN locale text, ADD COLUMN consent_screen text;

CREATE TABLE signup_restrictions (
    provider text NOT NULL,
    subject_hmac bytea NOT NULL,
    rejoin_allowed_at timestamptz NOT NULL,
    CONSTRAINT pk_signup_restrictions PRIMARY KEY (provider, subject_hmac)
);

ALTER TABLE matching_settings ALTER COLUMN matching_enabled SET DEFAULT true;

ALTER TABLE keyrings ADD COLUMN blocked_at timestamptz, ADD COLUMN block_reason text,
    ADD CONSTRAINT ck_keyrings_1 CHECK ((blocked_at IS NULL)=(block_reason IS NULL)),
    ADD CONSTRAINT ck_keyrings_2 CHECK (block_reason IS NULL OR block_reason IN ('LOST','AGE_DEADLINE'));

ALTER TABLE user_pairs ADD COLUMN rematch_banned_at timestamptz;

ALTER TABLE match_proposals DROP CONSTRAINT ck_match_proposals_5,
    ADD CONSTRAINT ck_match_proposals_5 CHECK (status IN ('PENDING','WAITING_FOR_OTHER','ACCEPTED','REJECTED','EXPIRED','CLOSED'));

ALTER TABLE chat_rooms DROP CONSTRAINT ck_chat_rooms_3,
    ADD CONSTRAINT ck_chat_rooms_3 CHECK ((closed_at IS NULL AND delete_at IS NULL) OR (closed_at IS NOT NULL AND delete_at>closed_at));

CREATE TABLE chat_safety_notices (
    notice_id bigint GENERATED ALWAYS AS IDENTITY NOT NULL,

ALTER TABLE reports ADD COLUMN resolved_at timestamptz,
    ADD CONSTRAINT uq_reports_1 UNIQUE (reporter_id, target_type, target_id, reason),

    ADD CONSTRAINT ck_reports_3 CHECK ((status IN ('RESOLVED','DISMISSED'))=(resolved_at IS NOT NULL));

CREATE TABLE report_messages (
    report_id bigint NOT NULL,
    message_id bigint NOT NULL,
    CONSTRAINT pk_report_messages PRIMARY KEY (report_id, message_id)
);

ALTER TABLE background_jobs DROP CONSTRAINT ck_background_jobs_1,
```
