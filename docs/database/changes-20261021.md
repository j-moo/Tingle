## 중요한 대체 조건

- login_sessions/sid 제외는 즉시 access 폐기나 refresh 회전/유실 재시도 문제가 해결됐다는 뜻이 아니다. 인증 담당 확인 전 보장 완료로 표시하지 않는다.
- 사진 image_url은 영속 참조다. 외부 공개/전달 URL·업로드 소유권·실제 파일 삭제 계약은 별개다.
- 문항·정책·계산 정의는 과거 버전 파일도 보존한다. 관리자 게시·검증·승인·롤백은 현재 범위 제외다.
- 분석 결과 생성시각과 input_hash를 없애면서 기존 응답의 필수값도 정리했다. 다른 시각을 생성시각으로 임의 대체하지 않는다.
- 별도 작업 테이블 대신 background_jobs의 업무 키·attempt·lease 검사를 사용한다. 메시지의 message_id/client_message_id/sequence는 모두 유지한다.

## MR9 숫자 제안 ID·영속 멱등 키 보완

제안 proposalId는 1 이상의 integer(int64) 숫자이며 DB proposal_id와 동일하다. 별도 공개 UUID나 매핑 컬럼을 두지 않는다. UUID 형식인 Idempotency-Key·세션 family ID는 그대로 유지한다.

수락·거절의 Idempotency-Key는 UUID 필수다. 사용자별 최초 실제 선택의 키를 low_request_key/high_request_key에 선택·시각과 원자 저장하고 제안 보관 동안 유지한다. 같은 키를 다른 제안·다른 선택에 재사용하면 409 IDEMPOTENCY_CONFLICT다. 같은 선택의 재시도는 현재 상태를 반환하며 최초 시각·30일 제한을 연장하지 않는다. 이미 선택한 뒤 새 키로 같은 선택을 보내면 상태만 반환하고 새 키는 저장·소비하지 않는다. 사용자 행→쌍→제안 순서로 잠가 다른 제안 간 키 경합도 직렬화한다. 키는 사용자별이므로 다른 사용자와 같아도 된다. 과거 응답 바이트를 재생하는 방식은 아니다.

테이블 수24 유지, 멱등 키2컬럼 추가로 총164컬럼. 로컬 일회용 PostgreSQL에서 schema.sql 생성과 JPA validate를 검증한다. 공용 DB 변경·배포는 수행하지 않는다.
