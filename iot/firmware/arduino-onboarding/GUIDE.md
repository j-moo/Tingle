# XIAO nRF52840로 시작하는 키링 개발

2026-10-28 · 김종무(IOT) · S15P31E106-149

폴더 구성과 실행할 파일은 [README.md](README.md)를 참고한다.

오늘 목표는 **부품 이해 → Arduino 환경 준비 → 내장 LED → USB 시리얼**이다.
보드는 사용자가 확인한 **XIAO nRF52840 일반형**이다.
첫 실습은 보드 1대와 데이터 USB 케이블만 사용한다. 핀헤더 납땜도 필요 없다.
실제 업로드 전에는 새 개발용 보드인지, 보존해야 할 기존 펌웨어·설정·기록이 있는지 확인한다.

## 1. 보드와 Arduino는 무엇인가

- **XIAO 보드:** 작은 프로그램을 실행하고 BLE로 통신하는 컴퓨터다. MCU는 보드 안의 제어 칩이다.
- **Arduino IDE:** PC에서 코드를 쓰고, 보드가 실행할 프로그램으로 바꾸고, USB로 전달하는 도구다.
- **보드 패키지(코어):** IDE가 해당 보드의 CPU·핀·USB·업로드 방식을 알게 하는 도구 묶음이다.
- **스케치:** Arduino 프로그램의 이름이다. 여기서는 C++ 기반 `.ino` 파일로 작성한다.
- **컴파일(검증):** 코드가 해당 보드용으로 빌드되는지 확인한다. 아직 보드에는 쓰지 않는다.
- **업로드:** 컴파일된 프로그램을 실제 보드에 쓴다. 그 뒤부터 보드가 새 프로그램을 실행한다.
- **시리얼 모니터:** USB를 통해 보드의 글자 로그를 읽고 명령을 보내는 창이다. BLE 통신과는 별개다.

우리 키링에서 XIAO는 상대 발견·판단·기록을 처리하고, 외부 RGB와 진동 모듈은 알림을 출력하며,
배터리는 이동 중 전원을 공급한다. 지금의 LED 실습은 출력을 배우기 위한 것이며 서비스의 매칭 성공을 뜻하지 않는다.
제품 동작은 [현재 MVP 명세](../../../docs/specifications/functional-spec-mvp.md)와
[IoT 통합 문서의 통신 명세](../../KEYRING-SPEC.md#protocol)를 별도로 확인한다.

## 2. 핵심 부품 4개

| 부품 | 프로젝트에서의 역할 | 처음 사용하는 방법 |
| --- | --- | --- |
| XIAO nRF52840 일반형 | 키링의 두뇌·BLE 통신·설정/기록 저장·출력 제어 | USB-C로 PC에 연결하고 아래 내장 LED부터 시험한다. GPIO는 신호 핀이며 전원 핀과 구분한다. |
| Grove Vibration Motor 105020003 | 손으로 느끼는 진동 알림을 만든다. 진동을 감지하는 센서가 아니다. | 실물 v1.2 구동회로 확인 후 VCC·GND·SIG·NC를 구별한다. SIG가 HIGH면 진동, LOW면 정지한다. |
| RGB LED SZH-EK058 | 빨강·초록·파랑 빛을 조합해 사용자에게 색을 보여 준다. | 실물 R/G/B/공통 핀과 공통 양극/음극을 확인하고 채널별 저항으로 한 색씩 시험한다. |
| DTP102050 3.7V 1,000mAh | USB 없이 이동 중에 전원을 공급한다. | 실물 극성·보호회로·충전 조건 확인 후 BAT+/BAT−에 연결한다. 오늘은 연결하지 않는다. |

Grove 제조사 문서는 동작 전압을 3.0~5.5V로 안내하고 v1.2에 트랜지스터가 추가되었다고 설명한다.
프로젝트의 3.3V 사용안은 입고품 기동·전압 강하·재부팅 시험으로 확인해야 한다.
GPIO는 모듈의 SIG만 제어한다. 모터 전원을 GPIO에서 직접 공급하지 않는다.
([Grove 공식 자료](https://wiki.seeedstudio.com/Grove-Vibration_Motor/))

XIAO의 내장 RGB와 구매한 외부 RGB는 서로 다른 부품이다.
내장 LED는 이미 보드에 연결되어 있어 별도 저항·전선이 필요 없다.
외부 모듈은 실물 구조를 확인해야 하며 내장 LED의 켜짐 논리를 그대로 적용하지 않는다.

## 4. 배선 전에 알아둘 단어

| 표기 | 뜻 |
| --- | --- |
| 3V3 | 보드의 3.3V 전원 |
| GND | 회로의 공통 기준·전류가 돌아오는 경로 |
| D0, D1 등 GPIO | 프로그램으로 신호를 읽거나 내보내는 핀. 칩 내부 P0.xx 번호와 구분한다. |
| VCC / SIG / NC | 모듈 전원 / 제어 신호 / 연결하지 않는 핀 |
| 직렬 / 병렬 | 한 전류 경로에 이어 넣기 / 같은 두 지점 사이에 나란히 연결하기 |
| HIGH / LOW | 디지털 출력의 높은/낮은 전압 상태. 부품에 따라 켜짐 논리가 다르다. |
| PWM | 빠르게 켜고 끄는 비율로 밝기 등을 조절하는 방법. 오늘은 단순 켜짐·꺼짐만 다룬다. |

XIAO GPIO는 3.3V 기준으로 사용하고 5V 신호를 직접 넣지 않는다.
배터리의 3.7V는 정격값이며 BAT+를 3V3·GPIO와 혼동하지 않는다.
전류 측정 모드로 배터리 +/−를 바로 연결하면 단락되므로 그렇게 측정하지 않는다.
오늘은 외부 전원과 배선을 연결하지 않아도 RGB LED·시리얼 예제를 실행할 수 있다.

후속 회로 실습에서는 가이드의 **제안** 배치(D2→Grove SIG, D0/D1/D3→외부 RGB)를 검토한다.
실물 Grove 리비전·RGB 공통 핀·저항·배터리 극성 확인 후 최종 핀 표를 정한다.
내장 LED 실습 파일은 이 외부 핀을 제어하지 않는다.

## 5. Arduino IDE 환경 준비

2026-10-27 PC 확인: Arduino IDE 2.3.10과 내장 Arduino CLI 1.5.1이 있다.
XIAO에는 **Seeed nRF52 Boards 1.1.13**을 사용한다.
이는 제조사가 BLE·저전력 사용에 안내하는 패키지다. mbed-enabled 패키지와 구분한다.
초기 예제의 2026-10-27 설치·컴파일 결과는 [검증 기록](VERIFICATION.md)을 확인한다.

다른 PC에서 처음 설정할 때:

1. [Arduino 공식 설치 안내](https://support.arduino.cc/hc/en-us/articles/360019833020-Download-and-install-Arduino-IDE)를 따라 IDE 2를 설치한다.
2. IDE의 **파일(File) → 환경 설정(Preferences)**을 연다.
3. **추가 보드 매니저 URL(Additional Boards Manager URLs)**에 아래 주소를 추가한다. 기존 주소는 보존한다.

```text
https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
```

4. 왼쪽 보드 매니저(Boards Manager)에서 `seeed nrf52`를 검색한다.
5. **Seeed nRF52 Boards**의 **1.1.13**을 설치한다.
6. **도구(Tools) → 보드(Board) → Seeed nRF52 Boards → Seeed XIAO nRF52840**을 고른다.
   Sense·Plus·XIAO M0·Arduino Uno와 구분한다.
7. 보드 한 대를 데이터 USB 케이블로 연결한다.
8. **도구 → 포트(Port)**에서 연결한 보드의 COM 포트를 고른다.
   뽑았을 때 사라지고 연결하면 생기는 포트를 확인한다. COM 번호는 PC마다 다르다.
9. IDE가 이미 실행 중이었다면 재시작하거나 보드 매니저를 다시 열어 설치 결과를 확인한다.

Seeed의 일반형/Sense 공통 튜토리얼에는 Sense 선택 그림도 있다.
이 실습에서는 사용자의 **일반형**을 선택한다.
보드 패키지·내장 LED·USB 설정 근거는 [Seeed 공식 시작 안내](https://wiki.seeedstudio.com/XIAO_BLE/)다.

## 6. 실습 — 내장 RGB LED 순서대로 깜빡이기

파일: [rgb_led_serial/rgb_led_serial.ino](rgb_led_serial/rgb_led_serial.ino)

1. IDE의 **파일 → 열기**에서 위 `.ino`를 연다.
2. 스케치 이름과 폴더 이름을 둘 다 `rgb_led_serial`로 유지한다.
3. 보드·포트를 다시 확인한다.
4. 왼쪽 위 **✓ 검증**을 눌러 컴파일한다. 성공해도 아직 보드 동작을 확인한 것은 아니다.
5. 대상이 새 개발용 보드이며 기존 기록을 보존할 필요가 없는지 확인한다.
6. **→ 업로드**를 누른다. 업로드가 성공하면 보드가 새 프로그램을 실행한다.
7. 내장 LED가 빨강 → 초록 → 파랑 순서로 각각 0.5초 켜지고 0.5초 꺼지는지 직접 본다.

코드는 이렇게 읽는다.

- `setup()`: 전원 인가·리셋 뒤 한 번 실행한다. 핀의 사용 방식을 정한다.
- `pinMode(..., OUTPUT)`: 이 핀으로 출력하겠다는 뜻이다.
- `LED_PINS`: 빨강·초록·파랑 LED의 핀 번호를 담은 정수 배열이다.
- `LED_COLORS`: 시리얼 모니터에 표시할 색상 이름을 가리키는 포인터 배열이다.
- `loop()`와 `for`: 배열의 LED 세 개를 순서대로 처리하고, 전체 과정을 계속 반복한다.
- `digitalWrite(LED_PINS[i], LOW)`: 현재 선택된 내장 LED를 켠다.
- `digitalWrite(LED_PINS[i], HIGH)`: 현재 선택된 내장 LED를 끈다.
- `delay(DELAY_MS)`: 기본값 500밀리초, 즉 0.5초 기다린다.

XIAO의 내장 RGB는 **LOW=켜짐, HIGH=꺼짐**이다.
`LED_BUILTIN`은 내장 빨간 LED다. 충전 표시등과 구분한다.
첫 예제의 `delay()`는 개념을 배우기 위한 대기다. BLE 통신을 붙일 때는 긴 대기로 처리를 막지 않도록 바꾼다.

작은 변경 실습: `DELAY_MS`의 `500`을 `200`으로 바꿔 다시 업로드한다.
주기가 짧아졌는지 확인한 뒤 기본 예제로 돌려놓는다.

## 7. 시리얼 모니터에서 색상·상태 확인하기

1. 앞 절의 `rgb_led_serial` 예제를 업로드한다.
2. **도구 → 시리얼 모니터**를 열고 **115200**을 선택한다.
3. 포트가 바뀌었다면 새 포트를 선택한다.
4. LED가 켜지고 꺼질 때마다 출력되는 색상·상태를 확인한다. 연결 시점에 따라 첫 로그는 달라질 수 있다.

| 로그 | 의미 |
| --- | --- |
| `RED: ON` / `RED: OFF` | 빨간 LED를 켬 / 끔 |
| `GREEN: ON` / `GREEN: OFF` | 초록 LED를 켬 / 끔 |
| `BLUE: ON` / `BLUE: OFF` | 파란 LED를 켬 / 끔 |

`Serial.begin(115200)`은 통신을 준비하고, `Serial.print()`는 보드에서 PC로 글자를 보낸다.
`Serial.println()`은 글자를 보낸 뒤 줄을 바꾼다. 이 예제는 수신 명령을 처리하지 않는다.
Seeed non-mbed 코어에서 USB 시리얼을 쓰므로 `Adafruit_TinyUSB.h`를 포함했다.
이 헤더는 보드 패키지에 포함되며 예제를 위해 별도로 BLE 라이브러리를 설치할 필요는 없다.

`if (Serial)`은 USB 시리얼 연결이 준비됐을 때만 로그를 출력하도록 한다.
모니터를 닫아도 LED 동작은 계속된다. 재부팅하면 LED를 모두 끈 뒤 빨강부터 다시 실행한다.
설정이나 기록을 영구 저장하는 예제는 아니다.

## 8. 막혔을 때 확인할 순서

| 증상 | 확인·조치 |
| --- | --- |
| 전원 LED만 켜지고 COM 포트가 없음 | 데이터 케이블인지 확인 → PC USB 포트 변경 → 장치 관리자 확인. 케이블 충전 성공과 통신 성공을 구분한다. |
| 보드 목록에 XIAO가 없음 | 추가 URL과 Seeed nRF52 Boards 설치 결과를 확인하고 IDE를 다시 연다. |
| `Serial`을 찾지 못함 | 일반형 보드와 non-mbed 패키지 선택, 예제의 `#include <Adafruit_TinyUSB.h>` 유지 여부를 확인한다. |
| `Adafruit_TinyUSB.h`를 찾지 못함 | 선택한 보드 패키지와 설치 상태부터 확인한다. 같은 이름의 라이브러리를 무작정 여러 개 설치하지 않는다. |
| Windows `9009`와 Python 실행 실패 메시지 | IDE 출력의 실패한 명령부터 확인한다. 이 PC에서는 보드 코어의 `platform.local.txt`에 설치된 Python 실행 경로를 지정한 뒤 IDE를 다시 열어 해결했다. `9009`만으로 원인을 확정하지 않는다. |
| 업로드 포트를 열 수 없음 | 다른 시리얼 모니터·터미널을 닫고 실제 COM 포트를 다시 고른다. |
| 업로드 후 로그가 없음 | 새 COM 포트와 115200 확인 → 모니터 다시 열기. 로그는 USB 시리얼 연결이 준비된 뒤 출력한다. |
| 빨간 LED 켜짐·꺼짐이 예상과 반대 | 내장 LED의 LOW=ON을 확인한다. 외부 RGB 회로의 논리와 혼동하지 않는다. |
| 컴파일은 성공했으나 업로드가 계속 실패 | 제조사 안내대로 리셋을 빠르게 두 번 눌러 부트로더 모드에 진입하고 새 포트를 골라 업로드한다. 기존 기록을 쓰던 장치는 복구·보존 방법부터 확인한다. |

첫 실습에서 J-Link·부트로더 재플래시·전체 플래시 삭제는 필요하지 않다.
위 기본 확인으로 해결되지 않으면 오류 창의 첫 오류와 보드·패키지·포트 정보를 기록한다.

## 9. 오늘 통과 기준과 다음 단계

[검증 기록](VERIFICATION.md)에 실제 관찰 결과를 남긴다.
컴파일 성공·업로드 성공·실제 LED/시리얼 성공은 각각 구분한다.

현재 예제의 통과 기준은 세 색상의 순서·주기와 시리얼 로그가 실제 LED 상태와 일치하는지 확인하는 것이다.
다음은 외부 RGB 한 채널 → 세 채널 → Grove 단독 → 합산 부하 → 배터리 순서로 진행한다.
실물 핀·전원 시험 뒤 BLE 두 보드 교환과 이벤트 저장으로 확장한다.

이 디렉터리의 예제는 제품의 매칭·알림 정책, 통신 계약, 인증, 영구 저장, 전력 성능을 구현하지 않는다.
제품 정책·통신 형식을 바꿀 때는 기존 계약과 관련 Story에서 별도로 검토한다.
